# N9 自动实盘独立授权与失败政策

版本1，2026-10-18。**设计交付，运行时未开放L3。** 对应任务N9-01；N9-02真实验证必须另获明确授权。给出资金与账户的目标不替代真实终端验收、逐项预算或授权范围。

## 1. 权限模型

自动化能力分为查看、研究、SIM条件自动、有限LIVE逐次确认、LIVE自动。研究评分、运行证据达标、配置保存、模式字符串均不能提升执行权限。当前SIM条件自动已具独立授权，LIVE仍默认关闭。

未来授权对象 `ExecutionGrantV1` 的必填项：grant_id/revision，账户身份，broker协议和证书指纹，策略版本白名单，生效/到期，允许时段与证券范围，单笔/单日买入/单日卖出/总持仓暴露上限，组合和单证券集中度，现金余量，最大回撤/日损阈值，最小行情覆盖和新鲜度，允许订单类型，确认政策，撤权与接管责任人，准入报告hash，授权人/时刻/审计事件。

所有金额/比例/范围均由用户审查具体值；没有默认允许预算。授权不可改写，变更生成新revision并使旧计划许可失效。生效权不得由模型或研究worker写入。每笔执行冻结 grant/revision，最新检查再次验证当前有效授权。

## 2. 提交前的必要条件

1. 真实回报与账户对账完成，原订单无UNKNOWN；broker-gw身份、协议版本与心跳已验收。
2. 完整源行情、交易日历/时段、可用资金、持仓可卖、冻结及实际配置版本就绪。
3. 当前策略/账户/证券/时间/价格均在授权范围，预算需预留已提交和未回报订单，不能只看成交持仓。
4. 独立风控通过；模型分数只用于排序，规则给价格/数量。研究任务结果不能直接切换生产策略。
5. 持久意图唯一、固定client_order_id；同一业务信号不能用新ID试探重报。确认/授权/风控过期须重检。

以后各条件按机器可验证字段实现，缺失即不建立新执行资格，不能用UI连接状态代替。

## 3. 失败政策与接管

| 事件 | 新开仓 | 已有订单/持仓 | 恢复条件 |
|---|---|---|---|
| 行情陈旧或覆盖不足 | 停止 | 不猜现价，不制造保护成交；保留订单身份 | 源时间和覆盖恢复、复核账户 |
| 订单提交/撤单超时 | 阻断同标的冲突动作 | UNKNOWN，仅查询原单、回报和账户 | 原单结果及冻结守恒被证实 |
| 晚成交/部分成交 | 重新计算剩余预算 | 成交幂等入账，撤单确认后才计算追价余量 | 真实回报版本与对账一致 |
| 配置/策略/授权变化 | 旧计划失效 | 不自动取消不属于本授权的人工单 | 新版计划与最新风险批准 |
| 回撤/日损超限 | 停止 | 按预先核准的退出政策执行或人工接管 | 独立审查解除；不自动复位 |
| Kill Switch/L0 | 停止 | **自动保护退出同样暂停，仅允许人工卖出**，界面持续提示 | Reset只解除急停，不恢复原模式/授权 |
| 进程/网络故障 | 不补造订单 | 重启先恢复持久账本/意图并对账 | 身份、冻结、回报全部核对 |
| 模型失效/预算耗尽 | 模型弃权 | 已获授权的规则策略按约定运行，不能扩大额度 | 模型评测/版本重新准入 |

撤权立即禁止新claim；已claim未外部提交者在最终检查中终止；已提交者不能假定撤回，应按原ID处理。撤权与订单并发的线性化点须有数据库事务与网关回执证据。人工接管以显式审计事件确认，不靠关闭桌面窗口。

## 4. N9-02后续验收顺序

先完成当前N7/N8真实通道证据，再用同一账本进行独立SIM故障矩阵：提交前后崩溃、回报重投/乱序/晚成交、断网、磁盘/权限、T+1/停牌/涨跌停、账户人工单、急停和恢复、模型失效、极端流动性。比较意图/订单/成交/现金/冻结/持仓守恒。

随后形成具体账户、策略与小额预算的授权提案，展示可复验的长时运行、灾备/对账/撤权记录。用户另行授权后才安排受限真实验证，逐级扩大范围，每级均可立即撤权。连续20日只是有限L2的必要运行证据之一，不能跳过其它验收或直接进入L3。
