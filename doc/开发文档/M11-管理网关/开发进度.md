## 监控驾驶舱 P1 补齐（S7 · ops）

- `GET /api/ops/gpu`：网关手写聚合（`ops_gpu.go`）。GPU 段走 nvidia-smi（700ms 超时，Windows 在 `host_windows.go`，其他平台 `host_other.go` 返回不可得），字段为利用率/温度/功耗/显存，n/a 一律记 -1、界面写「不可得」，不填 0。brain 段聚 `/v1/brain/stats` 的各档在途/排队与 `/v1/brain/usage?window=today` 的今日 tokens/h 与调用次数；任一段失败如实缺省，不编数。
- `GET /api/ops/broker-files`：broker-gw 边车当前不存在（`pkg/brokerif/emfile` 只有写入方，没有消费方在读文件单目录），接口就位但如实返回 `available=false` 并在 note 里点名缺口，待 M09 边车落地后返回真实计数。
- 前端：监控详情模型牌出 GPU 利用率/温度/功耗、显存、模型队列与今日吞吐；账户牌总览出文件单目录行；HUD GPU 格优先用真利用率，接口未通才回退 ops 资源节点的显存文本。

## 监控驾驶舱 P2 补齐（S7 · ops 运行口径）

- `GET /api/ops/db`（`ops_db.go`）：`pool` 段来自 `database/sql.Stats`（max_open/open/in_use/idle/wait_count/wait_ms + `pool_used_pct`）；库内省段来自 `data.AuditStore.DBStats`（`pg_database_size` → `size_bytes`/`size_pretty`、`SHOW max_connections`、`pg_stat_activity` 按 `state` 归并 total/active/idle/idle_in_tx）。慢查询走 `pg_stat_statements`：扩展没装或查询失败一律 `slow_queries.available=false` 并在 note 里写清「需要在 postgresql.conf 启用 shared_preload_libraries 并 CREATE EXTENSION」，**不填 0 条**。admin 本进程没连 PG（审计未启用）时返回 `available=false` + note；内省超时 3s，不透传请求取消。
- `GET /api/ops/nats`（`ops_db.go` → `hub.Stats()`）：进程收发计数/重连次数取 `nats.Conn.Stats()`；`stream` 段取 `StreamInfo(NOVATRADER)` 的条数/占用/首末序号；`consumers` 按 `natsRoutes` 里每个非 core、有 durable 的路由逐个 `ConsumerInfo`，使用过滤消费者`NumPending`作为兼容lag（basis明确），并返回ack_pending/redelivered，禁止全流序号相减，取不到则整行 `missing=true`（durable 首次订阅才建，属正常缺口）。断连时只回 `connected=false`，**不编计数**。
- 前端（M12）：HUD 库体积格与监控详情 PG/NATS 服务牌按字段出——连接池环形用量、库内连接与「事务中空闲」标橙、慢查询 Top5（平均 ≥500ms 标橙）、消费者表（缺 durable 标红）。两条接口没通时写「未接入：需要 GET /api/ops/db（PG 连接池/库体积/慢查询）」。两条路由与 `/api/ops/gpu`、`/api/ops/broker-files` 同批注册在 `Gate`，均要求登录。
