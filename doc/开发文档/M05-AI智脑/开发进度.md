## P1-5 AI 数字三档核对 + 证据链（2026-10-19）

对标 vibe-astock verifier：AI 输出在落库前由程序逐数字核对并原地修复，留痕随产物持久化，前端可逐条回查依据。

### 机制（brain biz `scrub.go` + `validate.go`）

- `numberSet` 升级为带出处：每个候选数字记录来源（事实标签 / 含数字的文本片段 ±18 字）。
- 三档判定（容差与既有 `matches` 一致：按输出小数位四舍五入相等，或相对误差 ≤0.5%）：
  1. **sourced** 事实包内找到出处（pct 文本允许按 ×100 命中系数存的事实）；
  2. **recomputed** 能由事实原始值的两两一次四则运算（+／|−|／×／÷ 双向）重算通过，算式记入留痕；运算池 >200 个事实时整档跳过（O(n²) 防护）；
  3. **omitted** 无出处 → 正文原地替换为「（略※）」并计数。
- 接线点：`GenerateBriefing`——`briefOut.check` 拆分为「结构 + 证据编号」校验（长度/编号/关注股在事实包/持仓只针对持仓），结构通过后 `scrubBriefing` 对 headline/market_view/risks/watchlist.reason/positions.view 逐字段三档核对；数字问题不再触发重试或整篇降级（结构与证据编号错误照旧两次不合格后降级）。
- 留痕 `EvidenceItem{field, span, verdict, match}`：sourced/recomputed 按（span|verdict|match）去重；omitted 按字段逐处留痕。`omitted_count` 用指针落库：**未核对 ≠ 0**（降级晨报与 2026-10-19 前的旧晨报为 null）。
- 持久化：随 biz.Briefing 整体进入 `morning_briefings.summary` JSON（既有 Save/Get 全字段往返，无 schema 迁移）。
- analyze / explain / ask 的 `dimOut`/`explainOut`/`askOut`/`summaryOut` 仍走严格拒收（数字无出处即整条作废重试）：评分链直面交易信号，宁缺毋滥，暂不接入 scrub。

### API / 前端

- proto：`EvidenceItem` message + `Briefing.evidence`（repeated）+ `Briefing.omitted_count`（optional int32，旧晨报 = null）；service `toBriefing` 透传。
- 前端 `morning-briefing` 面板改为按真实字段渲染（头版 / 大盘判断 / 风险 / 关注池 / 持仓看点 / 原始情报）；略掉数字时展示警告徽标「略 N 个无出处数字」+「数字核对明细」展开表（字段 / 数字 / 判定徽标（有出处·success、重算通过·info、已略※·danger）/ 依据（事实标签、文本片段或算式））。`types/brain.ts` 的兼容派生（summary/items/generatedAt）保持不变，监控画布与决策台不受影响。

- `go build ./...`、`go vet ./app/brain/...` 通过；`go test ./app/brain/...` 全绿（新增 `scrub_test.go` 7 例：sourced 出处、加法/除法算式重算、略掉替换与计数、百分比 ×100 出处、运算池超限整档跳过、晨报多字段去重与逐处留痕）。

## P1-7 五段式 AI 复盘（2026-10-19）

对标 vibe-astock 五段口径：情绪/资金/题材/龙虎榜/龙头五段独立模型会话、每段只看自己那块数据，汇总段读五段结论写总评与教训。设计见 [设计文档 §13](设计文档.md#13-五段式-ai-复盘p1-7)。

### 机制（brain biz `review_ai.go` + `repo.go`）

- 定稿先行（没有即时冻结一次）；P1-6 纪律落 `sealOf(day)` 进资料包时点，`stats.sealed_at` 可审计。
- 五段资料包各管一块：情绪/题材/龙头读 `emotion_day_frozen`（定稿），资金段读 `market_sentiment` + 20/60 日成交额均比 + 两融合计，龙虎榜段读 `hsgt_top10` 北向十大（东财席位明细属 P2-8，暂记 missing 用北向替代）。任何块取数失败记 missing、不落 0。
- 段输出 `segmentOut{text,points[2..4],evidence≥1}`：结构/编号按§6.1/6.2 校验；数字走`scrubFields`三档（P1-5 流水线复用，核对池=本段事实包），无出处原地替换「（略※）」并留痕。
- 段级降级：单段模型失败只拖垮该段（text 记原因 + `degraded=true`）；没取到数据的段不调模型。可用段 <3 段时不调汇总，用各段首要点拼兜底总评。
- 汇总段 `reviewSynthesisOut{summary≤300,lessons[2..6]}`；核对池 = 全部段事实包 ∪ 五段正文文本（五段数字自动成为 tier-1 出处）。汇总失败兜底拼接，综述类产物不做严格拒收（与晨报同口径）。
- 落库 `daily_reviews(kind='ai')` `(date,kind)` 唯一同日覆盖；`accuracy_stats={segments,evidence,omitted_count,sealed_at,partial,degraded_segments,missing}`、`lessons_learned`、`model`；decisions 审计 `review_ai` 一次 Begin/Finish（六段 callJSON 挂同一 decision）。
