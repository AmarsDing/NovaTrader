# M04 知识库 · 设计文档

版本 v0.3（2026-10-08 评审后修订）。

## 0. 评审结论（v0.2 → v0.3）

| # | v0.2 的问题 | 处理 |
|---|-------------|------|
| 1 | 写「挂在 intel」，但 `intel` 服务不存在，也没分端口 | 本模块先建 `backend/app/intel`，HTTP 2031、gRPC 2032。M03 以后加到同一服务 |
| 2 | 「关键词用 PostgreSQL 全文检索」：本机 PostgreSQL 只有 `simple` 和西文分词配置，没有 zhparser / pg_jieba，中文整句会被当成一个词，查不到 | Go 侧分词后写 `tsvector`，见第 4 节 |
| 3 | 分块 200–800 token，但 bge-large-zh-v1.5 最长 512 token，超出部分会被截断，后半段永远检索不到 | 目标 200–480 token，硬上限 500（含标题） |
| 4 | 没写嵌入服务怎么调、挂了怎么办 | OpenAI 兼容 `/v1/embeddings`；挂了先入库、只缺向量，后台补齐 |
| 5 | HNSW / IVFFlat 二选一未定 | HNSW + 余弦。IVFFlat 要先有数据训练，空库建索引质量差 |
| 6 | 「走完的信号」、事件主题、载荷都没定义；M06 写 `strategy.signal.updated`，`pkg/events` 只有 `strategy.signal` | 消费 `strategy.signal.updated`，终态才建案例；载荷见第 6 节 |
| 7 | 「过期」「来源不明」没有判定标准 | 见需求文档名词表和第 7 节 |
| 8 | 相似案例可能把 `as_of` 之后才结束的案例给研判用，等于偷看未来 | 查询带 `as_of`，只返回 `closed_at < as_of` 的案例 |
| 9 | 「业务代码不写裸 SQL」与向量距离、全文匹配冲突 | 允许在 `data` 层用 ent 的 `sql.Selector` 拼这两类表达式，参数一律走占位符；不写整句 SQL |
| 10 | 没有验收标准 | 已补到需求文档 |

## 1. 服务与目录

intel 服务的骨架归 M03，M04 的代码都放在单独的子包里，不和 M03 共用包：

```
backend/app/intel/
├── cmd/kb.go                 M04 的 wire ProviderSet（main.go、wire.go 只加一行引用）
└── internal/
    ├── biz/kb/               入库、检索、案例用例；分块、分词、RRF 等纯逻辑
    │   └── extract/          md/txt/docx/xlsx/pdf 抽文字
    ├── data/kbstore/         ent 仓储、嵌入客户端
    ├── service/kbsvc/        Knowledge gRPC/HTTP 适配
    ├── server/               HTTP 2031、gRPC 2032（M03 的文件，注册 Knowledge 服务）
    └── core/kbjobs/          信号事件消费、补嵌入、月度清理
backend/pkg/pgext/            vector、tsvector 列类型（ent field.Other 用）
backend/ent/schema/kb_*.go    三张表
```

事件主题用 `pkg/events` 里的 `SubjectSignal`（`strategy.signal.updated`）。

接口定义 `backend/api/intel/v1/knowledge.proto`。桌面客户端仍只访问 admin，由 M11 转发。gRPC 单条消息上限放宽到 32 MB，上传文件上限 20 MB（可配）。

## 2. 表

三张表都由 ent 建，启动时自动迁移。

**kb_document** 一份文档的一个版本。

| 字段 | 说明 |
|------|------|
| category | `case` / `rule` / `compliance` / `review` |
| title、source、source_type、author | 出处。`source_type` 为 `file` / `url` / `signal` / `manual` |
| format、file_name、size_bytes | 原文件信息 |
| content_hash | 原始字节的 SHA-256，唯一。重复入库直接返回原 `doc_id` |
| status | `active` / `superseded` / `expired` / `deleted` |
| version | 同一 `source` 第几版 |
| stock_codes、tags | 可选标签，检索可按股票过滤 |
| expires_at | 可空。过了时间检索就不返回 |
| chunk_count、embed_status | `pending` / `done` |
| superseded_at、created_at、updated_at | |

**kb_chunk** 分块。删除文档时级联删除。

| 字段 | 说明 |
|------|------|
| doc_id、seq | 唯一 |
| heading | 标题路径，如「第二章 > 2.1 入场」 |
| content | 正文，不含标题 |
| token_count | 估算值 |
| tsv | `tsvector`，GIN 索引 |
| embedding | `vector(1024)`，可空，HNSW `vector_cosine_ops` |
| embed_model、embedded_at | 向量来自哪个模型 |

**kb_case** 信号案例的结构化部分，正文另存一份 `category=case` 的文档。

| 字段 | 说明 |
|------|------|
| book、signal_id | 唯一，保证一条信号只有一个案例 |
| stock_code、stock_name、strategy、pattern、emotion_phase | 形态、情绪阶段 |
| signal_type、final_status | 终态 `closed` / `expired` / `cancelled` |
| signal_time、closed_at | |
| entry_price、exit_price、pnl_pct、holding_days | `pnl_pct` 单位是百分比，3.25 表示 +3.25% |
| outcome | `win` / `loss` / `flat` / `unfilled` / `cancelled` |
| attribution | 归因：`indicator_failed` 指标失效、`news_misread` 消息误判、`unfilled` 买不进、`emotion_mismatch` 情绪周期不匹配，或空 |
| doc_id | 可空。文档被清理时置空，案例保留 |

## 3. 入库

```
校验来源/分类/格式/大小 → 抽文字 → 算 content_hash
  → 已存在：在用就直接返回；已替换的重新启用
  → 分块 → 同一事务：写文档、写分块（含 tsv）、把同 source 的旧版本标成 superseded
  → 事务外调嵌入服务写向量；失败则 embed_status=pending，交给补嵌入
```

抽文字：

| 格式 | 做法 |
|------|------|
| md / txt | 按 `#` 标题切章节，空行切段 |
| docx | 读 `word/document.xml`，`Heading1..6` / `标题 1..6` 样式当标题 |
| xlsx | 读共享字符串和每个工作表；工作表名当标题，首行当表头，每行写成「列名：值」 |
| pdf | 纯 Go 读文字层，每页一个章节。抽不出文字（扫描件）就拒收，不做 OCR |
| doc / xls | 拒收，提示另存为 docx / xlsx |

分块：同一章节内按段落累积，目标 200–480 token，硬上限 500（标题也算在内）。超长段落按句号、问号、分号切；单句还超长就按字数硬切。同一章节相邻块重叠最多一句（≤ 60 token）。章节最后一块太短时并入上一块，但不跨章节合并。

token 估算：一个汉字或标点算 1，连续英文数字每 4 个字符算 1。

## 4. 检索

### 4.1 关键词

PostgreSQL 没有中文分词，所以分词放在 Go 里做：

- 连续汉字切成相邻两字（「弱转强」→「弱转」「转强」），单个汉字保留原字。
- 连续英文数字转小写后整词保留。`600519.SH` 得到 `600519` 和 `sh`。
- 其他符号丢弃。

文档分词结果带位置写成 `tsvector` 存到 `tsv`。查询用同样规则分词，各词用 `|` 连成 `tsquery`，按 `ts_rank_cd` 排序取前 50。单字查询只能命中单字成词的地方，召回有限。

### 4.2 向量

- 默认模型 `BAAI/bge-large-zh-v1.5`，1024 维，在 DGX 上以 OpenAI 兼容接口提供（vLLM 或 TEI）。
- 查询前加 bge 的检索指令「为这个句子生成表示以用于检索相关文章：」，文档不加。
- 只比较 `embed_model` 等于当前模型的分块，换模型时新旧向量不会混用。
- 按余弦距离取前 50。

换同维度模型：改配置后补嵌入任务按 `embed_model` 不一致整库重嵌。换不同维度模型：追加新列和新索引，不改旧列。

### 4.3 融合

倒数排名融合：`score = Σ 1 / (60 + 名次)`，两路各取前 50，合并后取 `top_k`（默认 8，最多 50）。向量路不可用时只用关键词，结果标 `degraded=true`。

只检索 `status=active` 且未过 `expires_at` 的文档。返回 `doc_id`、`chunk_id`、标题、章节、正文、来源、分类、融合分和两路名次。

返回的正文是资料，不是指令。M05 拼提示词时要放进数据块（与 M03、M05 一致）。

## 5. 相似案例

输入：情形描述、可选 `pattern` / `emotion_phase` / `stock_code` / `strategy` / `book`、`as_of`（默认当前时间）、`top_k`（默认 5）。

1. 先在 `kb_case` 按条件筛出 `closed_at < as_of` 的案例。
2. 有情形描述：在这些案例文档上跑第 4 节混合检索。没有描述：按 `closed_at` 倒序。
3. 返回案例字段、`doc_id`、命中的 `chunk_id` 和分数。

MVP 的 M05 不调用本接口；增强阶段再接入。

## 6. 信号转案例

M06 每次信号状态变化发布 `strategy.signal.updated`（JetStream）。本服务用持久消费者 `intel-kb-case` 订阅，只处理终态 `closed` / `expired` / `cancelled`，其他状态直接确认。

载荷（JSON，M06 按此发布）：

```json
{
  "signal_id": 1203, "book": "paper", "status": "closed",
  "stock_code": "600519.SH", "stock_name": "贵州茅台",
  "strategy": "first_board_weak2strong", "signal_type": "buy",
  "signal_time": "2026-10-08T09:41:03+08:00", "closed_at": "2026-10-10T14:50:00+08:00",
  "entry_price": 1500.0, "exit_price": 1548.0, "pnl_pct": 3.2, "holding_days": 2,
  "pattern": "弱转强", "emotion_phase": "发酵",
  "attribution": "", "reasoning": "……", "review": "……"
}
```

必填：`signal_id`、`book`、`status`、`stock_code`、`signal_time`。`closed_at` 缺省用事件时间。

结果：`expired` → `unfilled`，`cancelled` → `cancelled`，`closed` 按 `pnl_pct` 正负记 `win` / `loss` / `flat`。

同一事务写 `kb_case` 和案例文档。案例正文里写上信号编号，因为文档按内容哈希去重，字段全相同的两条信号不能合成一篇。`(book, signal_id)` 已存在就跳过，重复投递不会多建。载荷解析失败的消息终止投递并记日志，数据库错误则稍后重投。另有 `RecordCase` 接口用于补录历史信号，逻辑相同。

## 7. 后台任务

| 任务 | 时间 | 做什么 |
|------|------|--------|
| 补嵌入 | 每 5 分钟 | 找 `embedding` 为空或 `embed_model` 不是当前模型的分块，每批 64 条重嵌。嵌入服务没配置时不运行 |
| 月度清理 `kb.purge` | 每月 1 日 03:30，错过 47 小时内补跑（调度器只回看 48 小时） | 删除状态为 `superseded` / `deleted`、或 `expires_at` 已过超过 30 天的文档（分块级联删除，案例的 `doc_id` 置空） |

月度清理走 `pkg/scheduler`，执行记录写 `task_run`。

## 8. 配置

`config.yaml`：

```yaml
intel:
  http: { addr: 0.0.0.0:2031, timeout: 30s }
  grpc: { addr: 0.0.0.0:2032, timeout: 30s }
kb:
  embed_provider: openai   # openai | hash（仅开发自测）| none
  embed_endpoint: http://<dgx>:8000
  embed_model: BAAI/bge-large-zh-v1.5
  embed_dims: 1024
  embed_timeout: 30s
  embed_batch: 32
  max_upload_mb: 20
  consume_signals: true
```

`embed_dims` 必须等于表上的 1024，否则启动失败。`hash` 用词哈希生成向量，`embed_model` 记为 `dev-hash-1024`，只用于没有 DGX 时联调，不能用于正式数据。

本模块不引入 Neo4j。概念与个股关系在 M02 的 `sector_member`。
