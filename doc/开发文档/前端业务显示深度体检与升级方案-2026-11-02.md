## 0. 总体诊断：为什么"功能都有，但看着不舒服"

六条根因，按影响排序：

### 0.1 数据消费率过低——业务深度被前端"剪掉"了

后端已经算出并持久化的高价值数据，前端大量不接（后端调查逐域核实）：

| 后端已有（接口/表） | 前端现状 |
|---|---|
| `GetSeatStats` 席位 T+1/T+5 胜率（market.proto:118，seat_stats 表） | 全仓零调用 |
| `GetChipDistribution` 获利比例/90%成本区/峰价（market.proto:124） | 全仓零调用 |
| `GetReportEstimates` 多券商 EPS/目标价分歧、`GetFinanceBrief` 财务排雷、`GetAHPremium`（market.proto:131/149/166） | 全仓零调用 |
| `GetLimitPremium` 昨日涨停今溢价、`GetLadder` 连板晋级率 | 后端 10-13 已补，梯队面板未接 |
| `ShadowStats` 影子信号 AI 评分桶 T+1/3/5 后验（backtest.proto:284） | evolution 未展示 |
| `Brain.Usage/LatencyHistogram/TierStats.kvCacheUsage` | 归一化拿到后丢弃（api/brain.ts:208-210） |
| `PredictionCheck` 逐票检验明细（brain.proto:389） | 只显总数 |
| `trade_fill.fee`、`trade_cash.realized_pnl` | REST 不透传 → 无费用列、无当日盈亏分解 |
| `strategy_candidate.miss_reason` 漏斗 | 只在扫描当场显示一次，无聚合趋势 |
| 信号 `exitPrice/closedAt/createdAt/dims.comment` | 归一化层丢弃（api/types/strategy.ts:106 定义了无人渲） |

**结论：业务深度的瓶颈在前端消费层，不在后端能力层。** 第一优先级是"把已存在的数据接上来"，其次才是补新接口。

### 0.2 每个面板都是一个"小应用"，缺角色分工

27 个面板各自带标题栏、卡片阵、筛选器、刷新按钮。默认屏（desks.ts DEFAULT_LAYOUT）一屏塞 8 个面板（决策台+梯队+行情+信号+情报+侧栏+交易+下单条），在 1920×1080 上每个面板实际可用高度极低，互相挤压。缺少「导航层（找目标）→ 概览层（看结论）→ 明细层（读证据）」的三级分工。

### 0.3 真相多源、口径混排

- 比率 vs 百分点两套口径并存且未收口：strategy.proto 注释 `pnl_pct` 是百分比（3.2=+3.2%），PerformanceReply.avg_return 是小数；market.proto 里 Quote.pct_chg 是百分比、LimitPremiumRow 是分数。前端 `pctText`/`ratioPct` 全靠人肉选择，已经出过一次 100 倍 bug（旧评审 B1）。
- 风控状态 4 处各自读：riskStore、TradeView 本地 riskSnapshot、admission 信封 liveEnabled、前端写死 liveAllowed=false（TradeView:132）。
- sources 状态四地展示（datasource-health / datasource-center / OpsView / ConfigCenter link），`statusOf` 状态灯逻辑复制两份。
- brain-monitor 与 model-stats 同一份 tiers 数据两套列裁剪。

### 0.4 时间维度全面缺席

几乎所有面板只显示"最新一帧"：信号无生命周期时间轴（pending→risk_checking→approved→executing→closed 过程不可见）、情绪无当日阶段切换时点、风控拒绝无趋势、数据源健康无历史、委托无时间字段。盘中复盘"09:45 到 10:30 发生了什么"无界面可答。

### 0.5 首屏不是答案

多数面板首屏是表单或原始表：OpsView 无红黄汇总、datasource 无异常计数卡、回测无进度、通知无未读聚合。用户需要逐行扫描才能得出结论。决策台是唯一例外（缺口驱动），是全仓的信息设计标杆，其它面板应向它对齐。

### 0.6 交互断点普遍

行不可点（漏选行、梯队行、股池行、异动行、命中行）；深链白名单只有 2 个面板（notify 只能跳 quote-sidebar/alert-rules）；审批无 diff 盲签（evolution reason 恒空串）；已读/布局/偏好全在 localStorage（alerts.ts 死拉取 unreadCount 无 UI 消费）；长任务无进度（回测 5s 轮询只有状态文字）。

## 1. 统一信息设计规范（所有面板改造的公共约束）

在 R-UI 规则之上，补六条**业务信息设计**纪律，作为本方案的验收前提：

### S1 面板骨架三段式（头 / 主体 / 尾）

- **头部**：面板标题 + 数据时点（asOf）+ 新鲜度徽注 + 主操作（≤2 个）。任何面板必须能回答"这是什么时候的数据"。
- **主体**：一个主表或一个主图，不设并列双主。
- **尾部**：脚注行（口径说明/计数）+ 跳转链接。
- 已有的 NtAdminScaffold 三段式（筛选/主体/抽屉）推广为**全部业务面板**的默认骨架。

### S2 结论先行：首屏必须给答案

每个面板的第一个可视元素回答该面板的业务问题（"今天拦了几次""模型链路红了几层""今日信号胜率"），用结论条/计数卡呈现；明细表格永远在结论之下。hero 大数字每面板 ≤1（R-UI-06 已有，继续执行）。

### S3 数字口径收口（消灭单位歧义）

- 后端 proto 一律注释单位；前端 `format.ts` 只保留两个出口：`ratioPct`（比率输入）与 `ppText`（百分点输入），每个调用点注释口径。
- 金额用中文单位（万/亿，`compactAmount` 已有）；价格 2 位小数等宽右对齐；百分比带一位小数。
- 缺失一律「—」+ 原因徽注（R-UI-20 已有，补齐漏网点：SectorRow.heat、AI dims.comment、HotWord.rank）。

### S4 颜色语义分层

红涨绿跌（唯一出口 format.ts）；琥珀=预警/临期；玫红=风险/Kill；冰青=操作/选中；灰蓝=降级/规则分。**同屏不出现两个语义级同色的东西**（现状：limit-ladder 的 risk R3 与炸板率 tone 同橙红系）。

### S5 三级信息密度

L0 概览行（徽注/计数）→ L1 列表（每行 ≤9 列，数字右对齐）→ L2 抽屉详情（360/480/640 阶梯，R-UI-45）。**所有业务列表行必须可点击进 L2 抽屉**；抽屉是钻取的唯一形态，不新开面板。

### S6 跨面板联动总线

证券代码、信号 id、traceId 是三类全局定位符：任何出现证券代码的地方都可点击（SymbolName 内建），任何列表行可跳到对应面板带参定位（扩展 notify/audit/kb 的深链白名单到 risk/trade/signal/brain/market），traceId 可复制。

## 2. 逐业务功能深度方案

> 每个域给出：现状一句话 → 核心问题（带证据）→ 目标信息架构 → 改造清单（FE- 前端 / BE- 后端）→ 验收口径。
> FE 编号共 12 域，BE 编号汇总在第 3 节。

### 2.1 决策台 OverviewView —— 一日作战总览

**现状评级：良（全仓信息设计标杆，但局部错位）。**
四卡（当日盈亏 hero/权益/情绪/系统）、缺口清单、三列票（待执行/已执行/漏选）、一张票正文、晨报热词、持仓 9 列、全市场板块图。

**核心问题：**
- O1 「系统」卡混排实时性与炸板率两个不相干口径（OverviewView.vue:428）；「情绪」卡涨跌家数无单位标注。
- O2 漏选列截断 8 条（decision-desk.ts buildMissed limit=8），且漏选行**不可点击**——能看到"谁没选上"，进不去"为什么"。
- O3 三列票卡只有 时间/代码/分数：无方向色带、无入场价、无有效期——09:45 的票和 14:45 的票长得一样（旧评审 O2 仍在）。
- O4 板块图画的是**全市场**板块，与标题"持仓"语义错位（旧评审 4.1-4 遗留未改）。
- O5 竞价时段决策台无竞价强弱（`GetAuction` 链路 api/market.ts:515 已存在，决策台未接）。
- O6 票正文与 SignalView 重复渲染（同一 buildDecisionAction 两处调用），口径可能漂移。

**目标形态：**
```
┌ 当日盈亏 hero（含 已实现/浮动 分解） ┬ 可交易状态（链路齐/阻断n） ┬ 情绪（阶段·仓位系数·涨/跌） ┬ 今日风控（买入x/5·拦截n） ┐
├ 现在缺什么（阻断清单，可点击修复深链） ──────────────────────────────────────────────────────────┤
├ 待执行票卡流（方向色带/代码/分数环/入场区间/有效期倒计时/状态） ┬ 已执行（成交价/量/后验pnl） ┬ 漏选（原因徽标/规则分/可钻取） ┤
├ 选中票正文六块：行动 → 价格与仓位 → 四维投票 → 异议 → 理由证据 → 风控 ───────────────────────────┤
├ 竞价强弱条（09:15–09:30 时段显示） · 持仓盈亏表（含所属板块） · 焦点情报 ─────────────────────────┘
```

**改造清单：**
- FE-O1 四卡重排如上；情绪卡子句加"涨 x / 跌 y 家"；系统卡拆为"链路"徽注行，炸板率归入情绪域。
- FE-O2 票卡标准化：方向色带（红买绿卖）、SymbolName、时间、分数环、入场区间、有效期倒计时、状态徽章；漏选卡含 missLabel 徽标+规则分，点击跳 SignalView 带 symbol 定位。
- FE-O3 漏选完整列表（去 8 条截断），按 missReason 分组聚合计数头。
- FE-O4 板块图改为「持仓+候选」所属板块分布（依赖 BE-05 板块归属）。
- FE-O5 竞价时段头部接 GetAuction：竞价参与数/均涨幅/未匹配比，过时段自动隐藏。
- FE-O6 票正文抽为共享组件 `TicketDetail`，决策台与信号中枢同源渲染。

**验收：** 不滚动首屏即可回答"今天能不能做、做哪只、仓位多少、什么条件失效"；漏选每一行 2 次点击内到达解释。

### 2.2 信号中枢 SignalView —— 信号全生命周期

**现状评级：中。**
筛选（方向/状态/模板/排序）+ 四段漏斗 + 卡片流（评分环/雷达/四维/价格/R 倍数/有效期/理由/证据/meta）。推送订阅与有效期置灰已修好。

**核心问题：**
- S1 卡片流在 20+ 信号时对比困难：找最高分要上下扫，卡片占地大、密度低。
- S2 无生命周期时间轴：信号从 pending 到 closed 的状态流转完全不可见（M06 设计 §5–7 定义了完整状态机，界面只用了当前值）。
- S3 `exitPrice/closedAt` 已归一化但无渲染位——已平仓信号看不到出场价与出场时点（api/types/strategy.ts:106-113 定义无人消费）；`dims.comment`（四维评语）在 decision-desk.ts:238 被丢。
- S4 无代码搜索；无"临期（≤5 分钟）"快捷过滤；漏斗四段不可点击联动过滤。
- S5 后验盈亏只在卡片 meta 里，无聚合统计（今日信号胜率/平均后验）——Strategy 的 PerformanceReply 已有 win_rate/avg_return/attributions 未被此处消费。
- S6 R 倍数在 SignalView 内自算（L257），与决策台风控块口径未统一。

**目标形态：** 表格视图为默认（列：时间/代码/方向/综合分/规则·AI 分/入场/止损/止盈/R/有效期/状态/后验 pnl），卡片视图切换保留；漏斗四段可点击=过滤条件；行点击 → 480 抽屉：生命周期时间轴 + 四维雷达+评语 + 理由证据 + 关联订单 + traceId。

**改造清单：**
- FE-S1 表格/卡片双视图切换，表格默认；表格行点击开抽屉。
- FE-S2 抽屉含生命周期时间轴（依赖 BE-02 状态历史；过渡期用 createdAt/updatedAt/closedAt 三节点近似）。
- FE-S3 补 exitPrice/closedAt/dims.comment 渲染；后验 pnl 带持仓天数。
- FE-S4 顶部加代码搜索框与「临期」开关；漏斗阶段可点击过滤。
- FE-S5 底部统计条：今日信号 n · 已平仓 n · 胜率 · 平均后验（消费 PerformanceReply）。
- FE-S6 R 倍数计算收口到 utils 单出口，决策台/信号/下单条三处同源。

**后端依赖：** BE-01 ListSignals 时间范围+分页；BE-02 信号状态历史。

**验收：** 30 条信号 5 秒内定位目标；任意已平仓信号可见出场价/时点/持仓天数/后验盈亏；漏斗每段可点。

### 2.3 行情 MarketView + 报价侧栏 —— 个股全景

**现状评级：中偏弱（超短视角最不达标的核心面板）。**
K 线（仅 1d/1m）+ 指标 + 成本线 + markers + 消息列表 + 自制报价条；侧栏=五档+价格/量额/估值三平铺 grid。

**核心问题：**
- M1 周期只有日线和 1 分钟（PREFS_ALLOW freq ['1d','1m']）——超短盯盘的 5/15/30 分钟与分时完全缺位。
- M2 报价条用 bars 末根自制：「较前根」口径易被误读为对昨收（MarketView.vue:524-540 注释自承）；换手率、量比恒缺（GetQuote 链路在，本页不查）。
- M3 **后端个股数据富矿完全未消费**：GetQuote（全字段）、GetSeatStats（席位 T+1/T+5 胜率）、GetChipDistribution（获利比例/成本区）、GetFinanceBrief（财务排雷）、GetReportEstimates（券商分歧）、GetAHPremium、SearchSecurities——前端零调用（全仓 grep 核实）。
- M4 消息列与情报面板重复，无重要度筛选，不可跳到原文链接（IntelItem.url 丢弃）。
- M5 侧栏三个 grid 平铺 KV 无视觉锚点；52 周高低无距现价标注；估值区信息陈旧无口径时间。

**目标形态：**
```
┌ 报价头：现价 hero + 涨跌幅(对昨收) + 今开/最高/最低 + 换手/量比/封单额 + 涨/跌停价色带 ──┐
├ 主图：周期 1d|60m|30m|15m|5m|1m|分时 + 昨收/涨停价参考线 + 成本线 + 买卖 markers + 竞价区段着色 ┤
├ 页签：消息(重要度筛选) | 逐笔/资金 | 基本面(财务排雷+券商分歧+AH溢价) ─────────────────────────┤
└ 侧栏 F10：筹码分布(获利比例/90%成本区) + 席位胜率(T+1/T+5) + 龙虎榜要点 ──────────────────────┘
```

**改造清单：**
- FE-M1 报价头全部改走 GetQuote 标准化口径；涨跌停价色带标在价格轴。
- FE-M2 周期扩展（依赖 BE-03 确认分钟级供给）；加分时视图。
- FE-M3 消息页签加重要度筛选（≥3/≥4）与来源链接。
- FE-M4 侧栏接入筹码分布+席位胜率两卡（纯接线，接口已在）。
- FE-M5 F10Drawer 接入 GetFinanceBrief/GetReportEstimates/GetAHPremium（抽屉壳已存在，填数据）。
- FE-M6 K 线叠加竞价区段着色与量比柱（GetAuction 数据）。

**后端依赖：** BE-03 分钟级多周期 bars 供给确认；BE-04 Quote 补量比/换手率。

**验收：** `GP 600519` 打开后一屏内得到 价格状态+量价+盘口+席位/筹码+消息 全景，无需切面板拼信息。

### 2.4 涨停梯队 + 异动流 + 情绪阶段 —— 打板情绪一屏

**现状评级：良，缺打板关键三问。**
梯队六卡+分层+炸板表；异动流表；情绪五阶段轨道。

**核心问题：**
- L1 情绪阶段三处重复渲染（limit-ladder 头、SentimentStages、emotion-review），数据期不同步。
- L2 梯队按封单额排序，打板更关心**封板时间先后**（谁带的头）——firstSealAt 数据在 emotion-review 有，梯队面板没有。
- L3 **昨日涨停今溢价（GetLimitPremium）与连板晋级率（GetLadder）后端 10-13 已补，梯队面板至今未接**——超短情绪复盘最核心的两列缺位。
- L4 异动流行无封单额（kind=limit_up 时）、无量比；行不可一键加自选。
- L5 情绪阶段无当日切换时点（GetEmotionPath 已有，只有复盘面板用）。

**目标形态：** 梯队面板头部=情绪细条（阶段+切换时点+仓位系数，取代独立大组件）；主体三页签：高度梯队（连板分层，行内封板时间+封单额）/ 封板时间线（按首封时间排序的横道）/ 溢价与晋级（昨涨停今表现双口径 + 1进2/2进3/3进4+ 晋级率）。异动流行内补封单额/量比，行操作=「加自选」「看行情」。

**改造清单：**
- FE-L1 接 GetLimitPremium + GetLadder 入梯队面板（纯接线）。
- FE-L2 梯队加「按首封时间」排序选项；行点击聚焦 quote-sidebar。
- FE-L3 情绪轨道下沉为头部细条，删独立重复组件。
- FE-L4 异动流行加封单额/量比列（推送帧带字段，见 BE）；行双击加自选草稿。

**后端依赖：** 异动推送帧带 sealAmount/量比；BE-05 板块归属（梯队题材分组）。

## 5. 验收标准（怎么算"清晰、舒适、有深度"）

1. **3 秒结论**：任意面板首屏不滚动能回答该面板的业务问题。
2. **3 次点击溯源**：任意数字/状态，3 次点击内到达其证据明细（抽屉或定位面板）。
3. **口径零歧义**：全仓搜索不到无注释的 pctText 调用；每个比率/百分比数字可说出单位与口径。
4. **时间可见**：信号、订单、预警、数据源任意对象能看到状态流转与数据时点。
5. **深度可达**：席位、筹码、财务排雷、AI 后验、拒绝趋势、盈亏分解六类深度数据各有界面落点。
