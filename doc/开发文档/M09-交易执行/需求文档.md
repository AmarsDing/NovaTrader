# M09 交易执行 · 需求文档

| 项 | 内容 |
|----|------|
| 模块 | M09 |
| 服务 | `trade`（DGX）+ `broker-gw`（Windows） |
| 版本 | v0.2（实盘通道改为东方财富量化终端文件单） |

## 1. 目标

模拟盘和实盘走同一套订单状态机。实盘不操作鼠标，由本机「东方财富量化终端」扫 CSV 文件单，再把资金、持仓、委托、成交写回文件，由 `broker-gw` 读回。

## 2. 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-09-01 | 账户分 `SIM` / `LIVE`；资金、持仓、委托、成交分开记账 | P0 |
| FR-09-02 | 订单创建、风控、提交、撤单；`client_order_id` 幂等；状态全留痕 | P0 |
| FR-09-03 | T+1：当日买入不可当日卖；持仓分总量、可卖、冻结 | P0 |
| FR-09-04 | 模拟撮合：涨停买不到、跌停卖不出、部分成交、费用和滑点。与回测共用实现 | P0 |
| FR-09-05 | 通道接口：`sim` 与 `eastmoney-file`。不实现界面点击下单 | P0 |
| FR-09-06 | 实盘：Windows 上东方财富量化终端保持登录，扫单目录由配置指定 | P1（通道联调；MVP 先做模拟盘） |
| FR-09-07 | 对账：盘中看委托和资金，收盘对持仓。不平则告警；严重不平停止开仓 | P0 |
| FR-09-08 | 限价、超时撤单、有限次重报、追价上限 | P1 |
| FR-09-09 | 止损止盈由本系统盯盘触发，不把规则交给终端里的手工条件单 | P0 |
| FR-09-10 | 手动下单同样先过风控 | P1 |
| FR-09-11 | 每 10 秒账户快照 | P0 |
| FR-09-12 | 成交后更新持仓并发事件 | P0 |
| FR-09-13 | 每笔成交能追溯到信号和策略版本 | P0 |
| FR-09-14 | 交易密码只留在量化终端登录态里。本系统不保存、不传输交易密码 | P0 |
| FR-09-15 | 半自动实盘前，模拟盘连续满 20 个交易日且准入清单通过 | P0 |

## 3. 验收

- 模拟盘 10 个场景与手工推演一致：涨停排队失败、部分成交、T+1 卖出被拒、费用、撤单。
- 文件单联调（有证券账户和量化终端之后）：仿真账户完成一笔买入、一笔撤单、一笔卖出，本地订单状态与 `order_status.csv` 一致。
- 实盘小额单通过后，才允许把模式从 L1 调到 L2。

## 4. 明确不做

- 不点击东方财富主界面下单。
- 不逆向 App 或网页的交易接口。
- 不把迅投 QMT / miniQMT 作为本项目通道。那是其他券商的产品，不是东方财富桌面端的官方程序化接口。
- 不使用「量化策略托管 SDK」做家里的实盘。官方说明该实盘 SDK 只在托管环境可用；家里能用的是本地文件单。
