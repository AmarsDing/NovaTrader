## 1. 你安装的软件和「能自动下单」差在哪

东方财富有三层，不要混成一个：

| 软件 | 作用 | 能不能被本系统自动下单 |
|------|------|------------------------|
| 东方财富免费行情终端 | 看行情、资讯 | 不能。没有交易柜台 |
| 东方财富证券交易（需在 18.cn 开户并登录） | 人工买卖、界面里的条件单 | 条件单要人在界面里逐条设置，不适合接收我们的信号 |
| **东方财富量化终端** | 终端里「量化」入口安装，文档站 emt.18.cn / emquant.18.cn | **能。** 本地实盘方式是文件单扫单 |

量化终端里还有仿真账户，手续费可改，用来联调通道。每个账号的仿真策略数量有限（文档写每个账号最多约 10 个仿真策略）。我们自己的日常模拟盘仍在 `trade` 服务里撮合，不占用终端仿真名额。终端仿真只在联调文件单时使用。

官方还提供策略 SDK。文档写明：本地能用的实盘能力是「量化扫单（文件单）」；SDK 实盘只能在券商托管环境。所以家里的 DGX + Windows 交易机采用文件单，不采用托管 SDK。

## 2. 文件单怎么工作

终端配置：手工交易 → 文件单 → 设置输入目录、输出目录，选中账户并保持登录，开启扫单。

下单（我们写，终端读）：

1. 在输入目录写入 `2026-10-08_09:41:03.120.order.csv`。
2. 关闭文件。
3. 再写一个空的同名标志 `2026-10-08_09:41:03.120.order.csv.fin`。终端看到 `.fin` 才认为写完，避免读到一半。

撤单文件后缀是 `.cancel_order.csv`，同样加 `.fin`。

委托 CSV 表头（名称必须这样写）：

```text
sid,account_id,symbol,volume,order_type,order_business(order_biz),price,comment
```

| 字段 | 我们怎么填 |
|------|------------|
| sid | 等于 `client_order_id`，全局唯一，不复用 |
| account_id | 量化终端里的账户 ID，放配置，不进代码仓库 |
| symbol | `SHSE.600519`、`SZSE.000001`。由内部 `600519.SH` 转换 |
| volume | 股数，已按板块取整 |
| order_type | 限价单用 `1` |
| order_business(order_biz) | 买入 `1`，卖出 `2` |
| price | 限价，必填 |
| comment | 可空。不写策略机密 |

股票限价、买、卖的取值来自官方数据字典（order_type=1 限价；股票 order_biz 1 买入、2 卖出）。上线前用仿真账户对一笔，确认终端版本没有改字典。

终端写回（我们读，按账户 ID 分子目录）：

| 文件 | 刷新方式 | 用途 |
|------|----------|------|
| cash.csv | 整文件覆盖 | 资金、可用 |
| position.csv | 整文件覆盖 | 持仓、今日仓、可卖 `available_now` |
| order_status.csv | 整文件覆盖 | 委托状态、已成数量、柜台 `order_id` |
| execution_report.csv | 末尾追加 | 成交回报 |
| order_status_change.csv | 末尾追加 | 状态变化流水 |

`position.csv` 的 `volume_today` 是今仓，`available_now` 是当前可卖。对账时以这两个字段校正本地 T+1 账本，不一致就告警。

## 3. 进程怎么接

```
DGX：trade
  风控通过后的订单
      │  gRPC（局域网 mTLS）
      ▼
Windows：broker-gw
  只在本机写 CSV / 读 CSV
      ▼
东方财富量化终端（已登录）
      ▼
东方财富证券柜台
```

DGX 与 Windows 不共享磁盘。`trade` 不能直接写 CSV，必须由本机 `broker-gw` 写。`broker-gw` 不保存交易密码，不落订单库；订单真值在 `trade` 的 PostgreSQL，柜台真值以扫单输出为准。

终端进程退出、扫单关闭、输出文件超过 N 秒不更新：`broker-gw` 报不健康。有实盘持仓时，`trade` 停止新开仓并通知你。已经发出、尚未确认的订单标成 `UNKNOWN`，只通过对账查 `sid`，不自动再写一张单。

## 4. 订单状态

```
CREATED → 风控拒绝（结束）
       → APPROVED → 半自动则等待你在客户端确认（超时作废）
                  → 提交中 → 已报 → 部分成交 → 全部成交
                           → 撤单中 → 已撤
                           → 柜台拒绝
                           → UNKNOWN（等对账，不重发）
```

模拟盘不写文件，走内存撮合器，状态机相同。

盯盘卖出（`source=watch`，来自 `risk.exit`）提交后不等实盘确认窗。仍挂着的限价单超过 60 秒就撤掉剩余，并按 0.01 元向不利方向重报，最多 2 次。卖出价格不低于第一张单的 99.5%，买入不高于 100.5%。到次数或到价格边界后只撤单，原因写「超时撤单，已到追价上限」。手动单和普通自动单不追价。重报单号是原单号加 `#1`、`#2`。

## 5. 和条件单的分工

量化终端自带条件单、网格、涨停开板。那些是在终端界面里人工配置的。本系统的止损、止盈、时间止损由 M08 盯盘，触发后仍生成一张普通限价文件单。不在终端里再挂一套条件，避免两边同时卖出。

## 6. 回写信号

成交和下单状态由本模块维护，信号状态仍只经 M06 的 `Transition` 修改。

- 买入委托有成交：把对应买入信号迁到 `done`，操作方 `trade`。
- 这只票的仓位归零：把**同一条买入信号**从 `done` 迁到 `closed`，带上 `exit_price` 和 `pnl_pct`。`pnl_pct` 是百分比，3.2 表示赚 3.2%，按实际成交价计算，不是按信号里的计划价。
- 卖出信号在卖出成交后停在 `done`，不要迁到 `closed`。仓位还没卖完也不要迁，M06 会因此停止按原止损止盈检查。

M04 只在 `closed` / `expired` / `cancelled` 时建案例，所以平仓必须走这一步，不能只发 `trade.fill`。

## 7. 上线顺序

1. `trade` + 模拟撮合（不需要东财账户）。
2. 你开通东方财富证券，并在量化终端登录，配好扫单目录。
3. 仿真账户：买入、撤单、卖出各一笔，对上 `order_status.csv`。
4. 模拟盘满 20 个交易日。
5. 小额实盘一笔，然后才打开 L2。
