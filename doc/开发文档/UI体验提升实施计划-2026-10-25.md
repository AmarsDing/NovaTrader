## 0. 执行总则

1. **顺序**：W1 → W8 依次推进；标注【可并行】的子批在满足依赖后可与其它窗口的并行子批同时开工（不同文件白名单时）。
2. **窗口纪律**：每个窗口开工前先 `git status` 查属主脏文件；白名单内的文件若被属主占用未提交，该子批顺延为「X.b」登记依赖，不混线。只提交自己文件（并行仓白名单断言 + commit + 校验同链）。
3. **门禁**：每窗口收口执行《0.UI制作规则.md》R-UI-H 全套（typecheck/eslint/vitest、gallery 走查、断流走查）；proto/表结构改动同步后端构建与隔离 PG 门禁。
4. **规约挂钩**：各子批卡片标注落实的 R-UI 条款与 §8.5 借鉴条目编号，评审按编号核。
5. **不留半成品**：窗口结束时，白名单内文件要么全交要么全退；跨窗口的半成品状态写回本文件「进度登记」。
