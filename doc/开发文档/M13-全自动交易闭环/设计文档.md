## T01 M06 四上游端口实接（strategy）

现状：`backend/app/strategy/internal/data/` 已存在端口（GetSentiment 恒 WARM、Analyzer 恒降级、NegativeNews 恒无、MarketSource 缺日线）。

设计：
- **GetSentiment → market(2021)**：HTTP 客户端拿当日情绪（五阶段），缓存 60s；取不到按数据纪律返回缺失→scan 侧情绪系数=1.0 且 candidates 标 `sentiment_missing`（不误认 WARM）。
- **Analyzer → brain(2051)**：批量 AnalyzeBatch(≤30) HTTP 客户端，超时/降级落 `ai_degraded`（现有逻辑不变，只是把假端口换成真客户端）。
- **NegativeNews → intel(2031)**：查询当日 `intel.alert` 利空集合（按 symbol）；无数据与「无利空」区分表达（空集 ≠ 未取到）。
- **MarketSource → datahub(2011)/market(2021)**：盘前池日线取自 market_data（服务内 data 层直读 ent 属横切越权，须走 HTTP 只读接口；若 market 尚无日线查询口，按 proto-first 在 `api/market/v1` 增补只读 RPC 后实现）。
- 端点地址走 `configs/config.yaml` infra 节惯例（参照 trade→risk client 的装配方式），wire 注入。

改动面：`app/strategy/internal/data/*.go`（新增 client 实现）、`app/strategy/internal/biz/scan.go`（接真端口+缺失标记）、`cmd/wire_gen.go`（`wire` 重新生成）、必要时 `api/market/v1/market.proto`（+pb 重生成）。

## T02 信号→计划自动消费者（trade）

设计：
- `app/trade/internal/core/runner.go` 新增 durable watcher：JetStream 订阅 `strategy.signal.updated`（ack 幂等：以 signal_id 作 execution_intent.business_key，重事件命中唯一约束即跳过）。
- 过滤链：type=buy ∧ status=pending ∧ final_score ≥ `app.trade.auto.score_min`（默认 80，appcfg 可改）∧ 模板 ∈ `app.trade.auto.templates` 白名单 ∧ 符号 ∉ 黑名单（读 stock_blacklist 经 risk Check 自然兜底）∧ ai_degraded 率治理：参数 `app.trade.auto.allow_degraded`（默认 false——AI 全挂时不自动开新仓，对应评审风险三①）。
- 动作：biz.CreatePlan(sim_auto) → AuthorizePlan；失败通知 notify（critical）。
- **契约固化**（automation.go 头注）：信号状态机 pending→approved 由 trade place() 内联同步 /risk/v1/check 承担最终闸；strategy 侧 risk_checking/approved 仅服务人工半自动流。

改动面：`app/trade/internal/core/runner.go`（+watcher）、`internal/biz/automation.go`（+AutoConsume、契约注释）、`pkg/params/validate.go`（三个 app.trade.auto.* 白名单键）、单测。

## T03 LIVE 出口接线（trade + brokerif）

设计：
- `biz/engine.go` place()/Confirm 在 BookLive 分支（三道闸全过后）：由 plan 构造 broker 指令（side/limit_price/qty/client_order_id=SID），调 `pkg/brokerif/remote.Client.Submit`；返回 UNKNOWN → 订单置 submitted + notify critical + order_trail 记 `transport_unknown`，**不自动重发**（沿用 broker-gw storage 纪律）；明确错误 → failed。
- 撤单：用户对 active 委托 Cancel → remote.Cancel。
- 双闸读取点统一收口在 `data.Settings`（T05 提供 setter）。
- 幂等：SID 生成沿用 execution_intent ClaimIntent；同 SID 重交返回原回执。

改动面：`app/trade/internal/biz/engine.go`、`core/runner.go`（dispatch 协程）、`conf/conf.proto`（BrokerFile 出口开关注释放开，重生成 pb）、测试（mock remote）。

## T04 实盘回报入账归并器（trade）

设计：
- `core/runner.go` 新增 reportLoop：交易时段 2s / 非交易时段 30s 轮询 `remote.Snapshot`（委托+成交+账户）。
- 归并规则：成交通知按 exec_id 唯一键入 trade_fill（PG 唯一约束兜底，重放即跳过）；现金/持仓走现有账本入口（含 T+1）；委托状态映射到 trade_order 状态机；账户快照对账复用 reconcile（不平→停开仓告警）。
- 无对应本地委托的回报 → event_disposition/人工核对队列（沿用 UNKNOWN 纪律，资产类异常必须人眼）。
- 用 broker-gw `simulator.py` 产出回报流做端到端测试。

改动面：`app/trade/internal/biz/report.go`（新）、`core/runner.go`、`data/`（fill 幂等写入）、单测+模拟器回放测试。

## T05 LIVE 放行机制（trade + risk + admin + web）

设计：
- LiveEnabled：持久载体 = strategy_config 键 `app.trade.live.enabled`（值含批准人/时间/准入证据引用）。`data.NewSettings` 映射该键；新增 RPC `GrantLive/RevokeLive`（admission.proto）：Grant 校验 PaperAdmission 就绪（RunEvidenceReady ∧ 连续≥20 交易日） ∧ Owner 角色 ∧ 先写 audit_log 后生效。
- BrokerConnected：runner 健康循环探测 broker-gw `/health` → 写内存态 + service_instance 心跳备注；掉线自动回落至 false（fail-closed）。
- risk R01 的 `risk.live_admitted` 参数与 app.trade.live.enabled 双闸语义写进 M08/M09 文档互链。
- web 设置面板：准入状态只读展示 + Grant/Revoke 按钮（Owner 才可见），经 admin 网关转发；敏感操作走现有强审计。

改动面：`app/trade/internal/data/data.go`、`biz/admission.go`、`api/trade/v1/admission.proto`（+重生成）、`app/admin/gateway` 回执目标集补 trade、`web/src/panels/`（设置面板增量，过 vue-tsc/eslint）。

## T06 LLM 底座治理（pkg/llm + params）

- ModelConfig 增 `disable_json_mode bool`：为 true 时不带 response_format（适配不支持 json_object 的模型）；默认 false 保持现状。
- `pkg/params/validate.go` 核账：app.brain.large.*/small.*、app.intel.llm.*、app.kb.embed_* 键白名单齐全且含 disable_json_mode、env:/enc: 前缀合法性。

改动面：`backend/pkg/llm/llm.go`(+stats 无改)、`pkg/llm/llm_test.go`、`pkg/params/validate.go`、`configs/config.yaml`（注释）。
