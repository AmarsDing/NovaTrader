# M08 风控 · 设计文档

版本 v0.3（2026-10-08 评审后修订）。

## 1. 代码位置

| 位置 | 内容 |
|------|------|
| `backend/pkg/ashare` | 涨跌停、价格笼子、手数、单笔上限。交易所规则只写在这里 |
| `backend/pkg/risk` | 纯函数：参数、规则链 R01–R15、盯盘、Kill Switch 状态、速度计数。不碰数据库和网络，回测（M07）直接调用 |
| `backend/app/risk` | 服务：内存账本、事件订阅、审计落库、Kill Switch 持久化、gRPC/HTTP 接口 |
| `backend/api/risk/v1/risk.proto` | 接口定义 |
| `ent/schema/risk_check.go`、`risk_event.go` | 校验审计、风控事件（Kill Switch、熔断、模式、参数变更） |

端口：http 2081、grpc 2082（M00 约定 20x1/20x2，按模块号取 8）。配置节 `risk`。

## 2. 运行模式

| 模式 | 含义 | 允许的订单 |
|------|------|------------|
| L0 | 只看 | 只允许人工卖出 |
| L1 | 模拟盘 | SIM 账户的自动单与人工单 |
| L2 | 半自动实盘 | 再加 LIVE 账户订单。LIVE 自动单由 `trade` 等你在客户端确认 |
| L3 | 全自动实盘 | 保留，当前按 L2 处理 |

切到 L2/L3 要求参数 `risk.live_admitted=true`（模拟盘满 20 个交易日且准入通过后由你打开）。模式和 Kill Switch 一起存在 `risk_event`，启动时读最后一条。

## 3. CheckOrder

目标时延 ≤ 50 毫秒。规则只读内存，不在校验路径上查库。行情按代码从 Redis `snap:latest` 读（内存缓存 1 秒）。审计记录放进有界队列（`risk.audit_queue`，默认 4096），后台每 200 毫秒或满 200 条批量写库；队列满时拒绝（R00），保证「每次放行都有记录」。

调用方（`trade`）给 200 毫秒超时，服务端同样以 200 毫秒为上限，超时视为拒绝（R00）。启动时先从库里恢复参数、模式、Kill Switch，恢复完成前所有校验返回 R00。

校验串行执行：放行后立刻记入速度计数、当日开仓笔数和预留（3.3 节），下一张单才开始校验。

重启时从库里恢复当日已锁存的账户熔断（`risk_event`）和已放行买单数（`risk_check`）。速度计数、预留、盯盘最高价、利空标记只在内存，重启后从零开始。

输入：订单（`client_order_id`、账户类型、标的、方向、限价、数量、来源 `auto`/`watch`/`manual`、操作人、板块）。服务从内存补齐账户、持仓、在途委托、行情、市场状态、计数，组成一份 `risk.Input`，规则链只看这份输入。输入整体写进审计。

输出：是否放行、最终数量、规则编号、原因、逐条结果。拒绝时停止在第一条失败规则。

### 3.1 规则细则与默认参数

参数存在 `strategy_config`，键前缀 `risk.`，改动走 `pkg/params.Put`（自动生成版本快照，可回滚），并写一条 `risk_event`（kind=`param`，含操作人和新旧值）。改完立即生效。

| 规则 | 判定 | 参数（默认） |
|------|------|--------------|
| R01 授权 | Kill Switch 已触发：只放行人工卖出。模式不够（见第 2 节）：拒绝。人工单必须带操作人 | `live_admitted`（false） |
| R02 行情新鲜 | 快照 `as_of` 距今超过阈值，或快照被 datahub 标为 stale：自动单拒绝，人工单放行。阈值大于 M01 的快照周期（约 3 秒）加一次重试 | `quote_max_delay_ms`（10000） |
| R03 可交易 | 停牌、无行情拒绝。不在 CALL_AUCTION / PRE_MATCH / AM_TRADING / PM_TRADING 拒绝。买入另外拒绝：ST、上市不足 N 日、黑名单 | `allow_st_buy`（false）、`min_list_days`（5）、`blacklist`（逗号分隔） |
| R04 价格 | 价格 > 0、在 0.01 价位上、在涨跌停内。连续竞价（9:30–11:30、13:00–14:57）再检查价格笼子 | 交易所规则，不可配 |
| R05 手数 | 买入按板块取整且不超单笔上限。卖出按余股规则 | 交易所规则 |
| R06 可卖 | 卖出量 ≤ 可卖 − 在途卖出冻结（T+1） | — |
| R07 单票 | 买入时账户快照缺失或 `as_of` 超过阈值：拒绝。（持仓市值 + 在途买入 + 本单）≤ 权益 × 单票上限 × 系数 | `max_single_pct`（0.05）、`account_max_age_sec`（60） |
| R08 总仓 | （总持仓市值 + 全部在途买入 + 本单）≤ 权益 × 总仓上限 × 系数 | `max_total_pct`（0.80） |
| R09 板块 | 同板块市值 + 在途 + 本单 ≤ 权益 × 板块上限。订单、持仓没带板块时用 `stock_basic.industry` 补；仍没有时放行并在结果里注明 | `max_sector_pct`（0.30） |
| R10 开仓笔数 | 当日已放行的买单数 < 上限 | `max_daily_buys`（10） |
| R11 流动性 | 基准成交额 = max(当日累计成交额, 昨日成交额)。低于下限拒绝；本单金额超过基准 × 参与率则缩量 | `min_turnover`（5000 万元）、`max_participation`（0.01） |
| R12 资金 | 本单金额 + 预估费用 ≤ 可用资金 − 本服务已预留金额 | 费用用 `ashare.DefaultFee` |
| R13 自成交 | 同账户同标的有反向在途委托且价格可撮合（买价 ≥ 在途卖价，或卖价 ≤ 在途买价）：拒绝 | — |
| R14 速度 | 近 1 秒申报+撤单 < 上限，当日申报+撤单 < 上限。对买卖、人工单都生效 | `max_orders_per_sec`（5）、`max_orders_per_day`（1000） |
| R15 熔断 | 买入在以下任一成立时拒绝：当日亏损达阈值、指数跌幅达阈值、炸板率达阈值、风险度为 3。当日亏损熔断按账户锁存到收盘，回本也不解除，次一交易日自动解除。指数、炸板、风险度按最新 `market.state` 实时判断，条件消失即恢复；每次进入和解除都写 `risk_event` 并发 `risk.alert` | `daily_loss_pct`（0.02）、`index_drop_pct`（0.02）、`burst_rate_max`（0.5） |

R00 不属于规则链，表示请求本身无法校验：字段非法、风控未就绪、超时、审计队列已满。

缩量：R07、R08、R09、R11、R12 超限时把数量缩到上限内，再按板块取整。取整后不足一手则拒绝。结果写明「原数量 → 新数量」和触发规则。

### 3.2 仓位系数（FR-08-03）

系数 = 情绪系数 × 风险度系数，作用在 R07、R08 的上限上。

情绪系数优先用 `market.state` 里 M02 算好的 `position_scale`（在 (0, 1] 内时）；没有时按阶段查表。表的默认值与 M02 设计文档一致：

| 情绪阶段（M02） | ICE | RECOVER | WARM | HOT | FADE | 缺失 |
|-----------------|-----|---------|------|-----|------|------|
| 系数 | 0.2 | 0.5 | 0.8 | 1.0 | 0.3 | 0.5 |

| 风险度（0 正常 … 3 极高） | 0 | 1 | 2 | 3 |
|---------------------------|---|---|---|---|
| 系数 | 1.0 | 0.7 | 0.4 | 0（R15 直接拒绝开仓） |

风险度取 max(M02 `risk_level`, 参数 `risk_level`)。参数是你手工设的下限，默认 0。

两张表都可配：`phase_scale`、`risk_scale`，值为 JSON 对象。

### 3.3 预留

放行一张买单后，在内存里预留它的金额和市值，直到收到 `as_of` 晚于放行时刻 2 秒以上的账户快照，或 60 秒过期。这样两张单在同一个 10 秒快照周期里不会重复用同一笔资金。

## 4. 盯盘（FR-08-04）

每收到一次 `market.snapshot` 就从 Redis 读全部持仓标的的快照检查一次；超过 3 秒没收到该事件时自己轮询，止损不依赖事件。触发后发布 `risk.exit`，由 `trade` 生成卖单并照常调 `CheckOrder`（来源 `watch`）。同一持仓 60 秒内不重复发，发布失败时立即允许重发。只在可交易时段、可卖 > 0 时触发。

优先级从高到低（命中第一条即止）：

| 触发 | 条件 | 参数（默认） |
|------|------|--------------|
| 止损 | 现价 ≤ 止损价。持仓没有止损价时用成本 × (1 − 默认止损) | `stop_pct`（0.05） |
| 指数急跌 | 指数 5 分钟跌幅 ≤ 阈值 | `index_plunge_5m`（-0.015） |
| 突发利空 | 当天收到涉及该标的的 `intel.alert`，且情感分 ≤ 阈值 | `bad_news_sentiment`（-0.5） |
| 移动止盈 | 最高浮盈 ≥ 启动线，且从最高价回撤 ≥ 回撤线 | `trail_start_pct`（0.05）、`trail_drawdown_pct`（0.03） |
| 止盈 | 现价 ≥ 止盈价 | — |
| 时间止损 | 持有 ≥ N 个交易日、进入尾盘（14:30 后）、浮盈 < 最小收益 | `time_stop_days`（2）、`time_stop_min_gain`（0.01） |

卖出数量 = 可卖数量（按余股规则合法）。卖出价 = 买一 − N 个价位，不低于价格笼子下沿和跌停价。参数 `exit_slip_ticks`（2）。

最高价在内存里按行情维护，重启后从 max(成本, 现价) 重新开始。

## 5. Kill Switch（FR-08-06）

| 来源 | 怎么进来 |
|------|----------|
| 客户端按钮 | admin 转调 `TriggerKillSwitch` |
| 对账严重不平、量化终端失联 | `trade` / `broker-gw` 发 `sys.killswitch.request` |
| 行情中断且仍有持仓 | 风控自己判断：交易时段内超过 `market_down_sec`（30）秒没有新行情，且有持仓。「新行情」指非 stale 的 `market.snapshot` 心跳，或持仓标的快照的 `as_of` 前进。计时从进入交易时段算起，午休不计 |

`sys.killswitch.request` 用 JetStream 持久消费者 `risk-killswitch` 收，风控重启期间发出的请求重启后照样处理。载荷 `{"source","reason"}`，source 为空时取信封来源。

触发：先在内存里停止放行，再在同一事务写 `risk_event`（kind=`killswitch`，active=true，来源、原因）和 outbox，由 outbox 投递 `sys.killswitch` 和 `risk.alert`。模式降到 L0。落库失败时内存保持触发，每秒重试，请求消息也会重投。`trade` 收到后停收新单并撤未成交单，`strategy` 停发开仓信号。

恢复：只能调 `ResetKillSwitch`，必须带操作人和确认字样 `CONFIRM`。恢复后模式仍是 L0，你再单独选择模式。恢复同样落库并发 `sys.killswitch`（active=false）。

重启时读最后一条 killswitch 事件，已触发则保持触发。

## 6. 事件

| 主题 | 方向 | 内容 |
|------|------|------|
| `trade.account` | trade → risk | 账户快照（每 10 秒）：账户类型、权益、可用、日初权益、持仓（数量、可卖、冻结卖出、成本、市值、板块、止损价、止盈价、持有交易日数）、在途委托 |
| `trade.order` | trade → risk | 委托动作，`action=cancel` 时计入速度计数 |
| `market.snapshot` | datahub → risk | 每轮快照写完的心跳 `{as_of, count, stale}`。快照本身从 Redis `snap:latest` 读（`pkg/market.Snapshot`） |
| `market.state` | market → risk | M02 `pkg/market.State`：`phase`、`risk_level`、`index_pct`（百分数）、`index_pct_5m`（百分数）、`broken_rate`（0–1）、`position_scale` |
| `intel.alert` | intel → risk | M03 预警：`stocks`、`sentiment`、`title`。持久消费者 `risk-intel-alert`，只认当天的 |
| `sys.killswitch.request` | 任意 → risk | 请求触发 Kill Switch |
| `sys.killswitch` | risk → 所有 | Kill Switch 状态，只有 risk 发 |
| `risk.exit` | risk → trade | 盯盘卖出请求 |
| `risk.alert` | risk → notify | 熔断、Kill Switch、拒单率异常 |

拒单率：每秒看最近 `reject_alert_window_sec`（300）秒的校验。样本不少于 `reject_alert_min`（20）且拒绝率达到 `reject_alert_rate`（0.5）时，写 `risk_event`（kind=`reject_rate`）并发 `risk.alert`。之后 `reject_alert_cooldown_sec`（1800）秒内不重复发。`reject_alert_min` 设为 0 即关闭。样本不足不告警，避免开盘前几笔拒单就响。

ST、停牌、上市日、板块来自 `stock_basic`，昨日成交额来自 `market_data`（freq=`1d`，最近一个已收盘交易日），每 10 分钟刷新一次。

`trade.account`、`trade.order` 由 M09 实现；落地前以本节和 `backend/app/risk/internal/biz/payload.go` 为准。代码统一用 `600519.SH` 形式，收到其他写法（如 `sz000001`）会先规范化。

## 7. 接口（`api/risk/v1`）

| 方法 | HTTP | 说明 |
|------|------|------|
| CheckOrder | POST /risk/v1/check | 事前校验 |
| GetState | GET /risk/v1/state | 模式、Kill Switch、熔断、当日计数、参数 |
| SetMode | POST /risk/v1/mode | 改模式，需操作人 |
| TriggerKillSwitch | POST /risk/v1/killswitch | 触发 |
| ResetKillSwitch | POST /risk/v1/killswitch/reset | 恢复，需操作人和 `CONFIRM` |
| UpdateParam | POST /risk/v1/params | 改参数，先校验再落库 |
| DailyReport | GET /risk/v1/report | 当日校验数、拒绝按规则分布、熔断与 Kill Switch 事件 |

客户端不直连本服务，经 admin 转发（M11）。

## 8. 演练

模拟盘连续运行满 20 个交易日、准入通过之前，每一项都要在交易时段演过一遍并留下记录。

| 项 | 怎么做 | 通过标准 |
|----|--------|----------|
| 当日亏损熔断 | 把模拟账户权益打到日初的 98% 以下 | 买单被 R15 拒绝，卖单放行；权益回到日初之上仍然拒绝；次日恢复。重启后当日仍然拒绝 |
| Kill Switch | 客户端触发，再强杀 risk 进程后拉起 | 重启后仍是触发态，自动买单被 R01 拒绝。人工卖出放行。没有操作人和 `CONFIRM` 不能恢复。恢复后模式仍是 L0 |
| 外部触发 | broker-gw 或 trade 发 `sys.killswitch.request` | 收到 `sys.killswitch`（active=true）和 `risk.alert`。risk 停机期间发出的请求，拉起后仍被处理 |
| 行情中断 | 停 datahub 的快照，账户里留一手持仓 | 超过 `market_down_sec` 后 Kill Switch 触发，来源是 market。午休和刚开盘的 30 秒内不触发。持仓标的停牌、全市场心跳还在时不触发 |
| 盯盘卖出 | 持仓现价打到止损价 | 发出一条 `risk.exit`，60 秒内不重复。trade 据此下的卖单 source=`watch`，仍过 CheckOrder |
| 终端扫单停止 | 量化终端失联，broker-gw 发请求 | 与 Kill Switch 相同：停新单、撤未成交。这一项等终端和 broker-gw 接上后做 |
| 拒单率 | 连续制造超过 20 笔、一半以上被拒的校验 | 一条 `risk.alert`，30 分钟内不重复 |
