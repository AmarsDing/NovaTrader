# M14 智能体底座对接 · 设计文档

2026-11-02 v0.1。对齐底座 aranea-agents P0 改造（多调用方 caller 注册表、
租户门禁、webhook SSRF 双闸、幂等键持久化、GET /api/v1/runs 列表端点）。

## 1. 包结构（`backend/pkg/harness`）

| 文件 | 职责 |
|------|------|
| `doc.go` | 定位与诚实边界声明 |

| `errors.go` | `Error{Kind,Detail}`：Kind 哨兵供 errors.Is 分流，Detail 如实文案（绝不带密钥材料） |

## 2. 关键设计决策

### D1 恒阻断永驻（对齐 HCF ADR-AGT-01 同构）

`driver=blocked`（默认）或 token 解析失败/为空时，`NewClient` 返回
`blockedClient`——全部方法返回 `ErrHarnessContractUnverified`（带如实
reason）。该实现与对应契约测试（`TestBlockedClient_ContractNeverRemoved`，
标记永不删除）**永驻**：即使 http 适配器实机验证通过，blocked 路径仍是
配置缺失时的唯一合法行为。禁止把「底座未接通」塌成空列表/假在线。

### D2 token 解析复用 NT 密钥纪律

`NewClient(conf, resolveToken)` 的 resolveToken 由调用方注入，生产接线用
`llm.ResolveAPIKey`（明文/env:/enc: 三写法，密钥文件 `NT_LLM_SECRET_KEY_FILE`
同一套）。harness 包不直接 import llm——依赖经函数注入，保持包为叶子。

### D3 幂等键为客户端强制纪律

`SubmitRun` 在客户端侧即校验 `graph_id`/`idempotency_key` 非空（缺失返
`ErrHarnessBadRequest` 且**不发请求**）。底座侧按 (caller, key) 持久化去重
（表 twin_openapi_idempotency，7 天窗口，重启有效），重放返回
`{run_id, idempotent_replay:true}`。NT 业务侧按键规约 `nt-<业务域>-<业务ID>`
生成。

### D4 状态码→哨兵映射（诚实错误面）

| 底座状态 | 哨兵 | 说明 |
|---|---|---|
| 2xx | nil | 契约漂移（200 缺 run_id/解码失败）→ Unavailable 如实标注 |
| 400 | ErrHarnessBadRequest | 参数/白名单拒绝，底座文案透传 |
| 401/403 | ErrHarnessUnavailable | 注明「token 失效或未注册 caller」 |
| 404 | ErrHarnessNotFound | run/graph 不存在或租户不可见（底座门禁不泄漏存在性） |
| 5xx/网络 | ErrHarnessUnavailable | 子错误如实带上游原因 |

### D5 底座 P0 配套口径（本包依赖的上游事实）

- caller 注册：底座 `ARANEA_TWINOPENAPI_CALLERS` 需含
  `{"name":"novatrader","token":<env下发>,"workspace_id":"ws-novatrader"}`；
  存量 `ARANEA_TWINOPENAPI_TOKEN` 恒为 caller=twinmonitor（系统级），
  NT 不复用它。
- 租户门禁：NT caller 读面=共享+ws-novatrader 自有；写面=仅自有。
  共享图对 NT 可见但不可执行（底座 404，本包透传 NotFound）。
- webhook：NT 传回调地址时受底座双闸约束（默认档=内网限定；严格档需
  白名单登记）。secret 由 NT 生成自存验签，严禁复用 Bearer。
- run 列表：`GET /api/v1/runs?graph_id=` 为 P0 新增端点（此前机器面
  无列表，HCF AGT 曾被迫绕行交互面 JWT——该缺口已在底座侧闭合）。

### D6 webhook 接收端 = 无状态验签入口（T05 定案，2026-11-03）

设计裁定「run 追踪归属哪个服务」：NT harness 是**无状态客户端**，
仓内不建 run 表、不新立接收进程——run 状态归属提交方业务自己的记账面
（提交时本就持有 run_id + 幂等键）。故 T05 交付为 `webhook.go`
库级三件套：

- `SignV1(secret, ts, body)` / `VerifyV1(secret, tsHeader, sigHeader, body, now)`：
  与底座 `pkg/outboundwebhook.SignBody`、HCF `biz/agt.signWebhookV1`
  **逐字节同构**（消息形状 `"<ts-unix>\n<body>"`，签名头
  `v1=<hex-hmac-sha256>`，重放窗 ±5min）。
- `WebhookEvent`：`twinEventEnvelope` 忠实投影（payload 原文保留）；
  `InterruptID()` 只从 `run.waiting_approval` 的 payload 取值（底座保证
  interrupt_id==node_id）。
- `NewWebhookHandler(resolveSecret, consume)`：POST-only（405）/ 体限
  2MiB（413）/ 验签四态合一 401 同面防枚举 / 信封契约漂移 400 / 消费方
  故障 500 上抛。resolveSecret **每请求现取**（改密即时生效；与 caller
  token、nt-mcp token 三分立，严禁复用 Bearer）。

终态摄取双轨同 HCF W10 口径：webhook 只做加速，轮询 `GetRun` 常态兜底；
短窗口 run（提交→终态 < 一拍摄取间隔）由轮询兜底，无回退。
进程内挂载（挂哪个 HTTP 服务）是 T04 同一部署窗口事项；standalone
nthook 进程为摆设，不建。

### D7 审批回路消费 = 事件投递 + ResumeRun 能力（T06 定案，2026-11-03）

`Client.ResumeRun(ctx, runID, interruptID, decision)` →
`POST /api/v1/runs/{id}/interrupts/{interrupt_id}/resume`
（body `{approved,comment,approver_id}` 与底座 twinResumeDecision 键名对齐；
404→NotFound，400→BadRequest 透传底座文案，客户端必填校验不发请求）。
**红线**：harness 只提供能力，决议仅来自人工审批面（M09）——本包
**绝不自动 approve**（NT 纪律：LLM 只产出评分与理由，不直接推进执行）。
waiting_approval 事件的消费方（读 `WebhookEvent.InterruptID()` + run_id
→ 推人工审批队列 → 人工决议后调 ResumeRun）属业务侧立项，随 T04 上机。

## 4. 反向消费面：nt-mcp（三仓联动 P3，2026-11-02 定案）

aranea → NT 方向的**只读**工具暴露。独立进程 `cmd/ntmcp`（包
`pkg/ntmcp`：conf/server/tools/store），trpc-mcp-go v0.0.10 Streamable
HTTP `:9303`（仅内网）。

### 工具面（四件，全只读）

| 工具 | 入参 | 数据源 | 投影要点 |
|------|------|--------|---------|
| `query_market_snapshot` | symbols?, limit | Redis `snap:latest` HGETALL（datahub 同源） | 昨收/最新价/量额/五档/stale 时效标记原样透传；limit 服务端钳制 |
| `get_positions` | book=paper\|live | PG `positions` + `trade_cash` | 数量/可卖/成本/现价/浮盈 + 现金/日初权益；cash 缺行≠零（缺省不下毒） |
| `list_trade_signals` | book?, status?, side?, day?, limit | PG `trade_signals` | 信号类型/价格带/评分/状态/平仓结果；reasoning 截断 240 rune |
| `get_backtest_report` | task_id | PG `backtest_task` + `backtest_report` | 任务态/收益/回撤/夏普/胜率/前瞻校验；result 大 JSON 只给 `result_bytes` 体积不下发 |

### 纪律（与 harness / HCF hcf-mcp 同口径）

- **只读**：store 层只有 Query 链，不建库不迁移（绕过 entclient.Open，
  `dbinit.BusinessDSN` + `sql.Open(pgx)` 直连）；下单/改仓绝不进 MCP。
- **「错误≠空列表」**：仓储/Redis 错误落得 IsError 如实报，绝不塌成
  空数组装活。
- **鉴权**：静态 Bearer（`token_ref` env:/enc:/明文三写法经
  `llm.ResolveAPIKey` 启动时解析，失败/空值即拒启动）；常量时间比对；
  与 harness caller token、HCF AGT caller token **三分立**。
- **入参不信任**：limit 服务端钳制（`page_size_max=50`），book/side/day
  枚举校验，task_id 必填正整数。
- **配置**：`configs/config.yaml ntmcp:` 段（enabled 默认关、listen、
  token_ref、page_size_max、http_timeout、tools 白名单）。
