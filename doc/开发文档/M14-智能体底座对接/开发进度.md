### M14-T05/T06 明细（2026-11-03 仓内落地，P2 后段）

- **设计裁定（D6/D7，设计文档 §2）**：「run 追踪归属哪个服务」此前悬置——
  定案为 NT harness **无状态客户端**，仓内不建 run 表、不新立接收进程；
  run 状态归属提交方业务记账面（run_id + 幂等键提交时本就持有）。故两件
  均为 `pkg/harness` 库级交付，消费回调注入。
- **T05 webhook 接收端三件套（`webhook.go`）**：`SignV1/VerifyV1`
  （与底座 `pkg/outboundwebhook.SignBody`、HCF `biz/agt.signWebhookV1`
  **逐字节同构**：`"<ts-unix>\n<body>"` + `v1=<hex-hmac-sha256>` +
  ±5min 重放窗）；`WebhookEvent` 信封忠实投影（`InterruptID()` 仅从
  `run.waiting_approval` payload 取值）；`NewWebhookHandler(resolveSecret,
  consume)` 无状态验签入口——POST-only 405 / 体限 2MiB 413 / 验签四态
  合一 401 同面防枚举 / 信封契约漂移 400 / consume 故障 500 如实上抛。
  resolveSecret 每请求现取（与 caller token、nt-mcp token 三分立）。
- **T06 审批回路（Client.ResumeRun）**：`POST /api/v1/runs/{id}/interrupts/
  {interrupt_id}/resume`（body `{approved,comment,approver_id}` 与底座
  twinResumeDecision 键名对齐；404→NotFound、400→BadRequest 透传底座文案；
  run_id/interrupt_id 客户端必填校验不发请求；阻断实现恒阻断）。**红线**：
  harness 只提供能力，决议仅来自人工审批面（M09）——本包**绝无自动
  approve**；waiting_approval 事件 → 人工审批队列 → ResumeRun 的消费方
  属业务侧立项。
- **测试钉死全绿**：T-WH-NT-01（验签 401 同面五态）、T-WH-NT-02（SignV1
  算法形状 + 派发投影）、T-WH-NT-03（405/400 三态/413/500）+ 03b
  （InterruptID）、T-WH-NT-04（ResumeRun 契约/哨兵/必填不发请求）；
  `TestBlockedClient_ContractNeverRemoved` 增补 ResumeRun 检查。
  `go test ./pkg/harness/ -count=1` 11 件全绿；`go build ./...` 全绿。
- **部署项结转（随 T04 窗口同批）**：①业务侧选定挂载进程（admin :9302

## 如实声明

- 首版 driver 默认 `blocked`：**功能未实机验证前不宣称可用**。恒阻断路径
  与 `TestBlockedClient_ContractNeverRemoved` 永驻。
- 底座侧依赖（caller 注册、租户 workspace 分配）未部署前，本包一切调用
  如实返回 `HARNESS_CONTRACT_UNVERIFIED`。
- 本模块不触碰交易链路红线：底座 run 输出仅为分析结论，下单仍经 M08
  风控 + M09 文件单。
- **审批红线（T06 补充）**：`ResumeRun` 仅为能力面——决议仅来自人工审批
  面（M09），本包**绝无自动 approve**；LLM 只产出评分与理由，不直接
  推进执行。
- nt-mcp（T07）为**反向**消费面（aranea→NT 读），与 harness（NT→aranea
  提交/查询）方向相反、凭据分立；两者互不替代。
- T05 webhook 接收端为**库级交付**（D6）：仓内无 run 追踪面、无新进程——
  终态加速生效以业务侧挂载 handler + 提交面携带 webhook_url 为前提，
  未接线前终态摄取 = 轮询兜底（无回退）。
