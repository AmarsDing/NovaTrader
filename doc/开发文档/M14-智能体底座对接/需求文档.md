## 定位（如实声明，勿夸大）

本模块是 aranea-agents 底座的**客户端**：健康探测、agent 目录、run
提交/查询/取消。它**不是**宿主机监护/进程管理的承载者——进程级监护
（服务重启、守护）属底座侧能力边界，NT 仓不实现（M11 FR-11-08 边界声明
已按此修订，2026-11-02）。

## 需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-14-01 | 底座健康探测（机器面 GET /api/v1/health 忠实投影，不可达如实报错不冒充健康） | P0 |
| FR-14-02 | agent 目录拉取（GET /api/v1/agents；caller 租户面=共享+自有，由底座门禁裁决） | P0 |
| FR-14-03 | run 提交（POST /api/v1/runs；graph_id 必填——底座不支持 agent 直跑；idempotency_key 必填——底座按 caller+key 持久化去重） | P1 |
| FR-14-04 | run 详情/列表/取消（GET /api/v1/runs/{id}、GET /api/v1/runs?graph_id=、POST cancel；列表 graph_id 必填） | P1 |
| FR-14-05 | 恒阻断兜底永驻：driver=blocked 或 token 未配置时一切调用返回 ErrHarnessContractUnverified，禁止塌成空数据 | P0 |
| FR-14-06 | 密钥纪律：Bearer token 仅经 env:/enc:/明文三写法解析（复用 pkg/llm.ResolveAPIKey 语义），严禁入仓入库 | P0 |

## 非目标（首版明确不做）

- 进程级监护/重启（属底座侧，NT 不做）。
- webhook 接收端（NT 侧 HTTP 回调入口）：首版轮询 GetRun 兜底终态；
  回调接收端列入 P2（届时 secret 由 NT 生成自存验签，严禁复用 Bearer）。
- 审批回路（waiting_approval → resume interrupt）：底座端点已具备，
  NT 消费侧列入 P2。
- 大模型直接下单：底座 run 输出仅为分析结论，下单仍走 M08 风控+M09
  文件单既有链路（本模块不改变该红线）。
