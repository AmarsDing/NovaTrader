| 输入 | 来源 | 现状 |
|------|------|------|
| 全市场快照、日线 | M01 / M02 | 未完成。服务里是 `MarketSource` 端口。先提供一个读 `stock_basic` + `market_data` 日线的实现 |

## 2. 漏斗

```
全市场约 5000 只
  → 硬过滤：ST、停牌、上市不足 90 个自然日、昨日成交额 < 5000 万、当前价已在涨停价、黑名单
  → 每个模板 Filter，命中的再 Score。同一只股票命中两个模板时取高分
  → 规则分排序，取前 100（rule_top_n），写入候选表
  → 去掉已持仓、冷却中、有未结买入信号的
  → 前 30 名（ai_top_n）调用 M05，并发 4
  → 融合成综合分，≥75 入选
  → 当日买入信号数不超过 5（max_daily_signals）
  → 0～5 条买入信号
```

盘前扫描（09:00）只建盘前池，不出信号：开盘前没有当日价格，入场区间无从计算。

盘中：

- 事件触发为主。订阅 `market.alert`（M02 发布，载荷 `{"symbol":"600519.SH","kind":"limit_up|break|surge"}`），把标的放进盘中池，2 秒防抖后只扫盘中池 + 盘前池。
- 兜底定时：交易时段每 60 秒扫一次盘中池 + 盘前池；每 10 分钟做一次全市场扫描。
- 14:50 以后不出买入信号（`buy_cutoff`）。

性能：规则部分是纯计算，5000 只在 1 秒内。3 分钟的预算主要留给取数和 30 次模型调用。

## 3. 策略接口（`pkg/rules`）

策略不能查库。引擎把「此刻可见」的数据装进 `Snapshot` 交给策略。

```go
type Snapshot struct {
    Symbol, Name   string
    ST, Suspended  bool
    ListDate       time.Time
    AsOf           time.Time
    Bars           []Bar  // 已收盘的日线，旧 → 新，不含当日
    Today          *Bar   // 当日到 AsOf 为止；盘前为 nil
    Stage          Stage  // ICE RECOVER WARM HOT FADE
    NegativeNews   bool
}

type Strategy interface {
    Name() string
    Filter(ctx, Snapshot) bool
    Score(ctx, Snapshot) float64            // 0～100
    EntryPlan(ctx, Snapshot) (Plan, bool)   // 参考入场价、最长持有天数
    ExitPlan(ctx, Snapshot, Position) (Plan, bool)
}
```

同一文件里还有：`HardFilter`、`Screen`（漏斗规则部分）、`Fuse`（融合）、`Price`（价格）、`ATR`/`MA` 等指标。回测传历史 `Snapshot`、实盘传实时 `Snapshot`，调用的是同一批函数。

## 4. 两个模板

阈值都是默认值，放在 `strategy_config`，键名见第 13 节。

### 4.1 `first_board_weak2strong`（首板 / 弱转强）

前提（看已收盘日线）：

1. 昨日触及涨停价（最高价 ≥ 涨停价）。收在涨停为「封板」，没收住为「炸板」。
2. 前 5 个交易日（不含昨日）没有收盘涨停，确保是首板。
3. 昨日成交额 ≥ 前 5 日均额 × 1.5（放量）。

触发（看当日）：

4. 开盘涨幅在 0%～6% 之间（高开，但不是一字或大幅高开）。
5. 当前价 ≥ 开盘价，且当前价涨幅 ≥ 2%（高开高走，弱转强）。

打分（满分 100）：基础 40；昨日封板 +15、炸板 +10；放量倍数 / 3 封顶后 × 15；开盘涨幅在 1%～4% 加 15，在 0%～1% 或 4%～6% 加 8；（当前价 − 开盘价）/ 昨收 封顶 5% 后折算最多 10；昨日成交额 ≥ 3 亿 +5。

最长持有 2 个交易日。

### 4.2 `pullback_dip`（强势回踩）

前提：

1. 近 10 个交易日至少一次收盘涨停，或区间涨幅 ≥ 20%（强势）。
2. 当前价距近 10 日最高价回撤 8%～20%，且最高价不在今天。
3. MA10 > MA20，当前价 ≥ MA20（趋势未破）。
4. 当前价与 MA10 偏离不超过 3%（回到支撑）。
5. 昨日成交量 ≤ 前 5 日均量 × 0.7（缩量回踩）。

触发：当前价 ≥ 当日最低价 × 1.01，且 ≥ 昨收 × 0.98（止跌）。

打分：基础 40；回撤越接近 12% 越高，最多 15；缩量比 ≤0.5 得 15，0.5～0.7 线性降到 5；(MA10/MA20 − 1) 封顶 5% 后折算最多 15；区间涨停 1 次 +5、2 次及以上 +10；（当前价 − 当日最低）/ 昨收 封顶 3% 后折算最多 5。

最长持有 5 个交易日。

## 5. 融合与阈值

```
系数 = 情绪阶段系数（ICE 0.80，RECOVER 0.95，WARM 1.00，HOT 1.05，FADE 0.85，与 M05 相同）
正常：综合分 = 0.4 × 规则分 × 系数 + 0.6 × AI 分
降级：综合分 = 规则分 × 系数，信号标 ai_degraded
```

AI 分是 M05 已乘过情绪系数的综合分，所以系数只乘在规则分上。结果截在 0～100。

- 综合分 ≥ 75 入选；≥ 85 标高价值（`high_value`）。
- 模型不可用（超时、网关挂掉、未接入）：走降级公式。
- 单只返回的 JSON 校验失败（M05 已重试一次）：丢掉这一只，候选记 `ai_invalid`。

回测没有模型，始终用降级公式。

## 6. 价格与仓位

全部在 `rules.Price` 里，由代码计算，不用模型给的数。

| 项 | 规则 |
|----|------|
| ATR | 近 14 根已收盘日线的真实波幅简单平均（与通达信 `ATR` 同口径）。日线不足 15 根不出信号 |
| 参考价 | 模板 `EntryPlan` 给出，两个模板都取当前价 |
| 入场区间 | 参考价 ± 0.25 × ATR |
| 止损 | 入场 − 2 × ATR，但跌幅不超过 7%（`max_stop_pct`），超过则取入场 × 0.93 |
| 止盈 | 入场 + 3 × ATR |
| 取整 | 全部用 `pkg/ashare` 取到分，并夹在信号当日涨跌停价之间 |
| 合法性 | 必须 止损 < 入场下沿 ≤ 入场 ≤ 入场上沿 < 止盈，否则不出信号（例如当前价已贴着涨停） |
| 时间止损 | 模板的最长持有天数（2 / 5），写入信号 `hold_days_max` |
| 有效期 | 出信号后 30 分钟，最晚当日 14:57 |
| 仓位 | `position_pct`：高价值 5%（`position_per_stock`），其余 × 0.6 = 3%。情绪缩放和上限由 M08 做 |

卖出价：当前价 × (1 − 0.5%)，夹在跌停价之上。股数为全部可卖数量。

## 7. 信号与状态机

`trade_signals` 在原有字段上追加（全部有默认值或可空）：`strategy`、`strategy_version_id`、`trade_date`、`entry_low`、`entry_high`、`position_pct`、`valid_until`、`hold_days_max`、`rule_score`、`ai_score`、`dims`（四维分 JSON）、`evidence`（证据 ID 列表）、`ai_degraded`、`high_value`、`exit_kind`、`atr`、`trace_id`、`exit_price`、`pnl_pct`、`closed_at`、`holding_days`。`confidence_score` 存综合分。`pnl_pct` 是百分比，3.2 表示 +3.2%，与 M04 案例一致。

| 状态 | 含义 |
|------|------|
| `pending` | 待处理 |
| `risk_checking` | 风控中 |
| `approved` / `rejected` | 风控通过 / 拒绝 |
| `executing` | 已下单 |
| `done` | 这笔委托有成交。买入的 `done` 表示已开仓，还不是一笔走完的交易 |
| `closed` | 买入信号对应的仓位已归零 |
| `expired` | 过期 |
| `cancelled` | 取消 |

| 从 | 可以到 |
|----|--------|
| pending | risk_checking、expired、cancelled |
| risk_checking | approved、rejected（风控超时按拒绝） |
| approved | executing、expired、cancelled |
| executing | done、cancelled（零成交撤单） |
| done | closed（只针对买入信号） |

`rejected`、`closed`、`expired`、`cancelled` 是终态。卖出信号停在 `done`，不迁到 `closed`。非法迁移返回错误，不改库。

操作方（`actor`）也受限，防止绕过风控：

| 迁移 | 允许的操作方 |
|------|--------------|
| → risk_checking、approved、rejected | `risk`（M08） |
| → executing、done、closed、executing → cancelled | `trade`（M09） |
| → expired | `strategy`（到期任务） |
| pending / approved → cancelled | `user`、`risk`、`trade`、`strategy` |

接口：HTTP 2061 / gRPC 2062，`api/strategy/v1/strategy.proto`。`POST /v1/strategy/signals/{id}/transition` 改状态（非法迁移 400，并发冲突 409）；另有信号与候选查询、手动扫描、黑名单增删。

每次迁移在同一事务里：更新 `trade_signals.status`、写一行 `signal_events`（from、to、原因、操作方、trace_id）、写 outbox 事件。M08 / M09 改状态都调用 strategy 的 `Transition` 用例，不直接写表。

M09 在买入委托成交时把信号迁到 `done`。等这只票的仓位归零，再把**同一条买入信号**迁到 `closed`，并带上 `exit_price`、`pnl_pct`（百分比）、`closed_at`。`holding_days` 由 M06 按交易日计算。缺出场价或收益率、卖出信号、非 `trade` 操作方都拒绝。仓位还没卖完不要迁，否则这只票不再按原止损止盈出信号。M04 收到 `status=closed` 后按收益率记盈亏案例。

到期任务每 30 秒把 `valid_until` 已过的 `pending` / `approved` 改为 `expired`。

## 8. 冷却与去重

- 已持仓（`positions.quantity > 0`）不出买入信号。
- 同股同方向有未结信号（非终态）时不再出。
- 买入冷却 240 分钟（覆盖一个交易日）：同股最近一条买入信号在此时间内，不再出。
- 卖出冷却 5 分钟：上一条卖出信号终结后 5 分钟可以再出，避免止损单过期后一直不再卖。
- 冷却在调用模型之前判断，省掉无效调用。

## 9. 卖出信号与 M08 的分工

M06 每次盘中扫描对每个可卖持仓调用开仓模板的 `ExitPlan`，按优先级：止损 → 突发利空 → 止盈 → 情绪退潮（阶段为 FADE）→ 时间到。只在 `Today` 不为空（盘中）且可卖数量 > 0 时产生。

M08 盯盘按逐笔价格守止损、止盈、移动止盈，是实时兜底。两边都只产生卖出意图，都走 `CheckOrder`。重复由两层挡住：M06 的未结卖出信号去重；M09 同一持仓只允许一张未成交卖单。

持仓对应的模板取该股最近一条 `done` 买入信号的 `strategy`；找不到（手工买入）时只用信号里的止损止盈，不做时间止损。持有天数按交易日历从买入信号的 `trade_date` 算起。

## 10. 候选池与黑名单

| 池 | 存放 |
|----|------|
| 盘前池 | `strategy_candidates`，`pool = pre` |
| 盘中池 | `strategy_candidates`，`pool = intraday`；另有内存里的事件触发集合 |
| 持仓池 | `positions`（只读） |
| 黑名单 | `stock_blacklist`：代码唯一，原因，到期时间可空（空为永久），创建人 |

`strategy_candidates` 以（交易日、模板、代码）唯一。同一天多次扫描只更新分数和阶段，不重复插入。阶段：`ranked`（进前 100）→ `ai_scored` → `selected`。没入选的写 `miss_reason`：`held`、`cooldown`、`not_in_ai_top`、`ai_invalid`、`below_threshold`、`daily_cap`、`price_invalid`、`killswitch`。

## 11. 后验与漏选

`strategy_candidates` 带 `ref_price`、`ret_t1`、`ret_t3`、`ret_t5`：

- 入选的：`ref_price` = 信号入场价。
- 没入选的（漏选）：`ref_price` = 首次进入前 100 时的价格。
- `ret_tN` = 第 N 个交易日收盘价 / `ref_price` − 1，交易日按 `pkg/tradecal`。

每个交易日 15:40 回填一次。M07 自省读这张表，`strategy_feedback` 留给 M07 写归因。

## 12. 事件

| 主题 | 方向 | 载荷 |
|------|------|------|
| `strategy.signal.updated` | 发布，JetStream | 与 M04 设计第 6 节一致的 `{signal_id, book, status, stock_code, stock_name, strategy, signal_type, signal_time, entry_price, reasoning}`。`closed` 时另有 `exit_price`、`pnl_pct`（百分比）、`holding_days`、`closed_at`。每次都带 `from, stop_loss, take_profit, position_pct, final_score, ai_degraded, high_value, exit_kind, valid_until` |
| `market.alert` | 订阅，普通 NATS | 见第 2 节 |
| `sys.killswitch` | 订阅 | `{"active": true, "reason": "..."}`。`active=false` 由客户端人工确认后发出。缺字段按 `true` 处理 |

Kill Switch 生效后停止出买入信号，候选记 `killswitch`；卖出信号照常。启动时从 JetStream 读该主题最后一条消息恢复状态。

信号写库和发事件走 outbox。
