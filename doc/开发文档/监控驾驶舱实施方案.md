硬边界（写进代码时不得放宽）：

- 前端仍是 Vue 3 + Vite + Tauri。禁止 Electron，禁止把监控页做成独立 Web 站点。
- 只读。本页不调用 `placeOrder`、`cancelOrder`、`confirmOrder`、`triggerKillSwitch`、`resetKillSwitch`、`setMode`、`updateParam`、`transitionSignal`、`analyzeBrain`、`runBriefing`、`setSourceEnabled`、`triggerBackfill`、`collectDomain`。急停仍由交易台的 `KillSwitchBar` / `AlertCenter` 负责。

- 依赖零新增。2D canvas 用浏览器原生 API（`CanvasRenderingContext2D` + `ResizeObserver`），不引图形库。从本机打包，不引 CDN，不改 `tauri.conf.json` 的 CSP。
- 岗位固定 7 个：扫描、模型、消息、资金、外围、风控、主管。不做链上巨鲸，不生成第 8 个岗位，不把节点堆到 350。

## 2. 做完是什么样

登录后，顶栏有「监控」按钮，命令面板能搜到「打开监控驾驶舱」。进入 `/monitor` 后：

- 交易台的 dock 卸载，地址停在 `/monitor`，不会被拉回 `/`。
- 顶栏下是 HUD 数字带（阶段与涨跌家数、涨停、信号、漏选、风控、大模型、小模型、当日盈亏），每格可点选对应节点。
- 主体是一张 ComfyUI 式画布：卡片可拖动，空白拖动平移，滚轮缩放，双击或「重置视图」复位。卡片写职责、状态点和主词；连线是端口到端口的两股束线，颜色随域名。无推送时线上只有低亮度流向点，真实推送是亮彗星带标识符。
- 底部是终端带：一行运行状态光点 + 运行日志、任务调度、模型链路、账本四格。
- 点卡片弹出详情窗，列出这次输入输出的子卡片；选中牌与相邻牌保持亮，其余压暗。
- 接口失败或字段为空时，对应卡片是缺口文案，其余卡片继续更新。
- canvas 不可用时，同一页改读 HUD 与终端带，不留黑屏。
- 切回交易台后，dock 布局与离开前一致。
- `npm run test`、`npm run typecheck` 通过。产物里没有 three 块。

## 3. 画面规格

> 2026-10-12 起，本节 3.1 的三维网络与 3.5 的六窗终端带作废，以 `监控驾驶舱呈现方案.md` 第 0.5 节为准。保留的部分：只读边界、缺口语义、涨跌色只上金额、`buildScene` 与 `pushPulse` 纯函数、降级不留黑屏。下文的坐标与尺寸只作历史参考。

根节点 `.nt-monitor` 占满视口，背景 `--nt-bg-0`。上 62% 是画布，下 38% 是终端带。右侧检视栏宽 320px，默认收起，选中节点后展开，画布让出宽度。

### 3.1 上半网络

相机在 `(0, 42, 78)`，看向原点，透视 42°。地面是半径 70 的暗网格，颜色 `--nt-border-2`，不发光。三环在 y = 8 的平面上，单位是 three 世界坐标。

| 环 | 半径 | 节点从哪来 | 上限 |
|----|------|------------|------|
| 外环 `source` | 46 | `listSources()`，空则用 `opsStatus().sources`，再空则用第 5.1 节的 6 个缺口节点 | 12 |
| 中环 `service` | 30 | `opsStatus().services`，空则用第 5.2 节的 9 个缺口节点 | 16 |
| 内环 `post` | 16 | 固定 7 个岗位，顺序见下表，从正前方顺时针 | 7 |
| 中心 `book` | 0 | 一个资金盘面节点 | 1 |

岗位顺序与 id（禁止改名）：

| 顺序 | id | 标题 | 口播里对应的角色 |
|------|----|------|------------------|
| 1 | `post:scan` | 扫描 | 盯市场 |
| 2 | `post:model` | 模型 | 盯交易模型 |
| 3 | `post:news` | 消息 | 新闻和情绪 |
| 4 | `post:capital` | 资金 | 主力、龙虎榜、北向、竞价。没有这些字段就标未调用 |
| 5 | `post:overseas` | 外围 | 板块的 `overseas`。全空则未调用 |
| 6 | `post:risk` | 风控 | 风险敞口。链上巨鲸不在此列 |
| 7 | `post:desk` | 主管 | 只汇总待确认笔数 |

节点外观：球体半径 0.55（岗位 0.7，中心 1.1）。标签用 `CSS2DObject`，文案是标题加一行状态。颜色：

| `NodeStatus` | 颜色 | 含义 |
|--------------|------|------|
| `live` | `--nt-accent` | 有数据且状态为健康 |
| `idle` | `--nt-text-3` | 有返回但既不健康也不失败 |
| `gap` | `--nt-warn` | 没数、过期、或上游没调到 |
| `down` | `--nt-danger` | 明确失败 |
| `attention` | `--nt-accent-2` | 仅 `post:desk` 在待确认笔数 > 0，或 `post:model` 在 `highValue === true` |

静态连线（不动画）按第 5.4 节。粒子只来自 `Pulse`，存活 2400ms，同时最多 24 条，多的丢最旧的。粒子是沿边移动的小球，旁边的 CSS2D 文字是标识符，例如 `trace:abc`、`F:ma20`、`N:123`、`signal:88`。没有脉冲时网络是静止的。

中心节点文案三行：`权益 {amount}`、`当日 {signed pnl}`、`现金 {amount}`。盈亏用 `.up` / `.down`。`killActive` 为真时中心改用 `--nt-danger`，文案追加急停原因。本页不弹第二套急停锁，交易台的 `AlertCenter` 仍在全局（若该组件挂在工作台内，监控页要在自己的壳里挂同一个 `AlertCenter`，避免急停被卸掉）。

### 3.2 下半六窗

HTML 浮层，背景 `--nt-bg-1`，1px `--nt-border-1`。允许在 `.nt-monitor` 内使用 `backdrop-filter: blur(8px)`。交易台面板继续禁止玻璃。六窗从左到右：

| 窗 id | 标题 | 内容 | 空态文案 |
|--------|------|------|----------|
| `term:positions` | 持仓 | `account.positions`：代码、数量、成本、现价 | `持仓接口无返回` 或 `当前账本没有持仓`（后者仅当接口成功且数组为空） |
| `term:sectors` | 板块 | `listSectors(8)` 的名称和 `avgPct`，涨跌用 `.up` / `.down` | `板块接口无返回` |
| `term:radar` | 四维 | 当前焦点信号的技术 / 消息 / 资金 / 外围。没有焦点时用最新一条信号 | `没有信号，四维未形成` |
| `term:heat` | 涨停 | `listLimits('UP')` 前 8 条：代码、连板、状态 | `涨停接口无返回` |
| `term:equity` | 权益 | 三个数字：权益、现金、当日盈亏。有回测曲线时在数字下画折线，标题写「回测曲线，不是模拟盘权益」 | 三个数字各自缺失写 `—` 且旁注缺口；无曲线写 `没有权益序列` |
| `term:risk` | 风控 | 模式、急停、当日买单数、熔断 | `风控状态无返回` |

新闻带在六窗之下，高 36px，横向滚动最近 12 条。来源优先级：焦点股票的 `timeline(symbol).items`，没有焦点则用晨报 `briefing.items`，再没有则用 `hotWords()`。每条显示时间、来源或类型、标题或热词、关联代码。全部为空时整条写 `晨报未生成，且没有焦点股票的情报`。禁止写「今日没有消息」。

情报服务没有全市场列表接口（`intel.proto` 只有 `GetItem`、`Timeline`、`HotWords`）。第一版不新增 `List`。

### 3.3 交互

- 点击节点：相机在 600ms 内看向该节点，检视栏打开。栏内分段：状态与缺口原因、输入标识符、输出标识符、最近 8 条经过该节点的脉冲。
- 点击新闻：若带代码，把该代码设为焦点，高亮 `post:news` 与名称匹配的信号节点（信号节点不常驻，只在检视栏列出）。
- 点击主管节点上的「回到交易台确认」：`router.push({ path: '/panel/trade' })`。
- `Esc`：先关检视栏；栏已关则 `router.push('/')`。
- 顶栏左侧「交易台」按钮：`router.push('/')`。
- `document.hidden` 或组件卸载：取消动画帧、`renderer.dispose()`、退订 WebSocket。再次可见时重新开始。
- `renderer.getContext()` 失败或 `webglcontextlost`：卸下画布，显示第 3.4 节平面清单。

### 3.4 平面清单

无 WebGL 时仍渲染同一份 `SceneGraph`：三列（数据源、服务、岗位）加六窗和新闻带。这是降级，不是第二套设计。数据函数不分支。

### 3.5 性能

- `pixelRatio = Math.min(window.devicePixelRatio, 1.5)`。
- 节点总数不超过 80。超出截断并在检视栏写「已截断」。
- 轮询 10 秒一次 REST。WebSocket 事件 300ms 合并进场景，避免每帧 `buildScene`。
- 不创建离屏 Worker，不读全量 K 线，不把新闻正文放进粒子。

## 4. 场景模型

新建 `web/src/monitor/types.ts`，内容如下。实施时原样使用这些名字，测试和组件都从这里导入。

```ts
export type Ring = 'source' | 'service' | 'post' | 'book'

export type NodeStatus = 'live' | 'idle' | 'gap' | 'down' | 'attention'

export interface Identifier {
  /** F 因子 / N 情报 / trace 链路 / symbol 代码 / signal 信号 / rule 风控号 / source 数据源 */
  kind: 'F' | 'N' | 'trace' | 'symbol' | 'signal' | 'rule' | 'source'
  value: string
}

export interface SceneNode {
  id: string
  ring: Ring
  title: string
  status: NodeStatus
  /** 给人读的一行。gap/down 时必须是原因，不能是空串 */
  detail: string
  inputs: Identifier[]
  outputs: Identifier[]
}

export interface SceneEdge {
  id: string
  from: string
  to: string
}

export interface Pulse {
  id: string
  from: string
  to: string
  identifier: Identifier
  at: number
}

export interface NewsRow {
  id: string
  title: string
  source: string
  time: string
  symbol: string
}

export interface TerminalModel {
  id: 'term:positions' | 'term:sectors' | 'term:radar' | 'term:heat' | 'term:equity' | 'term:risk'
```


### 4.1 `buildScene` 规则

状态归一：

- 对应块 `null` 或 `ok === false`：相关节点 `gap`，`detail` 用第 5 节的固定原因。
- `status` 字符串（忽略大小写）属于 `ok|up|running|healthy|ready`：`live`。
- 属于 `down|error|unavailable|failed|closed`：`down`，`detail` 用上游 `detail`，空则写 `状态为 {原文字}`。
- 其他非空字符串：`idle`。
- `stale === true`：岗位改为 `gap`，`detail` 写 `数据已过期，截至 {asOf或generatedAt}`。

标识符抽取：

- `evidence` 里以 `F:` 开头的字符串 → `{ kind: 'F', value: 去掉前缀 }`。
- 以 `N:` 开头 → `kind: 'N'`。
- 信号 `id` → `{ kind: 'signal', value: id }`。
- 代码 → `{ kind: 'symbol', value }`。
- 风控命中：在 `evidence` 或 `dims` 的键里匹配 `/^R\d{2}$/` → `{ kind: 'rule', value }`。没有匹配则风控输出标识符为空，岗位仍可根据 `risk.ok` 为 `live`，`detail` 写模式和熔断，不编造规则号。
- 扫描输出：`phase` 非空时 `{ kind: 'source', value: phase }` 不合适。扫描输出用 `{ kind: 'symbol', value }` 只放涨停代码（最多 8 个）。情绪阶段写进 `detail`，不进标识符。

待确认笔数：`signals.items` 里 `status` 为 `approved` 或 `risk_checking` 的条数。大于 0 时 `post:desk` 为 `attention`，输出一条 `{ kind: 'signal', value: String(count) }`，`detail` 写 `待确认 {count} 笔`。

降级：信号 `degraded === true` 时，模型节点 `detail` 前缀 `规则分`。分数仍然展示，不改写成模型分。

焦点：`input.focusSymbol` 非空时，`post:news` 的输入追加该代码的 timeline id（`kind: 'N'`，最多 8 个）。雷达窗读取 `signals.items` 中该代码的第一条；没有则雷达 `empty` 为 `没有 {code} 的信号，四维未形成`。

截断：数据源超过 12、服务超过 16 时按原顺序保留前面的，`truncated = true`。

边：只连接两侧 id 都存在的对。id 不存在的边丢弃。

`equityCurve.points` 不产生节点。只有长度 ≥ 2 且至少两个 `equity` 非空时，权益窗 `caption` 为 `回测曲线，不是模拟盘权益`，`rows` 仍是账户三个数字。曲线点由视图从 `input` 读，不塞进 `rows`。

## 5. 数据从哪来

采集放在 `web/src/monitor/load-input.ts`，只调用下列现有函数。任一调用失败：该块 `ok: false`，其它块照填。用现有 `quiet()`（`web/src/utils/async`）吞掉异常。

| 块 | 调用 | 失败时的 detail |
|----|------|-----------------|
| account | `useAccountStore().refresh()` 后读 store。账本沿用 store 里的 `book`，默认 `SIM` | `账户接口无返回` |
