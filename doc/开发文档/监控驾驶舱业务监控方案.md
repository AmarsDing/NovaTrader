## 0. 2026-10-14 已确认的深化方向

保留原三段纤维画布、时段HUD和终端带。节点查看概况/输入/输出/质量/记录/配置，连线查看真实通道数据与计量依据；按信号/订单/trace追踪实际处理；在同页编辑配置、预览影响、保存版本并核验服务应用。历史查看与实时上下文分开。具体合同和验收见[监控与盯盘业务深化方案](监控与盯盘业务深化方案.md)§3、§7–9。

配置能力是监视功能的明确写入例外，范围从原数据源/模型/四维按阶段深化至策略、风控限额与自动计划政策；配置不等于交易授权，交易写操作继续在盯盘工作台。

## 1. 我坐在这块屏幕前，要能立刻回答的十个问题

监控页不是数据展板，是一台问答机。所有版面决定都从这十个问题倒推。

| # | 问题 | 层次 | 现在能答吗 | 靠什么答 |
|---|------|------|-----------|---------|
| Q1 | 今天能不能做？ | 市场 | 半答 | 情绪阶段有了，但缺炸板率趋势、连板梯队成功率、昨日涨停今日溢价——超短线判断「赚钱效应」的三个核心量 |
| Q2 | 现在几点，我该盯哪一块？ | 市场 | **不能** | 没有时段带。竞价 5 分钟决定一天，页面却和下午 2 点长一样 |
| Q3 | 系统活着吗，数据新鲜吗？ | 链路 | 半答 | 有状态点和「未返回」文案，但没有健康总分，没有「距今 N 秒」角标，静默断流看不出来 |
| Q4 | AI 现在给出什么了？ | 决策 | 能 | 待确认笔数 + 分数 |
| Q5 | 它为什么这么判？ | 决策 | 半答 | 有 `F:`/`N:` 证据条数，没有推理正文摘录（后端有 `llm_call_log`，桌面没有只读口） |
| Q6 | 它漏了什么？ | 决策 | 半答 | 有漏选条数和原因，但没有漏斗各层的过滤原因分布——只知道漏了多少，不知道漏在哪一层 |
| Q7 | 我的钱现在怎么样？ | 资金 | 半答 | 有盈亏和持仓，缺日内回撤、距止损/止盈的剩余空间、当日已实现与浮动的拆分 |
| Q8 | 风控在拦什么，额度还剩多少？ | 资金 | 半答 | 有「守着/急停」和命中规则号，缺限额使用仪表（今日买入 n/N、单票仓位 x/X） |
| Q9 | 模型跑得动吗，会不会让信号迟到？ | 链路 | 半答 | 有调用数和 P95，缺 GPU 利用率、显存、队列深度、tokens/s——本地推理的延迟根源在这四项 |
| Q10 | 它昨天的判断准不准？ | 决策 | **不能** | 没有评分与实际收益的相关性、没有分维贡献归因。这一问是学习闭环的入口，缺了它系统永远在自说自话 |

**结论**：Q2、Q10 完全缺失，Q1、Q3、Q5、Q6、Q7、Q8、Q9 都只答了一半。下面的方案按这个缺口排优先级，不按视觉酷炫程度排。

## 2. 要看什么：业务数据清单

每个域列出字段、来源、刷新频率、缺失时的写法。**「缺失写法」是纪律，不是建议**：没有的数写缺口，不写 0，不写破折号，不编曲线。

## 3. 怎么呈现：视觉编码原则

**数据性质决定视觉通道，不是反过来。** 这一条是本方案所有具体设计的依据。

| 数据性质 | 视觉通道 | 例子 | 禁止 |
|---------|---------|------|------|
| 存量（余额、仓位、只数） | 等宽大数字 + 水平条 | 权益 1,284,902 | 不用饼图 |
| 流量（每秒条数、调用速率） | **线宽 + 流向点速度** | 数据源→扫描的束线粗细 | 不用数字堆在边上 |
| 比率（胜率、炸板率、转化率） | 环形表 / 百分比条 | 准入 12/20 日 | 不用面积图 |
| 状态（活/闲/缺/断） | 光点颜色（青/暗/橙/红） | 服务健康 | **不用涨跌红绿** |
| 时间（新鲜度、时段） | 角标「距今 Ns」+ 进度带 | 行情 tick 3s 前 | 不写「正常」二字 |
| 分布（延迟、评分） | 迷你直方图（8 桶，24px 高） | P95 分布 | 不用箱线图 |
| 序列（权益、涨停家数） | sparkline（30 点，14px 高） | 日内回撤 | 不铺满整屏 |
| 事件（信号、成交、告警） | 脉冲彗星 + 事件流行 | `600519 88分 待确认` | **不给无事件的装饰动画** |
| 因果（证据、漏选原因） | 缩进列表 + 漏斗侧漏支线 | 「量价不足 4634」 | 不写成一段话 |
| 金额与涨跌幅 | 红涨绿跌（`--nt-up`/`--nt-down`） | +18,204.10 | **只此一处用红绿** |

### 3.1 四级信息层级

| 级 | 距离 | 时长 | 承载 | 字号 |
|----|------|------|------|------|
| L1 一眼 | 3m | <1s | 健康总分色、盈亏大数字、急停红环、时段带位置 | 26–32px |
| L2 三秒 | 1m | 3s | HUD 十格、画布卡片主词、漏斗光带宽度 | 15–20px |
| L3 细读 | 0.5m | 10s | 卡片副行、终端带四格、事件流 | 11–13px |
| L4 钻取 | 0.3m | 1min+ | 详情弹窗字段表、证据列表、推理摘录 | 12–14px |

**纪律**：L1 只允许五个对象发光（健康分、盈亏、急停、高分信号脉冲、待确认>0 的信号牌）。其余一切在 L1 距离必须是安静的。

### 3.2 视觉规格（具体到数值）

| 元素 | 规格 |
|------|------|
| 画布底 | `--nt-bg-0`；点阵 44px，`--nt-text-3` alpha 0.05，半径 1.2px |
| 列标签 | mono 11px，`--nt-text-3`，字距 0.14em，下方 0.5px 发丝线 |
| 卡片底 | `--nt-bg-1` alpha 0.92（常态）/ 0.98（选中） |
| 卡片边 | 1px `--nt-border-1`；悬停/高亮 1.5px 域名色 alpha 0.85；选中 1.8px `--nt-accent` |
| 标题带 | 高 20px，域名色 alpha 0.16，下缘 0.5px 分隔；状态点 r=3 在 x+10；标题 sans 600 11px；职责 mono 9px `--nt-text-3` 右对齐 |
| 主词 | mono 700 20px（焦点牌：账户/升格信号）；mono 600 15px（常规）；`--nt-text-1`，缺口时 `--nt-text-2` |
| 副行 | sans 9.5px `--nt-text-3`，单行截断 |
| **迷你活动条**（新增） | 卡片底缘 2px，60 格（每格 1 秒）；有活动的格 `--nt-accent` alpha 0.55，静默格 alpha 0.06 |
| **sparkline**（新增，仅 HUD 与账户牌） | 30 点，高 14px，线宽 1px 域名色 alpha 0.6，末点 r=1.6 实心 |
| 端口 | r=3 圆；入口 `--nt-text-3`，出口域名色 |
| 束线常态 | 双股错开，域名色 alpha 0.20 / 0.07，宽 1.3 / 0.9 |
| **束线流量映射**（新增） | 宽度 = `0.8 + min(2.4, log10(每分钟条数+1) * 0.9)` px；无流量数据时固定 1.3px，**不猜** |
| 束线活跃（选中相邻） | alpha 0.34，宽 +0.4px |
| 环境流向点 | r=1.7 alpha 0.5；周期由速率映射 1200–8000ms，**断流时停住并转 `--nt-warn` alpha 0.35** |
| 普通脉冲 | r=3 alpha 0.95 + 尾迹 2 格 alpha 0.5/0.25 + mono 9px 标签 |
| **高分信号脉冲**（≥85） | r=4.5，`shadowBlur 8` `--nt-accent`，标签加粗，尾迹 3 格 |
| **急停态** | 风控→账户的边 `--nt-danger` alpha 0.6 宽 2.4；账户牌外圈 1.5px 红环，呼吸 1.2s（`sin` 缓动，alpha 0.35↔0.75） |
| 漏斗光带 | 宽从 96px 逐级收窄到 12px；青色渐变 alpha 0.18→0.30；侧漏支线 `--nt-warn` alpha 0.25，虚线 `[3,3]` |
| 详情弹窗 | `--nt-bg-1`，边 `--nt-border-2`，圆角 `--nt-radius-l`，`backdrop-filter: blur(8px)` 只在遮罩层 |
| 数字变化闪 | 值变化时卡片边框 300ms 内 alpha 0.4→0（`--nt-accent`），不放大、不跳动 |

### 3.3 不要做的（反模式清单）

- **不要 3D**。透视会把中文压成一条，2026-10-10 已经踩过（见呈现方案 §0）。three 已卸载，不回头。
- **不要全屏粒子**。粒子只表示真实流动，一颗粒子 = 一个事件。
- **不要用装饰动效冒充数据**。固定周期的环境流向点已经是对这条纪律的最大让步，它的亮度必须低到「余光看不见、正视能看见」。
- **不要把画布做成唯一入口**。canvas 里的字对屏幕阅读器不可见，键盘也走不到。必须保留一份等价的 DOM 清单（详见 §9 可访问性）。
- **不要超过 ~40 张卡片**。ComfyUI 的可拖拽在 40 张以内是工具，超过就是找东西的游戏。数据质量源、后环服务暗点继续不上台。
- **不要在卡片上写整句话**。牌面只写主词 + 一行副词，句子放点开后的 L4。
- **不要用红色表示「重要」**。红色在这套系统里只有两个含义：跌（金额）和断（服务/急停）。

### 4.3 时段带：一天里页面该长什么样

- **活动条**是「静默失败」的解药：盘中某张牌连续 60 格全暗，即使状态点还是绿的，也应该被看见。连续 5 分钟无活动 → 状态点转 `--nt-accent-2`（attention），副行写「5 分钟没有动静」。
- **新鲜度角标**是「陈旧数据」的解药：所有来自接口的数字都带「距今 Ns/Nm」，超阈值变橙。这条纪律现在只写在文档里（缺失写缺口），没有可视化，等于没有。

#### 4.4.2 漏斗光带（Q6 的答案）

在「02 研判」与「03 裁决」之间横贯一条逐渐收窄的光带，替代现在扫描→四维→综合→信号的四段等宽束线：

```
        ┌────────────────────── 5,120 全市场 ──────────────────────┐
        └─────────────┬────────────────────────────────┬───────────┘
                      │                        ┄┄┄┄┄┄┄ 4,634 量价不足
               ┌──────┴───── 486 初筛 ─────┐
               └──────┬─────────────┬──────┘
                      │      ┄┄┄┄┄┄┄ 389 分数不足
                ┌─────┴─── 97 AI≥70 ───┐
                └─────┬─────────┬──────┘
                      │   ┄┄┄┄┄┄ 74 规则拦截
                  ┌───┴── 23 风控通过 ──┐
                  └───┬────────┬────────┘
                      │  ┄┄┄┄┄┄ 15 额度不足
                   ┌──┴── 8 已下单 ──┐
                   └──┬───────┬──────┘
                      │ ┄┄┄┄┄┄ 5 未成交
                    3 成交
```

- 主干宽度按 `sqrt(数量)` 映射到 96→12px，**用 sqrt 不用线性**，否则第一层会把后面五层压成一根线。
- 每段交界处标数字 + 转化率（`486 / 9.5%`），mono 10px。
- 侧漏支线是 `--nt-warn` 虚线，末端汇入「漏选」牌，标该层过滤原因的最大项。**漏选不再是一个孤立的数字牌，而是从主干上看得见的分流。**
- 某层数据缺失时，该段光带断成 `--nt-text-3` alpha 0.15 的虚线并标「未返回」，**不用 0 填充也不跳过这一层**——跳过会让人以为漏斗只有四层。

#### 4.4.3 边的语义升级

| 边 | 现在 | 升级后 |
|----|------|-------|
| 数据源 → 扫描/四维 | 固定宽度双股 | 宽度 = 每分钟条数对数映射；流向点速度 = 速率；断流时停住转橙 |
| 模型 → 负责的维度 | 竖向贝塞尔 | 保留；模型熔断时该边转 `--nt-danger` alpha 0.4 并停止流向点 |
| 扫描 → 四维 → 综合 → 信号 | 四段束线 | **被漏斗光带取代**（主干），束线只在光带缺失时兜底 |
| 信号 → 风控 → 账户 | 双股 | 保留；急停时转红加粗 + 账户牌呼吸环 |
| 服务 → 岗位 | 不画 | 继续不画（服务在底部光点行，不占画布） |

## 6. 无人值守的三道保险

7×24 无人值守真正的敌人不是崩溃，是**静默失败**：某个源断了，系统照跑，输出垃圾信号，人在睡觉。三道保险按发现速度排序：

### 6.1 第一道：静默检测（比 down 更早）

| 对象 | 盘中阈值 | 盘后阈值 | 触发后 |
|------|---------|---------|-------|
| 行情源 | 30s 无新 tick | 不检测 | 状态点转 attention，副行「30 秒没有新数据」 |
| 扫描 | 5min 无活动 | 30min | 同上 |
| 模型 | 10min 无调用（有待确认信号时） | 不检测 | 同上 + 事件流一条 `模型 静默` |
| 交易通道 | 有委托写出后 60s 无消费 | 不检测 | **升告警**（AlertCenter） |
| WS 连接 | 断开 | 断开 | 顶栏「不是实时」+ 事件流一条 |

实现：活动条的 60 格数据本来就在前端，加一个「连续暗格数」判断即可，不需要后端。

### 6.2 第二道：陈旧角标（防止拿旧数据当新的）

每个来自接口的数字，右上角 mono 9px 标「距今 Ns / Nm / Nh」。阈值：

| 数据类型 | 正常 | 变橙 | 变红 |
|---------|------|------|------|
| 盘中行情 | <10s | 10–60s | >60s |
| 情绪/涨停 | <60s | 1–5min | >5min |
| 账户 | <30s | 30s–3min | >3min |
| 模型统计 | <60s | 1–10min | >10min |
| 外围 | <2h | 2–12h | >12h |
| 盘后数据 | 当日 | 前一交易日 | 更早 |

非交易日全部按盘后阈值，否则整个页面会在周末全变红——那等于没有告警。

### 6.3 第三道：健康总分 + 告警联动

顶栏健康总分（§4.2）低于 70 时：
1. 分数转 `--nt-warn`；低于 50 转 `--nt-danger` 并发光。
2. 事件流插入一条 `告警 健康 62：数据新鲜度 -16，模型 P95 -6`（**必须写扣分项，不写「系统异常」**）。
3. 低于 50 且实盘模式 → 触发 `AlertCenter`（走现有告警通道，本页不新做推送）。

## 10. 守住的边界（不因本方案放宽）

- **只读**。不调用 `placeOrder`、`cancelOrder`、`confirmOrder`、`triggerKillSwitch`、`resetKillSwitch`、`setMode`、`updateParam`、`transitionSignal`、`analyzeBrain`、`runBriefing`、`setSourceEnabled`、`triggerBackfill`、`collectDomain`。唯一的写操作是详情窗里已有的配置项表单（`saveConfigValues`）。
- **大模型只出分和理由**。信号牌上的「回到交易台确认」只做路由跳转，本页没有确认按钮。
- **价格和仓位由规则计算**。详情窗展示计算依据，不提供调整入口。
- **红涨绿跌只用于金额和涨跌幅**（`utils/format.pnlClass`）。服务健康用青/暗/橙/红；同比箭头用 `--nt-text-3`。
- **发光预算**：L1 只允许五个对象发光——健康总分 <50、当日盈亏、急停态、≥85 分信号脉冲、待确认 >0 的信号牌。其余一律不发光。
- **玻璃拟态**只在详情弹窗遮罩与 `AlertCenter`。
- **缺失写缺口**，标明缺的是哪个接口。禁止 0、破折号、随机数、假设收益。
- **不注册进 `panel-registry.ts`**，不当第 22 个 dock 面板。`MonitorView` 自己挂 `AlertCenter`。
- **不做第二块屏**。popout 需要改 capability，本轮不动（`trade/settings/ops` 仍禁弹）。
- **不引新依赖**。画布用浏览器原生 2D API；three 已卸载，不回头。
- 模拟盘连续满 20 个交易日并通过准入后才允许半自动实盘——准入进度条只是展示，**本页不提供任何绕过入口**。
