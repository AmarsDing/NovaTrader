## 1. 一页结论

**系统骨架已经完成，但还没有「活」起来。**

- 13 个模块（M00–M12）代码完成度普遍在 70%–90%，架构、表结构、接口、桌面驾驶舱全部到位；21 个前端面板全部接真实 API/WS，无 mock。
- 但整条赚钱链路（数据 → 模型 → 信号 → 模拟盘 → 实盘）有**四个断点**，全部由外部环境阻塞，不在代码里：
  1. **数据没进库**：通达信 `vipdoc` 待盘后下载、Tushare 令牌未配、新闻源未通。
  2. **模型没接通**：DGX vLLM 地址未确认，四维研判、晨报、情报重评、知识库嵌入全部停在规则降级档。
  3. **20 日模拟验收未开始**：准入之前界面必须继续拒绝实盘。
  4. **实盘链路只有 43 行代码**：`broker-gw` 进程不存在，`pkg/brokerif/emfile` 只会写 order.csv/.fin，没有读终端输出、没有对账、没有 UNKNOWN 处理。
- 工程健康度实测：`app/admin` vet+test 过、web typecheck + 67 个 vitest 全过；但整仓库 `go build ./...` 仍被 `api/admin/v1` 模板残留 proto 卡死，且当前有大量未提交改动（含 demo 服务删除）。
- 监控驾驶舱已有一份同日提案（`监控驾驶舱业务监控方案.md`，S1–S7），方向正确，建议确认其 §11 七条冲突点后实施。
- GitHub 开源调研（见第 4 节）给出的最大启示：**专业感来自「信息层级 × 数据新鲜度 × 决策可追溯」，不来自 3D 和粒子**——这与项目既有视觉纪律一致，可作为监控升级和决策台深化的外部佐证。

**下一步的优先级不是加功能，是按 P1→P2→P3→P9→P10→P11 把断点逐一接上，同时用 S1–S7 和开源借鉴把「盯盘体验」做到专业级。**

## 3. 需求深度调研：作为唯一用户，我还需要什么

> 视角：这套系统的唯一操作员，7×24 无人值守，盘中只有几秒钟余光，盘后有一段复盘时间。
> 已有文档（个人全览、优化实施、监控业务方案的 Q1–Q10）已覆盖大部分，本节做整合与补全，按「一天的时间轴」重排，更贴近真实使用。

### 3.1 一天的时间轴需求

| 时段 | 我要回答的问题 | 现状 | 差距 |
|------|---------------|------|------|
| 08:30 盘前 | 外围怎么样？晨报说了什么？数据链路齐不齐？昨日复盘结论？ | 晨报有（模型降级中）；外围映射缺黄金/半导体/航空；复盘无 | 缺昨日复盘视图（漏选的票今天涨停了几只）、外围映射 |
| 09:15–09:25 竞价 | 竞价异动是谁？今天赚钱效应如何？ | **完全没有竞价视图** | 需 market 补竞价只读口（P1 接口）；监控方案已列为 S1 时段带 |
| 09:30–11:30 上午 | 今天能不能做？做什么？为什么没选上？链路哪条是空的？ | 决策台骨架已有（阶段A），票形（P3）未做 | P3：待执行/已执行/漏选三列 + 投票/异议/风控夹紧的票详情 |
| 13:00–14:30 下午 | 持仓距止损还有多远？有没有该卖没卖的？ | 盯盘卖单后端已有（risk.exit）；前端无「距止损 x%」列 | 持仓行加距止损/止盈剩余空间（纯前端可算） |
| 14:30–15:00 尾盘 | 该不该平仓？明天怎么办？ | 14:50 后不出买点已在规则；尾盘焦点切换无 | 监控 S1 时段带尾盘模式 |
| 15:00 盘后 | 今天做得对不对？评分和收益相关吗？漏选的票涨了吗？ | 后验 T+1/3/5 有；**评分-收益相关性、分维归因、漏选复盘均无** | P1 接口：`strategy/performance`、`strategy/score-vs-pnl` |
| 任意时刻 | 系统还活着吗？数据新鲜吗？会不会静默断流？ | 状态点有；无健康总分、无「距今 Ns」、无静默检测 | 监控 S2/S1：活动条、陈旧角标、健康总分 |
| 实盘前 | 凭什么相信它能下单？ | 20 日准入口径已有，会话账未建 | P9 可重放会话账 + 准入页逐项记录 |
| 实盘后 | 文件单写出去没有？终端消费没有？ | 无 | broker-gw 只读口 + 实盘模式下缺失升告警 |

### 3.2 需求分层清单

**A. 闭环必需（没有它们系统就是演示品）**

1. 数据进库（P1）：vipdoc 盘后下载、Tushare、新闻源、全量 stock_basic。
2. 模型接通（P2）：vLLM 地址、四维不再长期降级、情报重评、嵌入服务。
3. 决策可读（P3）：一张票顺着读完——身份/时机/价格/投票/异议/风控/账本。
4. 批准页（P4）：确认前账本不变，三句话写清这次做什么。
5. 会话账（P9）：可重放、对不上就停买、漏日不跳、20 日准入读这本账。
6. 真实回测（P7 + M01 数据）：至少一次长区间真实行情回测，成绩条六格 + 相对沪深300。
7. 实盘文件单（P11）：broker-gw 读终端输出、对账、UNKNOWN 不重发、人工确认才写。

**B. 体验增强（专业盯盘感）**

8. 监控 S1–S7：时段带、健康总分、活动条/新鲜度角标、漏斗光带、事件流 TAPE、详情窗深化、流量束线。
9. 决策台深化：P5 岗位值班表（七行）、P6 焦点股资金/席位/竞价。
10. 盘后复盘：评分-收益散点、分维归因、漏选复盘（只陈述事实，不算「本该赚多少」）。
11. 令牌合计只读口：`GET /v1/brain/usage`（监控方案已列，唯一明确的读口缺口）。
12. 行情页实时化：MarketView 订阅 market WS；盘口组件接入五档数据（若通达信源能提供）。

**C. 前瞻探索（不挡主线）**

13. 监控第二块独立屏（popout 能力扩展，trade/settings/ops 仍禁弹）。
14. 键盘/可访问性：画布等价 DOM 清单（监控方案 §9 已要求）。
15. 声音分级：AlertCenter 已有警笛；可探索「高分信号到达」的轻提示音（发光预算同级的听觉预算）。
16. 布局预设的场景化：竞价布局 / 盘中布局 / 盘后复盘布局随时段自动切换（监控方案 §4.3 的桌面版）。

### 3.3 明确不需要的（克制清单）

- 更多策略模板（P10 之前不加第三个）、全市场荐股、自然语言生成可执行策略。
- 3D 行情、全屏粒子、链上巨鲸、多空杠杆、交易所直连。
- 模型自动改参数、自动换模板（人批准是底线）。

## 4. GitHub 开源调研：科幻且专业的盯盘/交易界面

> 调研于 2026-10-12，覆盖 24 个代表性项目（GitHub API 实时星数）。先看结论：**本项目的技术选型（Vue3 + dockview + Tauri + lightweight-charts + ECharts + PostgreSQL）与开源世界的最佳实践高度重合，大部分交互范式已经落地；真正值得新增的是「高密度表格的刷新手法、回测 tearsheet 的指标图、K 线上的交易标注、研判报告可回放」四块。**

| QuantConnect/Lean、plotly/dash、awesome-quant | ~22k/~24k/~30k | 成熟引擎与索引 | 背景参考 |

### 4.2 已经被本项目吸收的（不必再立项）

dockview 布局 + popout（P3/P5）、Ctrl+K 命令面板（P5）、lightweight-charts 主图、ECharts 按需、红涨绿跌与发光预算、Kill Switch 常驻条 + 单键热键 + CONFIRM 复位、AlertCenter 全屏告警 + 声音、ai-hedge-fund 的会话报告/批准页/直播板/账本形状（P3–P9）、TradingAgents 的四维并行 + 一轮异议、freqtrade 的确认后下单/查单不重发/一根 K 线只取一次、模拟在实盘之前（20 日准入）。

### 4.3 新增值得借鉴的 8 点（按优先级）

1. **高密度表格「单元格闪烁」而非整表刷新**（ag-grid）。持仓、委托、涨停梯队、事件流 TAPE 的行级增量更新；先用手写 diff + CSS 过渡实现同效果，体积或交互不够时再评估引入 ag-grid。
2. **流式 pivot 自定义报表**（perspective，可选增强）。资金/板块/因子让用户自拖拽行列、实时 tick；其虚拟服务器可零 ETL 直查 PostgreSQL，与本项目 PG 栈契合。**S 期之后再评估，不进主线。**
3. **回测 tearsheet 指标图**（quantstats）。在 M07 报告与回测页（P7 成绩条）上补：回撤期间图（水下曲线）、月度收益热力图、rolling Sharpe、收益分布直方图；Monte Carlo 准入已有计算，补展示。
4. **买卖点与三价标注在 K 线上**（freqtrade `plot-dataframe`、jesse）。把信号箭头、入场/止损/止盈水平线、成交标记做成 lightweight-charts primitives；NtKline 已有 markers 基础，补三价线与信号联动（点信号票 → 行情页画出该票三价）。
5. **研判报告可回放**（TradingAgents 单页 HTML + 冻结当次设置）。每笔信号生成一份只读「研判报告」：四维分数、证据编号与原文、模型名/耗时/提示词版本、当时参数快照；决策台票详情与监控「推理摘录」共用这一个读口（后端 `llm_call_log` + `agent_decisions`）。
6. **AI 岗位卡片 + 决策链逐层展开**（TradingAgents 团队视图）。P5 值班表的呈现手法：七岗位各一卡，点开看输入证据 → 中间结论 → 最终评分；异议只一轮，明写「谁反对」。
7. **HUD 动效语言的克制采样**（edex-ui/arwes，只取灵感）。数字变化 300ms 边闪（监控方案 §3.2 已列）、事件行入场淡出、时段切换渐变；**扫描线、打字机、常驻呼吸全部禁用**，发光预算不变。
8. **审批是执行前的一等公民**（ai-hedge-fund 执行前批准页）。外部范式佐证 P4 设计：批准页不是弹窗确认，是「将要执行的决策」的完整展示（形成日/执行日/三价/股数/将提交风控的仓位）。

### 4.4 调研的两个提醒

- **edex-ui / arwes 均已停维护**：只作视觉灵感，禁止作为运行时依赖引入。

## 5. 总体方案

### 5.0 路线原则

1. **先喂饱，再美化。** 数据（P1）和模型（P2）不接通，任何界面升级都是给空壳化妆。
2. **决策闭环优先于监控酷炫。** P3/P4/P9 决定系统「能不能用」，S1–S7 决定「好不好盯」。两条线可并行，但人力冲突时闭环优先。
3. **20 日准入是不可跳过的闸门。** 在此之前所有实盘代码可以写、可以测，界面入口保持拒绝。
4. **克制清单（§3.3）与视觉纪律（红涨绿跌、发光预算、玻璃三处）不因任何开源借鉴而放宽。**

### 5.1 阶段路线（与 P0–P11 对齐 + 开源借鉴落点）

| 阶段 | 内容 | 依赖 | 对应既有方案 | 开源借鉴落点（见 §4） |
|------|------|------|-------------|---------------------|

| **B. 接通模型** | vLLM 地址、四维去降级、情报重评、嵌入服务 | DGX | P2 | — |
| **C. 决策闭环** | P3 票能顺着读完 → P4 批准页 → P5 值班表 → P6 焦点展开 → P7 回测成绩条 | A/B 可并行界面 | P3–P7 | ai-hedge-fund 会话报告/批准页/直播板（已立项）；§4.3 借鉴点 3/4/5/6/8 |

### 5.2 监控升级与开源借鉴的结合（D 阶段细化）

按监控业务监控方案 S1–S7 执行，开源借鉴只改「呈现手法」，不改数据口径：

| S 期 | 方案内容 | 开源对应手法 |
|------|---------|-------------|
| S1 | 时段带 + 健康总分 + HUD 十格 sparkline | finviz 式密度与一屏全览；借鉴点 7（HUD 动效克制采样） |
| S2 | 活动条 + 新鲜度角标 + 静默检测 | 交易所 time&sales 的「最后一笔距今」习惯 |
| S3 | 漏斗光带 + 各层过滤原因分布 | 漏斗可视化的标准做法（NtFunnel 已有，升级为光带） |
| S4 | 事件流 TAPE | 交易所逐笔成交带 / freqtrade 的运行日志流；借鉴点 1（行级增量 + 闪烁，不整表刷新） |
| S5 | 详情窗六张全字段 | ai-hedge-fund 会话报告的「点开才给正文」；借鉴点 5/6（研判报告、岗位卡片共用读口） |
| S6 | 流量束线 + 高分信号脉冲 + 急停呼吸环 | MarketSphere「粒子只表示真实流动」 |
| S7 | P1 只读接口逐个补 | —（纯后端） |

C 阶段同步吸收两条开源手法：**借鉴点 4**（信号票点开行情页时画出入场/止损/止盈三价线与买卖点标记，NtKline primitives）与**借鉴点 3**（回测页成绩条之外补回撤水下曲线、月度收益热力图、rolling Sharpe——quantstats tearsheet 的图形口径，数字仍来自 M07 引擎，前端不重算）。**借鉴点 2**（perspective 流式 pivot）不进主线，S 期之后再评估。

### 5.3 实盘文件单（F 阶段）任务分解

broker-gw 当前不存在，需要从零建（Windows Python 边车，与 pyworker 同机）：

1. **写出侧**（已有雏形）：trade 服务经 `pkg/brokerif/emfile` 写 order.csv + .fin；把「人工确认后才写」的门卫接到 P4 批准页。
2. **读取侧**（新建）：轮询终端输出目录，解析成交/撤单回报，映射回 `trade_order` 状态机；确定性单号（sid）贯穿。
3. **对账**：position.csv 今仓/可卖 vs 本地账本；不一致停止新开仓 + 通知；UNKNOWN 只通过对账查 sid，绝不重发。
4. **探针**：broker-gw 健康 + 文件单目录心跳（待写/已写/已消费/残留/最后成功时间），供监控账本格与告警消费；实盘模式下缺失升 AlertCenter。
5. **边界**：模型进程不读终端登录态，密钥只在配置与 broker-gw；终端退出/输出超时且有实盘持仓时停止新开仓并通知。

### 5.4 验收口径（什么时候算「完善」）

| 里程碑 | 可验证的判据 |
|--------|-------------|
| 数据活 | 决策台缺口条连续 5 个交易日写「链路齐」；stock_basic 全量；新闻 `intel.raw.*` 日均有量 |
| 模型活 | 新信号四维 `source` 非 rule 占比 >80%；晨报不再 `degraded=true`；知识库检索 `degraded=false` |
| 决策可读 | 随机抽 3 笔当日信号，能在一屏内读完投票/异议/风控夹紧/证据编号，且数字能在事实包中找到 |
| 回测可信 | 一段真实长区间回测完成，六格指标 + 相对沪深300 曲线 + 成交带齐全；截断自检通过 |
| 准入通过 | P9 会话账连续覆盖 20 个交易日，无未解释对账失败；准入表逐项有记录 |
| 实盘就绪 | broker-gw 仿真联调清单全过；UNKNOWN 不重发有测试；人工确认才写文件 |
| 工程干净 | `go build ./...` 整仓通过；模板 proto 与 GORM 依赖清除；工作区无大批悬置改动 |

## 7. 风险与边界（重申，不因本方案放宽）

- 大模型只出分数和理由；价格和仓位由规则计算；订单先过 R00–R15。
- 人签字才下单；批准页确认前账本不变；实盘文件单人工确认才写。
- 模拟盘连续满 20 个交易日并通过准入前，界面继续拒绝实盘。
- 缺失写缺口（「未接入/未返回」并指明缺哪个接口），禁止 0、破折号、编造数字与假设收益。
- 红涨绿跌只用于金额与涨跌幅；发光只给健康分过低、盈亏、急停、≥85 信号、待确认>0。
- 不引入新框架/中间件；不碰 `app/discovery/`；新增接口 proto-first；表结构走 ent Schema + 生成 + data 层三件套。
