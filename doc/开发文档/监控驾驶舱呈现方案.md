## 0. 现在这页为什么看不懂

2026-10-10 的页面把 postgres、redis、nats、数据源和七个岗位做成同样大小的球，每颗球下面写一整句橙色原因，相机贴着地平面看过去，字叠成一条。底下再排六个不透明方框，多数是空的。盈亏、盘面和「nats 没连上」用的是同一种喊法，脉冲被字盖住。

要改成：远看只看见光点、脉冲和少数几张牌上的数；点开才展开下一层卡片。不重要的对象证明自己还活着就够了。

## 0.1 评审结论（对照系统设计）

系统设计要的第一眼是：今天能不能做、做什么、为什么没选上、哪条链路是空的。监控页不替代决策台的票和批准页，它负责盘面、自己的账、链路活没活、模型在不在跑。点到个股之后，要能看到四维、消息和资金因子；下单和急停仍回交易台。

对照这个目的，原文有三处会把页面再次做成字墙，实施时按下面改：

1. 运维或数据源整段没返回时，不渲染 9 个服务兜底球和 6 个数据源兜底球。缺口写在盘面、账户和岗位的短句上。只有某一个服务或数据源明确为 `down`，才升成一张只写名字的牌，原因放在点开后的子牌。
2. 中弧上的「风控」是岗位牌（brief）。后环上的 `risk` 是进程暗点（ambient）。两件东西不要画成同一种。
3. 令牌合计仍然没有读口。本轮不改 proto，模型牌第二行固定「令牌未接入」。补 `GET /v1/brain/usage` 不挡这轮卡片。
4. 连线只画至少一端是岗位或前排牌的边。后环暗点之间不再拉线。

## 0.2 改成四块流式平面（2026-10-10）

圆环把「取数、研判、结论、进程」叠在同一圈，看不出数据往哪流。系统真正的链路是一条：

采集进库 → 行情和情报 → 本地模型四维研判（只出分和理由）→ 信号、风控、账户。

监控页改成从远到近的四块半透明平面。业务脉冲沿着平面之间的连线往相机方向移动。没有真实推送时，连线上只有一颗不带标识符的流向点，表示管道方向，不表示发生了一笔交易。

| 平面 | 远近 | 上面放什么 | 回答的问题 |
|------|------|------------|------------|
| 获取数据 | 最远 | 数据源光点；盘面、扫描、消息、资金、外围 | 数进没进来，盘面什么样 |
| LLM 分析 | 中间 | 模型牌，以及技术、消息、资金、外围四张分牌 | 模型在不在跑，四维有没有分 |
| 结论 | 最近 | 风控、主管、账户 | 能不能做、做哪几笔、自己的账 |
| 运行状态 | 贴地 | 服务、中间件、磁盘和显存。正常只有光点 | 哪条进程是空的 |

四维分牌没有分数时写「未调用」。模型降级时第二行写「规则分」。令牌仍写「令牌未接入」。下钻、只读和涨跌色规则不变。

第 0.2 节的监视范围仍然有效。它的画面（俯视四块平面、白线全连、没有推送也放流向点）被第 0.3 节取代。

## 0.3 这张截图要改掉的，以及下一版画面

2026-10-10 下午的页面已经分成「获取数据 / LLM 分析 / 结论 / 运行状态」，但看起来仍是一张网：

1. 白线把每张牌都连上，业务路径被盖住。看不出「取数 → 研判 → 结论」。
2. 相机从高处俯视，牌被压扁，中文挤成一条，没有一个主数字能当标题。
3. 十几张牌一样大，多数写「未调用」。盘面、盈亏、待确认和进程光点抢同一层注意力。
4. 地面网格是画面主体。连线上的蓝点在没有推送时也在走，那不是数据，是装饰。

下一版只保留一条脊线，三层主牌正对镜头。运行状态回到底边光点，不再跟结论牌抢同一块平面。

### 画面合同

相机放在 `(0, 8, 22)`，看向 `(0, 6, 0)`，透视 30°。三层架子几乎正对镜头，主牌的字在屏幕上不小于 22px。删除 `GridHelper`。背景是纯暗色，每层架子只用一条很淡的横边，不铺格子。

每层一张主牌，其余收成芯片（只一个词，宽约 96px）。点主牌或芯片才展开第 7 节的子牌。

| 层 | 主牌 | 芯片 | 主牌回答 |
|----|------|------|----------|
| 获取数据 | 盘面：阶段，副行涨家跌家。失败写「情绪未返回」 | 扫描、消息、资金、外围。数据源正常时不占牌，只在这一层用一颗光点表示源还在；`down` 才在芯片位写出名字 | 数进没进来，盘面什么样 |
| LLM 分析 | 模型：调用次数，或熔断层名，或「未调用」。副行固定「令牌未接入」。降级时副行改「规则分」 | 技术、消息、资金、外围。没有分数的芯片写「未调用」，不要再铺四张同样大的玻璃牌 | 模型在不在跑 |
| 结论 | 账户：当日盈亏，最大的一张。副行权益和持仓只数 | 风控（守着或急停）、主管（空闲或 N 笔）。待确认大于 0 时主管升成和第二张主牌一样大 | 今天的账，有没有要处理的单 |

脊线只有三段暗线：获取数据的主牌 → 模型主牌 → 账户主牌。别的静态边不画，包括服务到岗位、岗位到岗位的全连接。

动画只由 `graph.pulses` 驱动。脉冲未过期时，一颗球从 `from` 走到 `to`，旁边带标识符（`trace:`、`signal:`、`symbol:`、`rule:`）。没有未过期脉冲时，场景静止，不放流向点，不循环空转。`position` 推送只刷新账户牌，不发粒子。

主牌宽 320、高 168，主数字 28px，等宽，字色 `--nt-text-1`，底 `rgba(8, 12, 24, 0.72)`，边 `1px solid rgba(120, 200, 255, 0.55)`。芯片字 13px，边用 `rgba(255, 255, 255, 0.18)`，没有青边。涨跌色只上账户和价格。服务健康仍用青、暗、橙、红光点。

点选后相机在 500ms 内略转向该牌，子牌在它右侧展开，最多 8 张。`Esc` 先收子牌，再回总览。WebGL 不可用时，按这三层加底边光点做纵向列表，仍是玻璃牌，不是表格。

第 0.3 节被第 0.4 节取代。第 0.4 节恢复左侧数据源的名字，但仍然禁止俯视、地面网格、空转球和所有节点互相连线。

## 0.4 三列平面：数据源、专家、裁决

屏幕按驾驶舱分格，不把所有牌丢进同一张俯视网格。顶栏从左到右是阶段和涨跌家数、涨停、信号、风控、大模型、小模型，最右是当日盈亏。左栏每个数据源写状态，并写它送往哪个专家。中间是一条管道：上方两档模型用青线连到它们负责的专家，扫描把候选并行送到四维，综合再连到信号和风控。每张牌写职责，节点有状态光环，连线是三股束线。没有真实推送时束线不动。点一个数据源，被它喂到的专家牌亮边。点一张牌弹出圆角磨砂窗，读明细。模型和数据源可以改已有配置项。底栏只写中文服务名，点开看状态、审计记录，并可以重新检查；没有启停开关。中间数据流铺满画布，牌正面朝前、字号按屏阅读：扫描在左，四维同一列并列，再汇到综合、信号、风控；两档模型贴在专家列上方，青线从牌底连到负责的专家。连线从牌的右缘进左缘，不交叉穿过牌面。没有真实推送时线上没有光点。右上写接口已接或未接、模型名、调用和延迟；花费在令牌合计接口出现之前写「未接入」，不用调用次数冒充金额。右下账户用最大的盈亏数字。底栏用中文职责，例如数据库、消息总线，不直接显示 postgres、nats。风格参照 [3D NEXUS](https://metaquantuniverse.com/nexus/) 的深色座舱和顶栏大数字，不搬它的订单簿和币圈行情。

| 列 | 位置 | 第一眼 |
|----|------|--------|
| 获取数据 | 左 | 一个区域里放数据源，每源一个光点和名字。接口没返回时这一列只有一张牌：「数据源未返回」。有列表时最多 12 张，多的收成「还有 N」 |
| 专家 | 中 | 顶上一条模型状态。下面是扫描和四个维度，再汇到综合 |
| 裁决与账本 | 右 | 信号、风控、账户。这是最大的字 |

底边单独一排运行状态光点：服务、中间件、磁盘和显存。正常不写名字。`down` 才在光点旁写出名字。它们不进三列，也不和数据源连线。

### 左列：数据源

每张源牌两行：名字，以及状态词（在用 / 空闲 / 中断 / 未返回）。颜色在光点上，不用涨跌色。点开才给成功率、延迟、配额、最近错误。这些字段接口里没有时写「未返回」，不写 0。

源只连到会用到它的专家，按名字匹配，一条源最多两条线：

| 名字里有 | 连到 |
|----------|------|
| 通达信、tdx、tushare、akshare，且不是新闻或宏观 | 扫描、技术 |
| 新闻、快讯、公告、研报 | 消息 |
| 资金、龙虎榜、北向 | 资金 |
| 外围、宏观、global | 外围 |
| 涨停、情绪、板块 | 扫描 |
| 对不上 | 只连扫描 |

源和源之间不连线。

### 中列：模型条和专家

模型条在专家区上方，横跨这一列，两块并排，数据来自 `GET /api/brain/stats` 的两档：

| 块 | 主词 | 副行 |
|----|------|------|
| 大模型 `large` | 模型名。未配置写「未配置」，熔断写「熔断」 | 调用次数、在途、排队。没有次数写「统计未返回」 |
| 小模型 `small` | 同上 | 同上 |

两块下面共用一行：「令牌未接入」。合计接口没做之前不写 0。技术、资金走小模型；消息、外围、综合走大模型。这是路由说明，写在点开模型条之后，不写在牌面上。

专家按真实处理顺序排，四维是并行的，不要画成一个个往下传话：

1. 扫描。规则漏斗，不是大模型。牌面是阶段和涨停只数，失败写「未返回」。
2. 技术、消息、资金、外围并排。牌面是最近一笔信号里该维的分数；没有分数写「未调用」。降级时副行写「规则分」。
3. 综合在四维下方。牌面是综合分；没有信号写「未调用」。

连线只有这些：

- 扫描 → 技术、消息、资金、外围（候选送去并行研判）
- 四维各自 → 综合
- 综合 → 右列的信号

没有研判结果时，这些线画成暗线，表示路径在，不表示刚才跑过。球只在真实脉冲上移动。

### 右列：裁决与账本

模型只出分和理由。价格、仓位、能不能下，都在这一列用规则完成。

| 牌 | 主词 | 点开 |
|----|------|------|
| 信号 | 待确认笔数；0 写「空闲」；接口失败写「信号未返回」 | 代码、分数、入场、止损、止盈、状态。另给一张「回到交易台确认」，只做路由跳转 |
| 漏选 | 有漏选原因的条数；没有候选接口写「候选未返回」 | 代码、模板、漏选原因，最多 8 条 |
| 风控 | 「守着」或「急停」 | 模式、熔断、当日买单、命中的 `Rxx`、日报摘要。没有急停按钮 |
| 账户 | 当日盈亏，这一列最大的字 | 持仓、委托、成交。失败写「账户未返回」 |

连线：信号 → 风控 → 账户。待确认大于 0 时，信号牌升到和账户一样大。

### 点开一个专家

在中列链路下方展开四格，不盖住右列的盈亏，也不在三维场景里再扇一排小牌。

| 张 | 现在就能写的 | 还没有读口时 |
|----|----------------|--------------|
| 输入 | 该维用到的 `F:`、`N:` 条数；扫描则写漏斗留下的只数 | 「这次没有研判」 |
| 输出 | 分数或综合总结；降级写「规则分」 | 「未调用」 |
| 动作 | 扫描写漏斗数字；四维和综合写「只出分，不下单」；风控写命中的规则号 | 不编一段执行日志 |
| 正文 | 信号里已经带回的理由第一句 | 「研判正文未接入」。`llm_call_log` 里有摘录，但桌面还没有只读接口，本轮不新做这条接口，也不要编造思考过程 |

### 动画和字

静态线用暗青色，透明度约 0.35，只按上面三张表来画。脉冲仍只来自 `market`、`brain`、`signal`、`alert`，沿已有的那条线走，旁边带短标识符。没有未过期脉冲时画面静止。

数据源牌约 148×52。专家牌约 168×72。账户和升格后的信号牌约 280×140，主数字不小于 28px。玻璃底 `rgba(8, 12, 24, 0.72)`，专家和裁决的主牌用一圈细青边。涨跌色只用于盈亏和价格。

WebGL 不可用时，同样三列纵向排列，底边光点放在最后，仍是玻璃牌。

## 0.5 纤维画布：ComfyUI 式可拖拽节点图（2026-10-12）

参考界面的结构（抖音视频《YOUR LLM'S SECOND BRAIN》，用户截图两轮）加上 ComfyUI（litegraph）的交互方式，把整页改成一张 2D 画布：

- **技术**：`three` 依赖整体移除，改用单张 2D canvas（`canvas-stage.ts` 纯几何引擎 + `CanvasStage.vue` 渲染器）。配色从 `--nt-*` 令牌实时读取（MutationObserver 盯 `data-theme`），深浅色同一份。canvas 不可用时显示降级文案，监控改读 HUD 和终端带。
- **卡片**：圆角牌（标题带 = 域名色 + 状态点 + 中文职责小字；牌面 = 主词 + 副行；左右缘各一个端口圆点）。牌面只写 scene-model 给的 `face`/`sub`，不编数字。
- **交互**：卡片可拖动（拖哪张算哪张，边上的束线跟着重画）；拖空白平移；滚轮以光标为轴缩放（0.35–1.8）；双击画布或顶栏「重置视图」复位布局与视角。点牌弹原来的磨砂详情窗，点空白收窗。`Esc` 先收弹窗，再回总览。
- **布局（继承 0.4）**：三列标签「01 接入 / 02 研判 / 03 裁决」。数据源竖排在左（数据质量源不上台）；扫描在四维块中位；技术/消息/资金/外围四维并行一列；综合居中；信号、漏选、风控、账户（最大）在右列。大模型、小模型、令牌（令牌未接入）横排在四维块上方，小模型在左、大模型在右，各连自己负责的专家。
- **连线**：端口到端口的水平贝塞尔（模型 → 专家走竖向贝塞尔）。每条逻辑边画两股错开曲线，颜色取发出方的域名色。同源多目标时端口沿缘扇出，不拧成一股。
- **动画**：无推送时每股上有一个低亮度流向点（常驻环境流，只表示管道方向）；真实 WS 脉冲画成亮彗星 + 两格渐隐尾迹 + `kind:value` 标签（TTL 2400ms）。脉冲端点映射：service:brain → 大模型；service:market → 扫描牌左缘入口；post:model → 综合；不上台的端点不画。
- **选中**：选中的牌及其相邻牌保持亮，其余边和牌压暗；HUD 数字带的八格也能点选对应节点。
- **底部终端带**：一行运行状态光点（正常只给光点，down 才写名字，中文职责名）+ 四格终端：运行日志（通知+审计按时间合并）、任务调度（回测任务+模拟准入进度+影子对照）、模型链路（分档统计，固定注明「令牌合计接口未做，花费不折算金额」）、账本（当日盈亏大数字 + 权益/现金/持仓/委托/风控）。
- **放宽项（相对 0.4）**：允许常驻低亮度流向点；允许底部终端窗常驻；允许 44px 低对比点阵网格（只作定位参考）。
- **仍守住的边界**（第 1 节不变）：只读；红涨绿跌只上金额和百分比；缺口写「未返回/未接入」不编数；不进 `panel-registry.ts`；急停和下单仍回交易台。

## 0.6 时段带 + 健康分 + 十格 HUD（2026-10-12，S1 落地）

按《监控驾驶舱业务监控方案》S1 实施，画面合同在 0.5 之上加四样：

- **时段带（26px，HUD 之上）**：七个交易时段分段（盘前自检 08:30–09:15 / 竞价 09:15–09:25 / 上午 / 午休 / 下午 / 尾盘 14:30–15:00 / 盘后 15:00–17:00）+ 右侧倒计时（距竞价/距开盘/距午休/距收盘）+ 当前时段焦点问题一行。周末与节假日显示「今日休市」。时段判定是纯函数 `timeband.ts`（工作日规则，节假日暂无日历接口，数据静默由 S2 兜底，不编假日表）。
- **时段感知焦点（拓扑永不变）**：竞价时段 `post:scan` 加宽到 272px 升为焦点牌（face 20px）；尾盘 `book:center` 同样。午休画布压暗 0.75、盘后 0.5，休市/午休/盘后停掉环境流向点（calm）。卡片拖动偏移按时段分别记 localStorage（`nt-monitor:offsets:v1:<band>`）。
- **健康总分（顶栏）**：`健康 N` 徽章四档着色（≥90 青 / 70–89 常态 / 50–69 橙 / <50 红+glow）。点开弹层列五项扣分明细（数据新鲜度 20 / 服务存活 20 / 模型可用 20 / 风控在线 15 / 交易通道 25），每项写扣分原因；测不到的项标「未判定」并点名缺的接口。纯函数 `health.ts`，模拟盘通道固定扣 5（满分 95 是设计不是缺陷）。
- **HUD 扩到十格（76px）**：阶段/涨停/炸板率/主线/信号/漏选/风控/大模型/GPU/当日盈亏。前五格按时段替换（盘前=昨日缺口三格、竞价=竞价三格、午休=半场三格、尾盘=持仓三格、盘后=复盘三格、休市=任务三格），「当日盈亏」hero 格永驻末尾。五格带 sparkline（涨停数/炸板率/待确认数/P95/日内盈亏，RingSeries 会话内 30 采样，接口没返回断线不画）。同比箭头用 `--nt-text-3` 不用红绿。缺口格写「未接入：需要 GET /v1/…」。
- **纯函数与测试**：`timeband.ts`（时段判定/段落/倒计时/HUD 定义）、`health.ts`（健康分）、`hud.ts`（十格内容解析）、`sampler.ts`（RingSeries + sparkPath）全部纯函数；vitest 45 例覆盖（timeband 13 / health 12 / hud 12 / sampler 8…以 `web/src/monitor/*.test.ts` 为准），时段判定与健康分计算是 S1 验收的硬指标。

## 3. 卡片三档

`buildScene` 给每张牌一个 `rank`，视图只认这个字段，不在组件里再写一套如果。

| rank | 何时 | 三维里长什么样 |
|------|------|----------------|
| `ambient` | 正常的服务、数据源、风控、资源 | 半径 0.28 的球。颜色表示状态。没有 HTML 文字。`down` 或 `gap` 时才在球旁放一张极小玻璃条，上面只有名字 |
| `brief` | 七个岗位在正常工作 | 玻璃卡片，宽 168、高 64。第一行名字，第二行一个词或一个数 |
| `focus` | 盘面、账户，以及任何升格的异常 | 玻璃卡片，宽 260、高 120。最多四行。数字用等宽 |

升格规则（命中就从 ambient/brief 变成 focus，解除后回到原档）：

- 服务、数据源、资源状态为 `down`。
- 风控 `killActive`，或市场熔断非空。
- 模型任一层 `circuitOpen`。
- 主管待确认笔数大于 0。
- 情绪 `stale`，或阶段为 `HOT`、`FADE`、`ICE`。

盘面和账户永远是 `focus`，即使数字平静。

脉冲仍只来自真实推送：`market`、`brain`、`signal`、`alert`。球只在有未过期脉冲时沿第 0.3 节的路径移动，旁边一个短标识符。没有事件时场景静止。`position` 不发粒子，只刷新账户牌。

## 4. Three.js 卡片，不用传统界面

场景用 `WebGLRenderer` 只画第 0.3 节的三段脊线和真实脉冲。不画地面网格。所有可读的字用 `CSS3DRenderer`（`three/addons/renderers/CSS3DRenderer.js`）把 DOM 卡片放进同一相机。不用 canvas 写中文，不用底栏 HTML 六宫格，不用 `NtTable`。

卡片 DOM 结构固定：

```text
article.nt-glass
  span.dot          状态光点
  strong            标题
  em                主数字或主词
  small             最多两行补充，没有则不渲染
```

玻璃样式只写在 `.nt-monitor .nt-glass`：

- 背景 `rgba(14, 18, 32, 0.46)`
- `backdrop-filter: blur(16px)`
- 边 `1px solid rgba(255, 255, 255, 0.18)`
- 字色 `--nt-text-1`，辅字 `--nt-text-2`
- 圆角 12px
- 主数字 `--nt-font-mono`
- 涨跌只加 `.up` / `.down`

相机、主牌和脊线以第 0.3 节为准。第 0.2 节的四块平面坐标和全连接作废。运行状态的服务、资源和数据源仍是光点，排在画面底边，不和结论牌叠在同一块板上。`down` 才在光点旁写出名字。

点一张牌：相机在 500ms 内看向它，它右侧用同一套玻璃卡片扇出子牌，最多 8 张，第 9 张写「还有 N」。再点子牌，替换这一扇，不叠第三层传统抽屉。`Esc` 先收子牌，没有子牌再回总览。子牌不是屏幕右侧的 320px 白底栏。

总览里不再渲染 `.nt-terms` 六窗。新闻不做成底栏长条；消息牌点开后，每条标题是一张小玻璃卡。

WebGL 不可用时，用同一批 `rank` 数据做三排玻璃卡片的纵向列表（仍是 `.nt-glass`，不是表格）。这是降级，不是第二套仪表盘。

## 5. 牌面文案

每张牌的主词必须短。原因放进点开后的子牌。

| 牌 | 主词 | 补充 | 主词为空或失败时 |
|----|------|------|------------------|
| 盘面 | 阶段，如 `WARM` | `涨 12 跌 30` | `情绪未返回` |
| 账户 | 当日盈亏，带正负和涨跌色 | `权益` 与 `持仓 N` | `账户未返回` |
| 扫描 | 阶段词，与盘面相同 | 涨停只数 | `未返回` |
| 模型 | 调用次数 | 熔断时改成层名 | `统计未返回`；令牌行在合计接口完成前固定为 `令牌未接入` |
| 消息 | 条数 | `晨报` 或 `热词` | `晨报未生成` |
| 资金 | 领涨板块名 | 固定不写假资金分 | 板块失败：`板块未返回`。成功：第二行 `资金未接入` |
| 外围 | 有脉冲的板块名，或 `未调用` | 无 | `未调用` |
| 风控 | `守着` 或 `急停` | 急停原因不超过 12 字，其余在子牌 | `风控未返回` |
| 主管 | `空闲` 或 `N 笔` | 无 | `信号未返回` |

数据源和服务在正常时没有主词。失败时小玻璃条只写名字，例如 `nats`，不写「数据降级，不是最近交易日」。那句原因放在点开后的第一张子牌。

## 6. 唯一要补的读口：令牌合计

`llm_call_log` 已有每次调用的 `prompt_tokens`、`completion_tokens`、`tier`、`status`、`created_at`。`Stats` 没有合计。

在 brain 增加只读 `GET /v1/brain/usage`，经 admin 现有 `/api/brain/` 转发，不新开服务。

返回：

```text
date
promptTokens
completionTokens
calls
failures
tiers[]: tier, model, promptTokens, completionTokens, calls, failures
```

口径：`created_at` 落在请求日（默认今天，上海时区）的行求和。失败行仍计入令牌（调用已经发生）。没有行时各数字为 0，并带 `empty: true`，界面写「今日无调用」，不要写成未接入。

本轮不实现这条接口。模型牌第二行保持「令牌未接入」。接口落地后，`empty: true` 写「今日无调用」，有合计才写数字。
