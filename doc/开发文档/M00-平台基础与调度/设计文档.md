## 1. 时段状态机

时区固定 `Asia/Shanghai`。非交易日全天 `CLOSED`。

```
CLOSED → 07:30 PRE_OPEN → 09:15 CALL_AUCTION → 09:25 PRE_MATCH
      → 09:30 AM_TRADING → 11:30 NOON_BREAK → 13:00 PM_TRADING
      → 15:00 POST_CLOSE → 15:30 CLOSED
```

14:30 起 `PM_TRADING` 带子状态 `LATE_SESSION`。每次变化发 `sys.session.changed`。

## 2. 自动建库

1. 连接 `postgres` 系统库。
2. 若没有 `novatrader` 则 `CREATE DATABASE`。
3. 连接业务库，拿 PostgreSQL advisory lock。
4. 执行 ent `Schema.Create`。新字段必须有默认值。
5. 需要 pgvector 时，在迁移前执行 `CREATE EXTENSION IF NOT EXISTS vector`。这是基础设施语句，封装在 `pkg/dbinit`，业务代码不写 SQL。
6. 服务启动时调用 `pkg/entclient.Open`，把上面几步和打开 `*ent.Client` 合成一次。各 app 的 `NewEntClient` 只做配置映射。schema 包留在 `backend/ent`，不按服务拆分。

`CREATE DATABASE` 不能放进事务。

## 3. 事件

关键业务（订单、信号、风控、告警）走 NATS JetStream，至少一次，消费端幂等。行情快照走普通 NATS，不落盘。

写库和发事件用 Outbox：同一事务写业务表和 `outbox`，后台再投递。

### 3.1 版本与因果元数据

合同定义位于 `backend/pkg/events/envelope.go`。`New` 保持现有调用方式并生成版本 1；`Unmarshal` 同时接受缺失版本的旧信封（版本 0），拒绝未知非零版本、负 `entity_version` 和非法载荷 JSON。

| 字段 | 语义 |
|------|------|
| `event_id` | 事件身份；重试、outbox 重投沿用同一值 |
| `trace_id` | 链路身份；与直接父事件身份分开 |
| `causation_id` | 真实直接父事件的 `event_id`；未知时缺失 |
| `correlation_id` | 关联身份；有父事件时继承其值，父值缺失时使用父 `trace_id` |
| `entity_id` / `entity_version` | 可选业务实体身份和非负版本；未迁移生产者可以不填 |
| `time` | 本事件形成时间；outbox 写入要求非零 |
| `source_time` / `received_at` | 可选已知源时间、接收时间；公共构造器不推测或自动补填 |
| `published_at` | `Bus.Publish` 记录的本次发布尝试时间；不是源时间或投递成功保证 |

消费端用 `ContextWithEnvelope` 放入实际父事件，后续生产端用 `NewWithContext` 延续链路、直接因果、关联身份和已知源时间。无父事件或父源时间未知时保持缺失。普通 `New` 调用继续兼容，但不会自动产生因果关系；当前仅已触及的 trade/risk 路径接入，不能据此推断全业务链路已经贯通。

### 3.2 Outbox 持久化与恢复

共享 schema 为 `backend/ent/schema/outbox.go`，追加可选 JSON `metadata`；生成物继续由 `backend/` 下的 `go generate ./ent` 维护。

1. `outbox.Insert` 校验信封，在调用者的 `*ent.Tx` 内同时写入稳定身份列、载荷、原事件时间和元数据。`metadata` 不重复保存载荷，也不保存仅属于某次发布尝试的 `published_at`。
2. `Dispatch` 读取未发布行，恢复元数据。主列的事件、链路、来源、主题和载荷是权威值；旧行没有 `metadata` 时使用原 `created_at` 恢复 `time`，其余未知字段仍缺失。
3. 恢复失败或发送失败时增加 `attempts`、记录错误并停止本批投递；成功后才写 outbox 行的 `published_at`。稳定 `event_id` 供 JetStream 去重及业务消费幂等使用。
4. 业务事务保证已接入写入路径的业务数据与 outbox 一起提交。账户快照、日初资金和对应事件已在 trade 数据仓储中使用该边界，详见 [M09 设计文档](../M09-交易执行/设计文档.md)。数据库提交与 NATS 发布并非同一事务，发布成功后标记失败仍可能重投，消费端须保持幂等。

以上为2026-10-15元数据合同。2026-10-18追加了 `pkg/outbox/lease.go`：短事务`FOR UPDATE SKIP LOCKED`领取、30秒owner租约、事务外10秒发布、owner与有效租约条件确认、指数退避和12次后死信，非法元数据直接隔离。发布成功但本地标记失败仍会重投，JetStream窗口不能替代业务持久幂等。完整合同、当前只读追踪与无死信写入口见[租约与追踪记录](../实施记录/N2-02-事件租约与追踪-2026-10-18.md)。
