# M00 平台基础与调度 · 需求文档

## N2-02 投递可靠性补充（2026-10-18）

多实例dispatcher必须用有期限领取租约；网络发布不得长持数据库行锁，重试保留event_id。坏记录应隔离并暴露死信，不能挡住健康事件；发布成功与下游完成分开。当前实现和验证见[租约与追踪记录](../实施记录/N2-02-事件租约与追踪-2026-10-18.md)，死信人工重放写入口仍未开放。

## N2-01 进程操作观测补充（2026-10-18）

真实收到、入队/合并、执行中与完成结果必须分开；固定注册操作提供一分钟窗口、重启身份和完成口径，未知/未注册/未采样保持明确缺口。不得把本地函数返回或收到消息表述为broker确认或全链成功。合同与实测见[消费者与环境观测](../实施记录/N2-01-消费者与环境观测-2026-10-18.md)。

## N0-02 事件合同验收口径（2026-10-15）

- 新事件使用 `schema_version=1`；缺失版本的旧事件按版本 0 读取。不支持的非零版本、负实体版本及非法 JSON 载荷必须拒绝。
- `event_id` 标识一条事件，`trace_id` 标识链路，`causation_id` 只记录真实的直接父事件；关联与实体字段可选。没有父事件时不得补造因果关系。
- `source_time`、`received_at`、`published_at` 分别表达已知源时间、接收时间和本次发布尝试时间。未知值保持缺失，不用事件形成时间、重放时间或界面刷新时间替代。
- outbox 同一事务保留载荷和信封元数据；投递失败后重试不得改变 `event_id`。旧行没有元数据时仍可读取，未知源时间继续缺失。
- 验证须覆盖旧新合同兼容、真实父事件传递、元数据落库恢复、投递失败重试，以及业务快照与 outbox 同时提交或同时回滚。独立测试实例的通过记录与全环境、长期调度及压力验收分开记录。

当前实现范围与尚未完成项见 [开发进度](开发进度.md)。跨所有业务域的因果贯通、outbox 多实例领取租约及死信处置仍需后续实施。
