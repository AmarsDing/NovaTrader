# OpenBB、RD-Agent、vectorbt 与 NovaTrader 的接入研究

核验日期：2026-10-14。本文是总体实施方案的研究依据，记录官方项目事实、当前代码证据与建议。所有接入项均为待实施方案；本次未安装第三方依赖、未连接外部账户、未启用交易。

## 1. 选择结论

| 项目 | 对 NovaTrader 的位置 | 建议 | 不能混淆的边界 |
| --- | --- | --- | --- |
| OpenBB ODP | M01 的外围市场、宏观和可选衍生品采集连接器 | 按数据域做小范围 POC，优先宏观/跨市场，保留现有 A 股主源 | 连接器不等于数据授权、实时订阅或 A 股全覆盖 |
| Microsoft RD-Agent | M07 之外隔离运行的因子/模型研究作业 | 先冻结研究数据，再接离线提案，不进入交易热路径 | 自动写研究代码不等于自动获得有效策略，更不等于可自主上线 |
| vectorbt | 大批参数/因子组合的第一轮筛选器 | 许可审查后可选，最终候选仍用现有 Go 引擎复核 | 当前许可为 Apache-2.0 + Commons Clause；PRO 能力不能算入社区版 |

最先补的并非又一套框架，而是可重放的数据集版本、当时可用时间、真实历史覆盖、任务隔离与监控证据。只有这些先成立，新的研究工具才能提高效率。

## 2. 当前 NovaTrader 已有基础与不足

以下来自本地手写代码定向核验，不把文档的“完成”当作真实市场验收。

| 本地证据 | 已有能力 | 接入前要补的部分 |
| --- | --- | --- |
| [pyworker 说明](../../../pyworker/README.md)、[Go 边车适配器](../../../backend/app/datahub/internal/data/pyworker.go) | HTTP 调用通达信/AkShare；Python 只采集，不写库、不下单 | OpenBB 不能绕过 Go 采集校验、源状态、限频、质量标记 |
| [回测类型](../../../backend/pkg/backtest/types.go)、[引擎](../../../backend/pkg/backtest/engine.go) | 分钟/日线事件回测、按决策日复权、共享 A 股撮合/费用/T+1、数据/成交哈希 | 新引擎结果必须使用相同价格、成本、可卖量、涨跌停和成交时序口径比较 |
| [优化](../../../backend/pkg/backtest/optimize.go)、[截断自检](../../../backend/pkg/backtest/lookahead.go) | 网格/随机搜索、滚动前推、防未来扰动检查 | 防未来检查不是所有偏差证明；需要可用时间、退市样本、成分股历史与多重试验控制 |
| [自省与提案](../../../backend/app/backtest/internal/biz/evolve.go) | 后验归因、参数进化、样本外改善才提案、审批/回滚 | RD-Agent 应扩展候选与证据，不再建一套可绕过审批的策略生效通道 |
| [宏观 Schema](../../../backend/ent/schema/macro_series.go) | 指标期 `obs_date`、采集时刻 `as_of` | `code/obs_date` 唯一，修订易覆盖；缺发布时间、修订版本、当时可用值 |
| [财报 Schema](../../../backend/ent/schema/finance_report.go) | 报告期与公告日，修正公告分行保存 | `ann_date` 缺失时取报告期不能用于训练可用时间；需要真实发布时间/未知状态 |
| [证券基础](../../../backend/ent/schema/stock_basic.go)、[回测 Source](../../../backend/app/backtest/internal/data/source.go) | 有上市/退市字段、历史名称，区间有 K 线的股票进入回测池 | Source 暴露上市日、名称史，未提供完整证券状态/历史成分接口；退市 K 线是否齐全仍需对拍 |
| [事件信封](../../../backend/pkg/events/envelope.go) | `event_id/trace_id/time/source/subject/payload`；行情内存消息与关键持久事件分开 | 研究任务和数据集增加版本、业务时间和完成事件，不把大矩阵灌入 NATS |

特别需要防止两类时间混淆：宏观的“2025 年 1 月数据”不是 1 月 1 日已知；财报的“2025 年末报告期”也不是年末已公开。无法证明当时可用的数据可以供当前展示，不能进入历史训练或晋级证明。

## 3. OpenBB ODP

### 3.1 官方事实与版本边界

官方 README 自指的仓库为 [OpenBB-finance/OpenBB](https://github.com/OpenBB-finance/OpenBB)，描述的是 Open Data Platform（ODP）；用户给出的 [openbq-org/OpenBB](https://github.com/openbq-org/OpenBB) 在本次核验也能访问，README 链接仍自指前者。因此保留两个地址的核验记录，不依据缩写直接判定用户地址错误。

ODP 主仓当前为 [Apache-2.0](https://github.com/OpenBB-finance/OpenBB/blob/develop/LICENSE)。代码许可不授予第三方行情的使用、转售或再分发权。官方 V5 文档明确：OpenBB 不托管/提供数据，覆盖、限频及使用条款由上游服务决定。[Provider 官方说明](https://docs.openbb.co/odp/python/extensions/providers)

V5 使用按 provider 分开的命名空间与可独立安装包；部分 V4 provider 已移除，旧 `openbb-core` 1.x 连接器不能与 core 2 混装。不能从历史文章复制 `obb.equity.*`/yfinance 等示例就认定当前 V5 可运行；POC 应锁定实际包、版本和命令清单。[V5 Provider 清单与迁移边界](https://docs.openbb.co/odp/python/extensions/providers)

核心运行时以 `QueryParams/Data/Fetcher` 做请求校验、采集、结果转换，可通过 Python 或 REST 使用；`openbb-core` 单独安装没有数据源。适合吸收其 provider 接口和元数据模式。[官方架构](https://docs.openbb.co/odp/python/concepts/architecture)、[标准化规则](https://docs.openbb.co/odp/python/developer/standardization)

### 3.2 应复用的业务功能

- 跨市场背景：海外股指、利率、经济日历、能源/商品、宏观政策资料，补充 M05 外围联动解释。
- 一致的 source/字段/单位/错误分类，显示“数据来自谁、是否延迟、何时观测、支持什么”。
- 有许可与实际需求后再接期权/衍生品；它们属于新的数据域，不先变成 A 股交易指令。
- 按需使用 provider 扩展。当前官方核心列表主要是境外及公共经济数据，不能据此承诺沪深北全市场实时/分钟历史/公司行为覆盖；A 股继续由现有 M01 通达信/Tushare/AkShare 等统一接入。

### 3.3 具体接法

```text
已有 scheduler → datahub/biz 域任务 → datahub/data OpenBB 适配器
                                          │ HTTP（固定白名单的数据命令）
                                          ▼
                                 Python 数据边车的 OpenBB 角色
                                          │ 原始结果 + 上游时间/单位/警告
                                          ▼
datahub 校验/质量/限频/来源登记 → Go data 层 ent → PG
                                          │
                                 md.<domain>.ready → 下游处理/监控
```

沿用当前边车 HTTP 边界；重依赖独立虚拟环境/进程隔离，不把 OpenBB import 到每次盘口采集的热路径。Python 不直写 PG、不新增第二个业务数据库、不暴露任意执行命令。是否使用 OpenBB 自带 REST 是 POC 的实现选择，Tauri 前端仍只连 admin，不直连第三方服务。

结果转成 NovaTrader 的领域 DTO，额外保留 `provider/package_version/source_time/received_at/available_at/unit/currency/delay_kind/revision/raw_hash`。不可得字段为未知，不用接收时钟代替源数据时间。FRED 等 key 只保存在服务器凭据环境，不经 UI/NATS 传播。[官方凭据接口](https://docs.openbb.co/odp/python/user-guide/credentials)

### 3.4 最小 POC 与验收

选一个无需新账户的公开宏观域，或使用用户已授权的现有 key，最多 3 个指标；冻结 30 条原始样本。验收：单位/百分比、上海/UTC、观察期/发布时间不混淆；空结果/429/上游超时能正确记录；重复请求不重复入库；修订值可追溯；采集关闭时不影响 A 股快照；监控能看到源状态和质量。不能证明发布时间则该指标仅参与当前背景展示。

## 4. Microsoft RD-Agent

### 4.1 官方事实与边界

官方仓库 [microsoft/RD-Agent](https://github.com/microsoft/RD-Agent)，[MIT 许可](https://github.com/microsoft/RD-Agent/blob/main/LICENSE)。当前 README 要求 Linux，多数场景使用 Docker，区分因子、模型和联合研究；模型调用及算力费用另计，代码免费不能等同于运行免费。[官方快速开始](https://github.com/microsoft/RD-Agent#-quick-start)

量化场景与 Qlib 紧密关联，可提出研究假设、生成代码、执行实验、反馈迭代；官方示例使用训练/验证/测试区间、CSI300 和特定组合策略。示例收益或论文表现不能作为 NovaTrader 的预期收益。默认样例不代表当前全市场 A 股、分钟超短线或本项目执行规则已经适配。[量化场景文档](https://rdagent.readthedocs.io/en/latest/scens/quant_agent_fin.html)、[因子实验接口源码](https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/experiment/factor_experiment.py)

### 4.2 应复用的业务功能

- 盘后研究代理：从已授权的研究报告/复盘问题提出可检验的因子假设。
- 自动形成候选代码、因子定义、实验配置、失败原因与反例，给用户一张可审查的“研究提案卡”。
- 基于 M07 现有自省的亏损归因，提出限定参数或新增因子实验，保留人工审批和回滚路径。
- 让 AI 处理研究工作量；实时定价、仓位、风险批准、交易仍由确定性服务完成。

### 4.3 具体接法与隔离

不并入仅采集的 pyworker；未来新增可选 `research-worker`，Linux/DGX 上以受限作业运行，Go backtest 服务拥有任务状态与持久记录。

```text
M07 研究任务 → 冻结数据 manifest + 预算/截止时间 → 隔离 research-worker
                   │                              │
                   │                      RD-Agent/Qlib 候选实验
                   │                              │
                   └──── 产物校验/泄漏检查 ← 因子/代码/日志/环境摘要
                                      │
                           Go 事件回测 + 样本外/压力复核
                                      │
                      待审批提案 → 策略版本 → 影子 → SIM → 有限准入
```

建议新研究记录独立于每日选股 `StrategyCandidate`，不要把“研究实验”塞进按股票/交易日唯一的候选表。追加 ent `ResearchRun/ResearchArtifact/FactorDefinition/DatasetManifest/ModelVersion` 等手写 Schema，由 Go data 层管理。NATS 发小型状态/完成通知，数据矩阵通过只读文件产物与 hash 交换。新主题是否持久化必须登记到 `events.StreamSubjects` 和 ACL；不能假设任意新主题会自动进入 JetStream。

研究容器无账户凭据、无交易服务路由、无 PG 写权限、无宿主 Docker socket；只读数据输入，单独输出目录。限制 CPU/GPU/内存/磁盘、作业墙钟、LLM tokens/费用、并发和迭代次数；取消/超预算杀作业并保留日志。生成代码、模型反序列化和研报内容按不可信产物处理，不能在主服务进程执行。

建议首个 POC 上限为 5 个因子、3 次研究迭代、1 个预先锁定的研究问题；实际资源预算在任务创建时显式固定。隔离、限额、人工晋级是 NovaTrader 接入要求，不是宣称上游已经替我们实现了这些门槛。

### 4.4 数据与研究验收

先用纯价格量因子，随后才加入消息/财报/宏观，避免一开始就引入不可证的可用时间。固定训练/验证/封存测试，不让 Agent 看封存测试结果后反复调优；有标签重叠时做 purge/embargo。按市场阶段/板块/流动性分层，保存全部失败实验，报告总试验数，评估换手与成本敏感性。

POC 通过须有：固定数据+环境+seed 可重放；因子只读当时可用数据；截断扰动前的输出不变；新增因子不是已有因子的简单重复；样本外结果、费用翻倍/滑点恶化、缺数与停牌均有记录；超时取消有效；产物审查与 Go 引擎复核完成。统计通过只允许成为待审批候选，不自动修改生产权重。

## 5. vectorbt

### 5.1 官方事实与许可边界

官方仓库 [polakowo/vectorbt](https://github.com/polakowo/vectorbt)。当前许可是 **Apache-2.0 with Commons Clause**，上游自称 fair-code；条款对以该软件功能构成主要价值的收费产品/服务有限制，不能按“纯 Apache 可自由商业化”处理。实现 POC 前固定版本和许可快照；商业分发/服务化前按实际用途审查或取得授权。[当前 LICENSE](https://github.com/polakowo/vectorbt/blob/master/LICENSE.md)

社区版可做数组参数批量模拟、信号/订单/自定义订单函数、绩效分析。PRO 是另一产品，更多并行、验证/优化、交易类型及工具能力不能默认包含在社区版；不把当前 master、旧教程和 PRO 文档拼成一张能力清单。[社区 README](https://github.com/polakowo/vectorbt#readme)、[社区版与 PRO 对照](https://vectorbt.dev/getting-started/upgrade/)

### 5.2 应复用的业务功能

把上千组均线窗口、阈值、选股因子组合做快速第一轮筛选，输出参数热力图、稳定区域与差异。目标是节省研究时间，并非新增一个与当前 Go 回测互相矛盾的准入裁判。

其订单回调允许自定义状态逻辑；共享现金与同一时刻资产处理顺序会影响结果，必须显式固定。默认简单 `from_signals` 不能证明已正确模拟 A 股可卖量、涨跌停排队和费用结构。[官方 Portfolio API](https://vectorbt.dev/api/portfolio/base/)

### 5.3 具体接法

在可选 Python 研究环境实现 `VectorScreenAdapter`，输入 Go 导出的不可变 dataset manifest，输出候选参数、筛选分数、模拟假设与产物 hash。由现有 Go 任务队列记录进度/取消；筛选结果仅送回 M07 做事件回测，复用已有优化提案审批。

先做“因子/参数计算加速”，再决定是否使用其组合撮合。若必须做 A 股模拟，需要自定义卖出可用量、整手/尾仓规则、交易时段、成交量上限、双边/单边费用与最小费、停牌/涨跌停；没有足够订单簿时保守判未成交。研究、验证和真实撮合结果要标注不同引擎，不伪称订单逐笔一致。

### 5.4 最小 POC 与验收

先取已归档的 30 只证券、至少 2 年日线、100 个参数组合；包含退市/停牌/名称变更/除权案例，具体区间以数据实际覆盖为准。比较纯因子数值及信号时间，不能仅比较收益率。独立记 Numba 冷启动编译耗时与热启动耗时、峰值内存、取消响应；速度必须在同样的数据和规则下测，不引用上游“几秒完成”作为本机承诺。

排名前列候选回到 Go 引擎重跑，列出因撮合/成本/时序导致的差异；选 3 笔成交手工核账。若节省的时间不足以覆盖维护/许可成本，保留现有 Go 搜索即可，不引入运行依赖。

## 6. 三项目共同的数据契约

建议先定义以下版本化契约，再安排 AI 实现适配器。字段属于计划，并非现有接口已支持。

| 契约 | 最小字段 | 验收重点 |
| --- | --- | --- |
| DatasetManifest | dataset_id、版本、schema_version、hash、行数、源/包版本、范围、证券池版本、日历版本、修订策略、质量摘要 | 同一 manifest 可重放；外部源修订不静默覆盖 |
| Observation | symbol、域、event_time、available_at、received_at、revision、单位/币种、source、quality | 源时间/可用时间/收到时间分离；未知不填现在 |
| FeatureDefinition | 公式/代码 hash、依赖字段、lookback、预测 horizon、当时可用约束、输出单位 | 禁止未来填充；新闻/财报按公开时刻落入特征 |
| ResearchRun | 问题、数据/环境/模型版本、seed、预算、train/valid/test、状态、取消、实验总数、产物 | 每个结论能回到输入与实际运行日志 |
| CandidateProposal | 基线/候选、样本外与压力结果、限制、反例、审批者、策略版本 | 未通过/缺证据不能晋级，只显示待验证 |

复权因子应留原始价格与版本；因子计算使用决策当时可见的复权信息，执行使用未复权价格。A 股交易日、午休、停复牌、ST/板块规则、整手、T+1、费用和成交量约束由共享规则/撮合负责；不能依赖 pandas 默认工作日或全球市场模板。具体费率和规则按生效日期版本化，上线前再核验交易所/券商规则。

## 7. 建议排期与 UI 可见产物

| 批次 | 范围 | 用户在既有界面中看到什么 | 完成门槛 |
| --- | --- | --- | --- |
| R0 | 数据时态/版本、覆盖与缺口清单、重放基础 | 监控节点显示源时间/收到时间/延迟/覆盖；研究卡能打开数据版本 | 财报/宏观可用时间未知不进入历史训练；退市与缺数可定位 |
| R1 | OpenBB 一个宏观域 POC | 原监控画布新增域能力与数据说明；盯盘解释可展示外围背景来源 | 与当前 A 股采集隔离、可关闭、限频/失败正确 |
| R2 | vectorbt 可选批量筛选 | 研究工作区显示参数稳定区、耗时和 Go 复核差异 | 许可明确、可复现、实际性能有收益，否则不接 |
| R3 | RD-Agent 限额离线研究 | 监控显示研究队列/算力/预算/进度；提案卡显示因子假设和反例 | 取消/超预算有效、封存测试、全实验留痕、人工审查 |
| R4 | 已批准候选影子与 SIM | 盯盘显示当前生产与影子版本差异、预测区间/失效条件/证据 | 预测校准、成本与市场阶段稳定性、账户隔离完成 |

UI 的实时运行状态来自实际遥测与任务记录；研究进度没有精确工作量时显示阶段与已完成数，不造百分比。霓虹连线表示真实观测到的数据/事件，有证据才能亮；OpenBB 每日宏观采集不会因为画布动画变成实时行情。盯盘的买点输出应是“条件、区间、有效期、概率校准、失效点、数据质量与不可执行原因”，不能把模型评分伪装成确定收益或正式委托许可。
