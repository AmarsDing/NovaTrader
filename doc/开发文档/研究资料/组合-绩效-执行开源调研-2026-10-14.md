# 组合优化、绩效分析与执行引擎调研

> 调研日期：2026-10-14。仅使用项目官方仓库、官方文档及维护者发布的包元数据。本次交付为未来实施建议，未安装新框架、未连接真实账户。下文接口和指标阈值均为建议合同，不代表现有接口已经实现。

## 1. 结论与接入顺序

| 项目 | 本项目定位 | 建议顺序 | 不应承担的职责 |
|---|---|---|---|
| QuantStats | 已有 Go 回测/SIM/LIVE 权益的独立绩效审计及报告 | 第一优先，先统一净值口径 | 撮合、交易费用计算、订单风控、真实交易 |
| PyPortfolioOpt | Python 研究 worker 中的组合目标权重生成器 | 第二优先，先做影子建议 | 直接买卖、预测精确买点、绕过 A 股交易约束 |
| QuantConnect LEAN | 离线事件回测的对照引擎、未来多资产实验 | 后置可选 POC | 直接替换当前 Go 主账本或东方财富文件单通道 |

这三项可以补强现有系统，但不能证明某策略会盈利。工程上的主线仍为：研究结果 → 冻结版本的策略提案 → 本项目 Go 回测与规则验证 → SIM 影子/自动验证 → 准入 → 受限半自动 LIVE。大模型和研究库不持有交易权限。

## 2. 当前项目可衔接的位置

| 已有代码/设计 | 本次发现 | 方案含义 |
|---|---|---|
| `backend/pkg/backtest/metrics.go` | 已有费用后权益点、总收益、年化、最大回撤、Sharpe、回合统计和可重现报告 | QuantStats 导入同一权益序列，作交叉核验和丰富展示；不要重新写一个权益账本 |
| `backend/app/backtest/internal/biz/task.go` | 已有排队任务、参数/数据哈希、引擎版本、随机种子、重跑 | 外部研究运行使用同一任务身份及产物指纹 |
| `backend/app/strategy/internal/biz/performance.go` | 目前按后验信号收益累加得到信号样本回撤，统计对象是信号样本 | 面板必须区分“信号样本表现”和“资金账户净值”；不能将它交给 QuantStats 冒充账户 NAV |
| `backend/pkg/brokerif/sim`、`backend/pkg/ashare` | 共有模拟撮合、费用、板块交易规则 | 批量研究仍需经此基准复测；组合权重落股数时复用规则元数据 |
| `backend/app/trade/internal/biz/types.go` | 委托与成交包含信号、策略版本、账本身份 | 组合计划继续携带这些身份，不建立与原委托脱节的第二套订单 |
| M09 与 `CLAUDE.md` | 通达信行情、Windows `broker-gw` 读写东方财富量化终端 CSV 文件单；Go/PostgreSQL 为订单真值 | LEAN 券商连接器的存在不等于当前东财通道可用 |

本项目 `pyworker` 的既定职责是采集，不宜把耗时优化塞进采集请求。新增研究/报告 worker 应独立进程、隔离依赖和 CPU/内存限额，由 Go 的任务层提交，状态和产物通过 data 仓储写 PostgreSQL/ent；Python 不自行创建业务库。监控画布加入“组合优化”“绩效核验”“研究对照”节点，沿用现有画布，不重建一套前端。

## 3. PyPortfolioOpt

### 3.1 官方事实与版本边界

正确仓库为 [PyPortfolio/PyPortfolioOpt](https://github.com/PyPortfolio/PyPortfolioOpt)，采用 [MIT 许可证](https://github.com/PyPortfolio/PyPortfolioOpt/blob/main/LICENSE)。支持均值方差、协方差收缩、Black-Litterman、HRP 等方法。[官方项目说明](https://github.com/PyPortfolio/PyPortfolioOpt)

本次检查的维护者包发布为 **1.6.0**，PyPI 标示发布于 2026-02-26；main 元数据要求 Python `>=3.10,<3.15`。在线文档标题仍显示 **1.5.4**，不能仅凭“latest”文档推定 API 与已选版本一致。[维护者发布页](https://pypi.org/project/pyportfolioopt/)、[main 元数据](https://github.com/PyPortfolio/PyPortfolioOpt/blob/main/pyproject.toml)、[在线文档](https://pyportfolioopt.readthedocs.io/en/latest/OtherOptimizers.html)

实施时固定库版本、依赖锁、求解器名称/版本、环境镜像摘要和运行提交 SHA。1.6.0 的离散分配源码仍可能根据可选依赖选择 ECOS_BB，并提示未来版本行为变更；不要依赖隐式默认求解器。solver 的许可和部署条件另记依赖清单。[离散分配源码](https://github.com/PyPortfolio/PyPortfolioOpt/blob/main/pypfopt/discrete_allocation.py)

### 3.2 值得复用的能力

- 候选股票已经由本项目研究/规则生成后，结合协方差收缩、持仓集中度和行业约束，给出组合权重候选。
- 以最小波动、HRP、等权作基线，逐步再加入收益预测。历史均值和 AI 置信分并不等于可靠预期收益。
- Black-Litterman 的研究输入是带收益期限和不确定性的观点；JEV/其他模型若以后产生预测，应先完成期限对齐与概率校准，再作为一个可评估观点来源，不能把“80 分”直接写成“80% 预期收益”。

HRP 通过相关距离、聚类和层次分配生成权重，**不能将 HRP 自动等同于一般等风险贡献/ERC 风险平价**。它的 API 与凸优化约束机制不同，不能假定给 HRP 调同一组行业/换手限制就已生效。若业务需要 ERC，应另立算法合同、验证每资产风险贡献。[HRP 官方说明](https://pyportfolioopt.readthedocs.io/en/latest/OtherOptimizers.html)

`DiscreteAllocation` 提供整数股数分配，但通用“整数股”并不包含本项目交易品种的最小买入数量、数量步长、零股卖出、T+1 可卖、挂单冻结、交易费用、停牌、涨跌停及流动性约束；这些由 NovaTrader 的规则元数据与最终风控负责。不能把它返回的股数直接转 CSV。[离散分配官方说明](https://pyportfolioopt.readthedocs.io/en/latest/Postprocessing.html)

### 3.3 建议合同

`PortfolioOptimizationRequest`：

| 字段组 | 必须包含 |
|---|---|
| 身份 | `run_id, trace_id, strategy_version_id, model_version_id?, book, account_id, requested_by` |
| 时点与数据 | `as_of, price_snapshot_id, data_hash, universe_version, corporate_action_policy, currency=CNY, timezone=Asia/Shanghai` |
| 历史矩阵 | 仅 `known_at <= as_of` 的收益矩阵、交易日历、缺失/停牌标记、协方差窗口与频率 |
| 账户 | 权益、可用现金、当前/冻结/可卖持仓、活动委托、账户状态版本 |
| 约束 | 单股/行业上限、总风险预算、现金下限、换手/成交量上限、禁买名单、持仓锁定 |
| 求解 | 算法、预期收益模型、目标期限、求解器、超时、随机种子、fallback 政策 |

`PortfolioPlan`：目标权重、现金权重、风险贡献、相关性/行业暴露、建议增减仓、预计费用与换手、约束检查、`solver_status`、数据覆盖、理由、有效期、输入版本及产物哈希。每项约束标明“求解已处理/后置已验证/未支持”。

落地分两层：Python 生成连续目标；Go 生成遵循板块规则的股数和拆单建议，并再次验算资金/费用/组合暴露。HRP 后简单截断再归一化可能破坏上限，禁止用这种方式冒充可行解。无法满足约束时明确 `INFEASIBLE`，沿用已批准仓位或现金策略；不会因求解失败自动放松风控。此阶段输出为建议计划，执行还必须重新核验账户/行情版本并过最终风控。

### 3.4 POC 验收

1. 同一数据/约束/版本运行结果在明示容差内一致，权重有限非负，资产权重与现金权重之和为 1。
2. 人工构造高相关、零波动、缺历史、协方差奇异、不可行行业限额、T+1 冻结、资金不足案例；任何失败均有原因且不会产生委托。
3. 对等权、当前规则仓位、最小波动、HRP 做相同时间切分的样本外比较，统一费用/滑点，不以样本内最高 Sharpe 作为上线依据。
4. 整手化/费用预留后仍满足资金、暴露和可卖约束；展示权重目标与可执行结果的偏差。
5. 上限示例可先定为 100 个候选、250 个日收益点、单任务 30 秒超时；实测 P50/P95/内存后调整，不把该建议当作库的性能保证。

## 4. QuantStats

### 4.1 官方事实与版本边界

正确仓库为 [ranaroussi/quantstats](https://github.com/ranaroussi/quantstats)，采用 [Apache-2.0](https://github.com/ranaroussi/quantstats/blob/main/LICENSE.txt)。本次核验发布页和 `version.py` 均标示 **0.0.86**。近期发布修订了统计及报告行为，因此必须锁版本并保存 golden 数据；不能自动升级后继续声称口径一致。[发布记录](https://github.com/ranaroussi/quantstats/releases)、[版本源文件](https://github.com/ranaroussi/quantstats/blob/main/quantstats/version.py)

main 元数据要求 Python >=3.10、pandas >=2.0.0，而 README 仍出现 pandas >=1.5.0；部署取锁定发布包元数据及实际测试结果。库可接受本地 `Series`，无需使用它的 Yahoo 下载快捷方式。[依赖元数据](https://github.com/ranaroussi/quantstats/blob/main/pyproject.toml)

### 4.2 必须先统一的口径

| 问题 | NovaTrader 合同 |
|---|---|
| 收益输入 | 小数收益 `0.01=1%`；由已核对的费用后账户 NAV 导出，不输入价格、百分数 1 或单笔交易收益冒充日收益 |
| 出入金 | 单独保留外部现金流与时点，先按已定义 TWR 分段/单位净值方法消除出入金影响；时间未知则报告不可比较，不机械套用一个公式 |
| 费用 | 撮合/真实成交账本先计佣金、税费、滑点/冲击；报告只消费费用后净值，避免双扣。毛/净收益各自标识 |
| 日历频率 | 先用上海交易日收盘净值与显式 `periods_per_year=252`，注明年化假设；分钟研究先复合到交易日，不按 252 年化分钟收益 |
| 无交易与缺数 | 无交易但估值完整的交易日可以为 0；采集失败、缺估值和账户对账失败不能填 0；报告显示覆盖率与缺口 |
| 基准 | 使用本项目同日历、同币种、同起止日的显式基准收益 Series，不传 ticker 字符串触发外部下载；明确价格指数或含分红总回报指数 |
| 风险利率 | 保存年化 RF、换算方法和频率；第一轮 RF=0 与现有 Go 口径对照。非零 RF 要单独核对日率换算差异 |
| 信号/成交/账户 | 信号命中率、成交回合胜率、盈利日占比分开显示；不能都称“胜率” |

QuantStats 的 Sharpe API 带频率/RF 参数，HTML 报告接受日收益、基准和 `periods_per_year`；部分胜率/连续盈亏等统计是收益周期级，而非逐笔交易级。报告默认日期匹配也可能截掉起始零收益区间，应在项目端先对齐日期，显式设置并验证起止日。[统计实现](https://github.com/ranaroussi/quantstats/blob/main/quantstats/stats.py)、[报告实现](https://github.com/ranaroussi/quantstats/blob/main/quantstats/reports.py)

### 4.3 接入与验收

新增 `PerformanceReportRequest`，携带 `task_id/book/account/strategy_version/data_hash/ledger_hash/calendar_version/fee_policy/benchmark_id/rf/periods_per_year/start/end`，以及已验证的 NAV、收益、现金流、交易回合。Go 生成输入，Python 仅分析，返回结构化指标 JSON + 自包含 HTML 产物 + 警告/版本清单。界面原有绩效面板消费 JSON；HTML 作为可导出研究附件，不把整张网页嵌入实时盯盘主屏。

POC 以同一费用后序列核验累计收益、回撤、日频 Sharpe、年化、月度复合收益：示例容差为累计收益/回撤 `1e-8`、相同定义下 Sharpe `1e-6`。出现差异先解释初始权益点、回撤符号、样本标准差、RF、年化天数，再调整适配层；禁止为“通过”改成交账本。另验出入金不制造收益、NaN 不制造平盘、基准缺数不静默补齐、零收益/短样本指标明确不可估计。

监控节点展示待处理报告数、输入净值覆盖、费用/基准口径、最后成功/失败、耗时、版本和产物链接。盯盘摘要展示“费用后收益/最大回撤/样本外区间/与基准差额”，不要用单一 Sharpe 或单期漂亮报告代替准入判断。

## 5. QuantConnect LEAN

### 5.1 官方事实与版本边界

正确仓库为 [QuantConnect/Lean](https://github.com/QuantConnect/Lean)，核心引擎采用 [Apache-2.0](https://github.com/QuantConnect/Lean/blob/master/LICENSE)，支持 C#/Python 算法、回测与实盘。当前 master 的 Launcher 项目目标为 **net10.0**，公共程序集版本标记 **2.5**；这些不是一个可直接用于生产复现的完整发布身份，POC 应固定提交 SHA/容器摘要和运行时。[Launcher](https://github.com/QuantConnect/Lean/blob/master/Launcher/QuantConnect.Lean.Launcher.csproj)、[程序集版本](https://github.com/QuantConnect/Lean/blob/master/Common/Properties/SharedAssemblyInfo.cs)

代码许可证不包含市场数据/云服务授权；数据集需按其专属许可使用。[QuantConnect 数据许可说明](https://www.quantconnect.com/docs/v2/cloud-platform/datasets/licensing)

官方当前券商清单包含 IB、Alpaca 等，但本次核验未列出 **东方财富量化终端 CSV 文件单**。已有券商支持不能被描述成已支持本项目 A 股实盘。自定义经纪适配须实现资金、持仓、活动委托、下单/撤单与事件回报等合同，而非仅导出一个 CSV。[官方券商列表](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages)、[IBrokerage 接口](https://github.com/QuantConnect/Lean/blob/master/Common/Interfaces/IBrokerage.cs)

LEAN 有可替换的成交、滑点、手续费、购买力和结算模型；默认模型依赖其市场假设，A 股涨跌停排队、停牌、板块交易数量、T+1、复权和税费仍需单独验证。[Reality Modeling](https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/key-concepts)

### 5.2 推荐方案与第二账本代价

推荐先做**隔离离线对照**：冻结同一份行情/交易日历/公司行动、相同规则及费用参数，把确定性参考策略同时送入现有 Go 回测和 LEAN，逐事件比较权益、现金、可卖数量及成交差异。只返回研究报告，不接 `broker-gw`，不保存真实账户凭据。

直接让 LEAN 管理实盘会引入 C#/.NET 运行时、Python 桥接、独立 Portfolio/Cashbook/TransactionManager 状态与 Go 交易状态机的双重归属。下单重试、撤单竞态、部分成交、断线重放、T+1、对账差额和 Kill Switch 都需要明确唯一权威，否则两个引擎可能各自认为“尚未下单/尚有可卖”。这是基于现有架构的工程判断，不是 LEAN 项目缺陷。

将来若确需 LEAN 参与在线研究，应只向 Go 提交 `StrategyIntent`（含信号、数据快照、有效期、策略版本），由 Go 的唯一订单入口决定价格/股数、最终风控、幂等和提交。不得让 LEAN 与 Go 同时持有同账户的执行权。若希望改为 LEAN 单一主执行引擎，那是另一个架构迁移项目，需要用户明确改变现有东财/Go 主线后再设计。

官方经纪插件模板也要求符号映射、订单事件、撤单、账户读取、断线重订阅和长期测试，可以借鉴其合同清单完善本项目 `broker-gw`，无需为此把 LEAN 装进主执行链。[官方 Brokerage Template](https://github.com/QuantConnect/Lean.Brokerages.Template)

### 5.3 可选 POC 与退出条件

| 项目 | 验收要求 |
|---|---|
| 输入 | 固定的一组含缺失/停牌、涨跌停、除权、部分成交、收盘作废、T+1 的离线夹具；来源和授权明确 |
| 时间 | 统一上海时区、分钟 K 起止约定、信号可见时间、下一可交易时刻；截断/未来扰动不改变切点前决策 |
| 财务 | 逐事件比对现金、持仓、可卖、费用与权益；未解释差异不取平均，不以最终收益接近代替账本相同 |
| 成本 | 记录新适配代码量、依赖、安全补丁负担、内存/启动/运行时间和可复现环境 |
| 成功 | 能发现本项目引擎遗漏，并有可重复差异报告；若收益仅是多一张报告，不升为必选依赖 |
| 退出 | A 股规则无法合理对齐、两套策略实现长期漂移、维护成本超过价值时，保留研究记录，停止主线接入 |

## 6. 可交给 AI 的三个小批次

1. **绩效合同先行**：补费用后 NAV/现金流导出与口径文档 → 冻结 golden 数据 → QuantStats 离线 worker → Go 指标核验 → 原绩效面板添加“口径/覆盖/版本/报告”。不得触碰交易权限。
2. **组合影子建议**：定义 `PortfolioPlan` proto/ent 记录 → 独立优化 worker → 等权/最小波动/HRP 基线 → Go 交易约束与最终权重验证 → 只读建议卡和风险暴露图 → 样本外/SIM 证据。未经准入不自动转委托。
3. **LEAN 对照实验**：单独 ADR 明确实验预算和非主线定位 → 数据/规则夹具 → 固定镜像和 SHA → 逐事件差异产物 → 决定保留/退出。当前执行引擎继续独占真实订单生命周期。

每批次都交付输入合同、失败行为、重现产物、针对性测试、监控字段和实际截图；文档状态必须区分“设计/POC/已实现/已联调/已准入”。
