# Jev 与 Longbridge Pro 官方调研

核验日期：2026-10-14。用户已明确“jev”指 **JEV 模型**；本次将其定位为 TypeSafe AI 的 Jev。下文将上游事实与 NovaTrader 的建议分开。本次没有调用付费模型、上传账户数据或启用交易。

## 1. Jev 的实际能力

Jev 是面向结构化判断的 System One 模型，接受文本、JSON 和文本数组，返回受限答案与概率；目前不直接接受图像、音频或视频，也不生成长文解释或代码。原语为 Choice（固定选项）、Score（等级量表）、Noul（命题为真的概率）。校准描述群体统计性质，不能保证某一答案正确。[官方能力与边界](https://docs.typesafe.ai/concepts/system-one)

官方接入为 `POST https://api.typesafe.ai/v1/systemone`，请求指定 `state/questions/model`。响应含实际 model、answers 和 token 用量；Choice 概率对应所定义的选项，Score 对应所定义的等级。它们不是天然的证券收益概率。[API 合同](https://docs.typesafe.ai/api)

当前官方模型页列出 `jev-1.13.0`，`jev-latest` 是可移动别名；应固定版本，并在升级后重验阈值。官方说明英文表现最好，其他语言需要本域验证。页面展示托管调用；本次没有核实到可下载、自托管的开放权重与相应许可，因此不能把 SDK 的自定义 base URL 当作 DGX 本地部署证明。[模型与版本说明](https://docs.typesafe.ai/models)

2026-09-29 的评测论文研究分类、路由、自然语言推理等任务，指出不同标签与阈值下存在差异。该论文没有验证 A 股收益预测、择时或实盘盈利。把这些结果迁移为金融判断能力属于待检验假设。[研究论文](https://arxiv.org/abs/2609.37647)

## 2. 在 NovaTrader 中的接法——建议，尚未实现

推荐作为 M03/M05 的可选 `FastJudge` 适配器，与现有本地 LLM 并存；默认关闭，先离线标注验证，再在线影子运行。

```text
已授权公开情报 + 时点有效的市场事实
    → 去重/时间/来源/正文清洗（确定性处理）
    → Jev 原子问题：相关性 / 否定与传闻 / 证据是否支持结论 / 研究任务路由
    → 类型、范围、问题完整性、有效期检查
    ├─ 足够可信：形成分类标签或任务优先级
    ├─ 模糊/冲突：交现有本地 LLM 深入研判
    └─ 超时/无效/断网：弃权，使用规则或显示待研判

规则价格/股数 → 固定意图/订单ID → 必要授权确认 → 提交前最终风控 → 同ID订单：独立快链路，不等待 Jev
```

首批问题限定为事实判断，不问“明天一定涨吗”。例如：

| 问题 | 类型 | 下游用途 |
|---|---|---|
| 正文是否明确涉及目标公司，而非同名主体？ | Noul | 关联候选标签，低可信交复核 |
| 这是一项已生效事实、拟议计划、传闻、否认，还是无关内容？ | Choice | 情报去噪与时间线分层 |
| 输入事实是否支持所给摘要中的主张？ | Noul | 摘要质量检查，不能凭此创造证据 |
| 应进入公告风险、行业研究、普通新闻还是人工复核队列？ | Choice | 任务分流，风险规则仍直接处理结构化事实 |
| 对预定义事件严重程度量表处于哪一级？ | Score | 告警候选排序，不能直接改变交易限额 |

建立 `FastJudgeRequestV1`：`request_id/input_snapshot_id/input_hash/cutoff_at/valid_until/question_set_version/model_version/deadline_ms/data_policy`。响应保存 `answers/actual_model/question_ids/received_at/duration_ms/usage/cache_status/provider_request_id/abstain_reason`。每个判断关联真实情报 ID，不能把模型概率作为事实来源。

请求只包含该任务必要的公开新闻/市场事实。托管调用的数据路径、保留条款和地域可达性在接入时核验；默认不发送账户身份、资金持仓、凭据和私有研报。API key 仅服务端保管；未来如扩展敏感数据用途，使用独立配置与审计。

Python SDK 提供异步客户端、连接复用与重试配置；DEBUG 会记录未脱敏的请求/响应正文，未知答案类型可能被跳过。接入时关闭正文 DEBUG，校验预期问题 ID/数量/类型，并用统一截止时间限制重试，避免过期判断继续进入决策。[SDK 使用与日志行为](https://docs.typesafe.ai/sdk/python/usage)

相同输入的独立问题可批量提交；官方 cookbook 的速度与费用数字是其示例结果，不能直接当作本机收益。缓存键包含输入 hash、问题版本与模型版本；变化中的市场事实必须重新判定。[批量问题示例](https://docs.typesafe.ai/cookbooks/parallel_questions)

## 3. Jev POC 的验收与退出

以下为本项目拟议实验，未执行：

1. 冻结至少 500 条中文 A 股公告/新闻，覆盖否认、同名、过期、传闻、多公司和缺正文；记录标注准则和争议复核，按时间分训练阈值集/封存测试集。
2. 与确定性关键词/实体规则和现有本地模型比较：相关性 precision/recall、macro-F1、Brier/ECE、弃权覆盖率、误报/漏报类型。阈值只在开发集调，报告可信区间和每类样本数。
3. 单独测连接、排队、请求 P50/P95/P99、超时率、429/529、输入长度、费用；再测从新闻接收到有效标签的端到端时间。厂商“更快”演示不是当前系统 SLA。
4. 在线影子至少覆盖不同市场时段；不改变现有选股/风控结果，记录如果使用它会有何差异。收益相关假设另建前瞻验证，不用后见行情解释历史正确。
5. 停用条件：效果不优于更简单基线、中文关键事件漏判、费用失控、网络时效不稳定、模型版本不可固定或数据处理条件不满足。停用后规则/本地模型继续工作。

## 4. Longbridge Pro 值得借鉴的部分

官方组件指南描述组件工具箱、缩放/脱离/固定、联动组，以及自适应和画布布局。可借鉴“一个上下文驱动多组件”，减少用户重复输入；保留 NovaTrader 已有 dockview 与独立监控画布。[组件与布局官方指南](https://longbridge.com/sg/en/support/topics/longbridgepro/guide)

官方 0.19 发布说明包括筛选、量化工作台、回测和布局改进。适合借鉴筛选条件可保存、分布与结果相邻、图表与实验产物联动；功能存在不等于本项目已有适配。[官方发布说明](https://longbridge.com/en/changelog/longbridge-pro/0.19)

当前桌面介绍展示 AI 分析侧栏、过程摘要，以及图表上的委托/止盈止损交互。可借鉴“先结论再依据”和在价格图中表达计划；在 NovaTrader 中拖线只生成计划草稿，松手后重算风险和要求适用授权，不能把视觉动作当作券商成交。[官方桌面介绍](https://longbridge.com/desktop)

## 5. 转成 NovaTrader 的设计决策——本项目建议

- **监控**：原画布保持。节点展开“运行/数据/输入输出/配置/历史”，连线展开“合同/真实流量/时序/样例/异常”。顶部回答当前是否可盯盘、是否可交易、最急需处理什么；底部显示真实事件与处理结果。
- **盯盘**：原票式工作台保持。市场/板块/股票/新闻/计划/订单采用可锁定的联动组；账户与下单上下文不得因点图表而静默变更。
- **信息顺序**：一句白话动作 → 触发/失效/有效期 → 风险与账户限制 → 图表与关键反证 → 完整事实。把“等待条件”“资料不足”“风控禁止”“已成交”显式分开。
- **科技感**：深海底色延续，增加分层毛玻璃、冰青/电蓝霓虹边缘和真实事件路径高亮；密集数据有稳定背板，数字不做模糊或投影。新视觉合同取代先前仅三处可用玻璃的限制，见主方案及视觉规范第七节。
- **减负**：默认展示最有行动价值的少数项，其余折叠可查；异常聚合成根因/影响/建议动作，避免数十个重复红灯。空行情、无消息和未接入分别展示。

本地五段视频的采样证据独立记录在[视频界面研究](本地视频界面研究-2026-10-14.md)；不把网站宣传图或一段概念动画当作已有可运行功能。
