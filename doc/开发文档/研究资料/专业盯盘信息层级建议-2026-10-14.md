# 专业盯盘信息层级与联动设计建议

> 日期：2026-10-14。本文为只读设计审阅及未来实施合同，不代表新增功能已实现。保留现有监控画布 + HUD + 终端带，以及 dockview 工作台与“一张票”的主体设计。代码依据包括 `MonitorView.vue`、`OverviewView.vue`、`decision-desk.ts`、`TradeView.vue`、账户/交易类型与 M07/M09 设计。

## 1. 首屏应先回答的三件事

1. **系统现在能否可靠工作**：行情/情报/推理/风控/交易链路是否有阻断，关键数据新鲜程度和观测缺口是什么。
2. **我的资金现在暴露在哪里**：账户、模式、已用风险预算、可卖/不可卖持仓、活动/未知委托，哪些需要关注。
3. **我下一步需要做什么**：等待、看一条证据、调整一个设置、确认一个计划、处理一个异常。每次只突出当前最重要的行动。

海量信息留在系统内持续处理，首屏输出“结论 + 主要依据 + 主要反证 + 当前限制”。信息完整通过逐层展开获得，不靠把所有表格同时铺满屏幕。

## 2. 监控面板：固定拓扑上的运行解释

| 原有区块 | 建议深化 | 正确口径 |
|---|---|---|
| HUD | 运行模式/授权、行情覆盖与年龄、关键阻断、端到端延迟、当前待处理任务 | 连接正常不等于行情新鲜；未知延迟不能显示 0ms；健康分同时显示观测覆盖 |
| 接入→研判→裁决画布 | 保留节点位置，叠加当前业务运行阶段和真实可追踪流量 | 活动画面不等于成功；一条连线的速率注明单位/窗口/观测范围 |
| 节点详情 | 概览、输入、输出、质量、历史、配置；概览先给影响和最小恢复动作 | 配置保存/版本加载/当前运行生效分别显示 |
| 连线详情 | 生产者→消费者、事件主题/合同版本、吞吐/积压/错误/延迟、近一条样本与 trace | 缺少积压/P95/逐条关联时写“未采集”，不从视觉动画估计 |
| 终端带 | 按一件事故聚合同因事件，展示开始、影响扩散、处理、恢复与复验 | 原始日志仍可展开；恢复必须有新的成功证据 |

HUD 固定优先级：急停/执行不确定 → 关键数据或风控阻断 → 降级/延迟 → 正常运行摘要。不能用一张“总分 90”遮住交易链路已断。

每个节点应回答“正在做什么 / 当前处理哪个对象 / 谁依赖它 / 最近成功产物 / 失败影响 / 下次动作”。例如研究节点不是只显示 CPU，而是显示“任务 R-xx 正在做样本外验证，已完成 6/10 个窗口；结果尚未准入”。进度必须来自任务记录。

点击异常后保留画布全局位置，侧边展开一条影响链：源数据过旧 → 特征未更新 → 信号被阻断 → 没有新委托。业务影响先于技术栈细节；端口、堆栈和重试日志放“技术详情”。

查看历史时整屏显著显示“回看 · 日期时间”，停止与实时健康/交易动作混用。回到实时恢复最新权威状态，而不是播放完历史后认为当前也已恢复。

## 3. 盯盘工作台：保留一张票，按决策层级增厚

### 3.1 六层联动

| 层级 | 默认一句话 | 可展开的专业证据 | 联动目标 |
|---|---|---|---|
| 市场 | 当前环境支持何种风险预算、主要变化 | 涨跌广度、量能、涨跌停/炸板、指数/行业分歧、数据覆盖 | 点击变化定位相关板块和候选集合 |
| 板块 | 热度来自价格、资金还是消息，是否持续 | 成员覆盖、领涨/拖累、扩散速度、相对强弱、情报来源 | 筛股票，保留板块条件与时间 |
| 股票 | 为什么进入候选，最重要的反证是什么 | 走势/量价、资金、消息、同板块对照、四维异议、关键数据年龄 | 更新一张票和行情，不直接写交易表单 |
| 计划 | 当前应等待/观察/准备确认/失效，以及触发条件 | 入场区间、确认条件、时间窗、失效线、目标/止损、仓位理由、预测证据 | 明确选择计划后生成带身份的草稿 |
| 订单 | 条件未触发、待确认、已提交、部分成交、撤单中、未知分别可见 | 事件流水、实际成交均价、费用、剩余量、真实通道回报 | 定位原计划与账户风险，不将“提交”写成“已买入” |
| 账户风险 | 当前可用预算、不可卖风险、未知订单占用 | 行业/相关性暴露、挂单冻结、可卖量、组合压力情景、对账状态 | 返回最应处理的计划/订单/持仓 |

板块热点与股票推荐是两个集合。热度高但不符合交易条件时应显示“活跃但未选入”，而不是自动加上推荐标记。推荐列表保留“为什么推荐”和“为什么被淘汰”，帮助用户少做重复搜索。

### 3.2 一张票的正文顺序

1. **身份条**：股票名称/代码、账户 SIM/LIVE、策略版本、计划有效期、数据时点。模式与账户常驻，不能只藏在设置。
2. **行动句**：例如“等待价格进入计划区间，并满足成交量条件”；“停止开仓：行情已过期”；“计划已失效”；“持仓中，今日可卖 0 股”。这些是文案模板，显示前须由实际规则/账户证据支持。
3. **条件尺**：现价位置、入场区间、失效/止损/目标线；明确计划价与实际委托/成交价。K 线周期与价格时间不可省略。
4. **理由与反证**：默认各最多 3 条，按影响排序；每条可点来源、时点、规则/模型版本，不二次调用大模型现场编理由。
5. **仓位与风险**：建议权重、当前权重、预计新增费用、预算占用、可卖限制；“允许”必须来自最终风控，不由票面估计替代。
6. **过程**：产生→复核→条件等待→授权→委托→成交→保护→退出，显示当前停在哪一步及阻断原因。
7. **深层证据**：技术图、消息原文、四维得分、特征、预测评价、逐事件追踪、研究报告。逐层展开，返回时保留选择和滚动位置。

首屏最多一个主按钮，其名称与状态对应：查看阻断、查看依据、准备模拟确认、核对原委托等。全自动模式的启用属于独立准入流程，不是把“确认”按钮改成“自动”。

## 4. 联动 context：选择与执行分开管理

建议建立可版本化的 `WorkbenchContext`，而非各面板只传一个股票字符串：

| 字段组 | 建议内容 |
|---|---|
| 焦点 | `market, sector_id?, symbol?, signal_id?, plan_id?, order_id?` |
| 账户 | `book, account_id, authorization_level` |
| 数据 | `as_of, source_time?, received_at, snapshot_id, data_version, observation_mode=live/replay` |
| 因果 | `trace_id?, strategy_version_id?, model_version_id?, originating_panel, context_revision` |
| 联动范围 | `link_group_id, pinned, follow_selection` |

上述新增字段先作为未来合同定义；当前没有 `plan_id`/快照版本的路径不得随意拼字符串冒充真实标识。

- 市场→板块→股票默认单向下钻；详情反向选择只有用户明确操作才改变全局焦点，避免联动环造成跳屏。
- dockview 支持“跟随当前选择”和“固定此票”，固定面板头显示固定对象与账户。不同账户的面板使用不同联动组。
- 用户正在编辑委托时，其他面板切换股票不会静默改写委托。先完成/丢弃当前草稿，或点击明确的“带入此计划”。
- 执行草稿冻结订单身份、账户、股票、方向、信号/版本及有效期；跨账户切换后重新加载账户、活动委托与风控，不沿用旧允许结论。
- 慢请求返回时比对 `context_revision`/账户/股票；旧响应不能覆盖新选择。事件按服务端对象版本归并，补偿查询后恢复权威状态。
- 回看模式不提供真实执行入口；历史图拖动也不能修改当前有效计划。图上拖线先生成“拟修改”，经重新校验后才成为新版本。

Longbridge 官方手册提供组件联动组、组件分离/固定、自定义布局和布局管理等能力，可借鉴“同一对象跨组件持续工作”的交互。其官网还展示图表与交易联动。这里借鉴交互，不复刻品牌，也不据此推定 NovaTrader 已有同等执行能力。[官方 Pro 指南](https://longbridge.com/sg/en/support/topics/longbridgepro/guide)、[官方桌面产品页](https://longbridge.com/desktop)

## 5. 结论必须标明证据类型

| 类型 | 例子 | 视觉与文案 |
|---|---|---|
| 已观测事实 | 价格、成交回报、账户可卖量 | 正常高对比文字，带来源时间；必要时可核对原始记录 |
| 规则计算 | 入场区间、建议股数、触发/失效条件 | 标“规则”，可展开参数和版本 |
| 模型估计 | 未来收益分布、方向概率、情报归纳 | 标“估计”，带预测期限、更新时间、模型版本和评价范围 |
| 可执行许可 | 当前账户最终风控通过并在授权范围内 | 明确授权边界、有效期与核验时点；不使用 AI 高分替代 |
| 未知/未采集 | 缺行情、无校准、未收到回报 | 明文“未知/未采集/待核对”，不用 0、空白或正常绿点冒充 |

“四维综合分 85”只代表评分口径；没有校准证据时不能显示“上涨概率 85%”。“链路在线”只代表连接/心跳证据，不能写成“系统全部正常”。

不要在模型结论中用“必涨、精准买点、一定成交”。用户需要的是条件化、可核查、可取消的行动计划。

## 6. 预测如何变成可读的买卖计划

预测显示至少包含：目标（如未来 N 个交易日收益/达到阈值）、起点与截止时间、数据版本、概率或分位区间、失效规则、样本外评价区间、样本数量/覆盖和校准状态。

- 价格走势图上历史为实线，预测为虚线及概率带，预测起点固定在产生时刻；后来价格不能回填改变旧预测。
- 未校准输出显示“模型排序/估计区间”，不显示精确概率。少样本、分布漂移或特征缺失时给出不足原因并降低行动权限。
- “预测买入点”改为“在此时间窗内，满足这些条件才考虑进入此价格区间”。可显示条件满足 2/4，但 2/4 不是 50% 成功率。
- 对比至少保留“保持现金/当前规则基线”和当前模型，不只展示最佳结果；费用前后、样本内/外分开。
- “预计损失”只是按情景/止损价计算，明确是否含费用/跳空情景；止损线不构成保证成交价。

这部分属于未来能力，当前 `decision-desk.ts` 的综合分、四维异议和规则入场区间只能支撑已有解释，不能冒充已经有概率预测模型。

## 7. 保护状态应比一条止损线更明确

| 实际状态 | 票面必须表达 | 后续动作的边界 |
|---|---|---|
| 今日买入暂不可卖 | 触发退出条件，但可卖量 0；最早可卖时间以规则/日历/账户确认为准 | 记录待处理保护，不能显示“已止损” |
| 停牌或无有效报价 | 保护规则已启用，但此时无法核验/提交/成交的具体原因 | 保留风险暴露、等待有效数据/复牌，不虚构成交 |
| 跌停/流动性不足 | 已触发/已报单，剩余 X 股尚未成交 | 持续追踪真实回报，预计损失不当作固定最大损失 |
| 撤单中 | 原单剩余量仍可能成交 | 确认撤销后才按政策考虑下一单，避免重复卖出 |
| 部分成交 | 已成交/剩余/可卖/冻结各有数量 | 按剩余风险更新保护，不能整票标为已退出 |
| 回报未知 | 原委托结果待核对，冻结新的冲突动作 | 查询原订单身份并对账，不能重建新订单“试一次” |
| 行情旧或账户未对账 | 当前保护判断受限，原因和持续时长可见 | 停止依赖无效数据的新开仓；恢复须重新核验 |

保护概览建议使用“规则已启用 → 条件已触发 → 委托已发送 → 真实成交完成”四段，每段独立显示；技术层“盯盘程序在跑”不等于资金已受保护。

## 8. 组合风险摘要：替用户处理复杂度

默认首屏用一句话与四个摘要，不显示一圈难解释的仪表：

- **预算**：总权益、可用现金、挂单冻结、新开仓预算剩余；没有完整账户状态则显示“预算待核对”。
- **集中**：最大单股/行业暴露、相关资产聚集；点击定位哪些票贡献风险。相关性必须标历史窗口和覆盖。
- **可退出性**：可卖/今日不可卖金额、停牌/受限风险、未成交退出委托；它与账面盈亏同样重要。
- **执行不确定性**：UNKNOWN 数量、对账差额、陈旧行情影响的持仓数量、最近核对时点。

风险情景只在数据支持时显示，如“板块同跌情景损失”“费用后止损情景”；没有协方差/压力模型时不伪造 VaR。最大回撤来自账户费用后净值，信号样本回撤另标；组合优化建议和已执行持仓分别显示。

## 9. 毛玻璃与霓虹：加强层次，不淹没数字

| 视觉层 | 建议 |
|---|---|
| 场景底 | 延续深蓝黑，使用低对比网格、微弱体积光；背景不承载数据状态含义 |
| 玻璃容器 | 一级 HUD/票面/侧栏使用冷色半透明材质，文字背板保持足够不透明；背后内容动时仍可读 |
| 霓虹边界 | 冰青/电蓝描边与局部边缘光强化选中与流向；关键警报用独立语义色，不让所有卡片同亮 |
| 文本 | 主数字银白、标签冷灰；正文不用大面积低透明字；数值等宽、单位紧邻、精度随数据可靠程度 |
| 行情语义 | 保持红涨绿跌；科技青只用于交互/流转，不拿绿色同时表示上涨和系统健康 |
| 运动 | 仅真实新事件产生短脉冲，多个事件聚合；无数据时静止并标原因；支持减少动效 |
| 层级 | 选中票最亮，相关节点/证据次亮，其他背景降亮；同时发光对象设预算，保持阅读焦点 |
| 性能 | 合并推送、局部更新、环形缓冲和可见区域绘制；blur 集中在有限容器，提供高可读/低 GPU 模式 |

用户已明确希望增强毛玻璃、半透明和霓虹，后续视觉规范应同步更新为这项新方向。目标不是削弱效果，而是在真实桌面渲染和高密度数据下验证效果。建议验收正文对比度至少 4.5:1，关键数字/状态不能仅靠颜色识别；在 Tauri WebView 中检验模糊回退效果。

## 10. 可执行的 UI 迭代顺序与验收

1. **先统一 context 与状态词典**：身份/时点/单位/未知/版本；实现固定票、账户隔离和过期响应保护。验收切股票、切账户、慢响应、断线回放、编辑中切焦点不串单。
2. **再丰富默认摘要**：市场一句话、票面行动句/反证、账户四摘要、监控业务影响。验收读屏者 10 秒内说出是否阻断、为何关注这票、下一步是什么；未知情况能正确识别。
3. **补全过程与保护**：计划→订单→持仓事件链；部分成交、撤单中、T+1、UNKNOWN 的真实解释。验收各状态夹具、重复/乱序事件、重连对账，不能只截“正常”样例图。
4. **最后接研究预测和组合能力**：仅在数据合同与样本外证据到位后展示概率/风险模型；原面板继续承载，不新增一个脱节的“AI 大屏”。
5. **视觉与性能一同验收**：1920×1080 首屏、窄 dock 面板、多屏/不同缩放、玻璃回退、减少动效；给出实时正常、降级、未知三类真实截图。绘制帧率和端到端延迟分别测量，不能拿动画帧率证明业务实时性。

每次交付都附“本次新实现/沿用已有/仍待实施”清单。新术语在第一次出现时用一句人话解释，专业字段留给展开层；系统的复杂度应由系统承担。
