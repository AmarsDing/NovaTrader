# 数据纪律：没取到 ≠ 0（全仓写作红线）

> 版本：v0.1 · 日期：2026-10-19 · 适用范围：backend 全部服务 + web 前端 + pyworker/broker-gw。
> 凡新增「取数」路径（采集、查询、计算、归一化、展示）必须遵守本文。与 M01 设计文档
> N3-01、M02 设计文档 §4.4 配套阅读。

## 1. 红线一句话

**任何一次取数失败、源端异常、窗口为空、窗口不足，都必须以「缺失」显式表达，禁止用 0 冒充。**
0 是真实的数值（真涨停 0 成交、真空仓），缺失是没取到——两者进入 MA、涨跌幅、风控、
面板后的后果完全不同。把缺失写成 0，就是把「看不见」变成「算错了」。

## 2. 统一封装：`dataformat.Result[T]`

位置：`backend/library/dataformat/result.go`。这是全仓唯一的「取数结果」封装。

```go
r := dataformat.OK(42.0)
r := dataformat.Missing[float64](dataformat.WhySourceDown, "eastmoney HTTP 429")

if v, ok := r.Value(); ok { /* 只有 ok 才能用 v */ }
r2 := dataformat.Map(r, func(v float64) float64 { return v * 100 }) // 缺失自动传播
r3 := dataformat.First(primary, fallback)                            // 主备源链
r.ValueOr(0) // ⚠ 仅展示层兜底（如进度条宽度），禁止用于掩盖缺失后继续计算
```

- 零值 `Result[T]{}` 本身就是 `Missing(unknown)`：声明后忘赋值也安全。
- `Value()` 返回 `(v, ok)` 两个值，编译器强制你面对缺失分支。

### Why 六值（取值稳定，日志 / data_quality_issue.message / 前端文案共用）

| Why | 语义 | 典型场景 |
| --- | --- | --- |
| `not_run` | 采集没跑 / 任务未执行 | 调度未到点、依赖服务未上、覆盖率分母为空 |
| `source_down` | 源端失败 | 限流/封禁（P3-9 已打标）/超时/5xx/连接重置 |
| `empty` | 源成功但窗口内真无数据 | 90 天解禁窗 0 行且采集新鲜 |
| `stale` | 有数据但已过期 | 快照超 stale_after、本地数据停在历史日期 |
| `filtered` | 被校验链隔离 | 异常值、时间倒挂、覆盖率不足 |
| `unknown` | 拿不到任何证据（兜底，能不用就不用） | 零值 Result |

## 3. 各层分工

| 层 | 职责 | 规则 |
| --- | --- | --- |
| 采集适配器（data） | 把源字段解析成 domain 类型 | 解析失败 → `nil`/跳过该行 + 不静默落 0；半覆盖源在类型里用 `*float64` 留缺失 |
| biz 校验链 | 把质量问题写成 `Issue` → `data_quality_issue` | 失败/异常/缺失都要留痕；闸门判定遇到「无法判定」（Missing）时放行还是拦截必须显式写明理由 |
| 存储（ent schema/repo） | 保存缺失 | 可空字段用 `Optional`+`Nillable`；upsert 用 `SetNillable*`；禁止给数值字段塞 0 表示缺失 |
| 服务层 / API | 把缺失传给前端 | proto 可空字段保持 nil；JSON 归一化层禁止 `?? 0` 吞掉 null |
| 前端 | 呈现缺失 | 展示「—」/「没取到（原因）」；判定条件必须 `!= null` 先判；告警在缺数字时灰显而不是消失 |

`source_health.last_error` 记源端失败原文（截 500 字符）；`data_quality_issue` 记数据层面
的问题行。两者与 `Result[T]` 的分工：Result 管「函数返回值层面不丢缺失」，两张表管「持久化留痕」，
UI 管「让人看见」。三层都要做，只做一层等于没做。

## 4. 写作红线清单（DO / DON'T）

**DON'T（真实破口，均已修过）**：

- `num(x) ?? 0`、`xxx ?? 0` 把 null 吞成 0（前端 api 归一化层、面板）。
- 解析失败 `f, _ := anyNum(v)` 后直接用 `f`——那是伪 0（东财 `anyF`、Tushare `pre_close`）。
- 覆盖率分母为空时返回 1 让闸门静默通过（`Completeness` 旧语义）。
- 缺 `adj_factor` 写 0——会把历史复权价清零。
- `omittedCount ?? 0 > 0` 这类判定：null 时不告警，告警悄悄消失。

**DO**：

- 指针/nil 保留缺失：`PreClose *float64` 解析失败保持 `nil`。
- 用 `dataformat.Missing(why, note)` 表达「没取到 + 原因」，`Map/FlatMap` 让缺失传播。
- 闸门无法判定时：显式记 `Issue{Severity: "warn"}` 并写明放行理由（如冷启动不能卡死）。
- 展示层：`intText(null)` → 「—」；灯用 `off`（灰）；判定 `!= null && > 0`。
- 告警在数字缺失时显示「信息缺失」灰标，不许静默消失。

## 5c. 已落地锚点（P3-10c 前端归一层全审，2026-10-19）

方法论：6 路 fan-out audit 把全仓 70+ 处 `num(...) ?? 0` 逐字段三判定——**后端可缺性**
（proto optional / DB Nillable / 采集缺键是否折叠 0）× **消费面形态**（先判 found/>0/hasClose
的比较守卫，还是 toFixed/插值直出）× **fix·sentinel·param** 三分类。结论：绝大多数是
**冗余哨兵**（kratos EmitUnpopulated 恒发 + proto 非 optional + 消费方全判守卫），真破口
收敛到 10 处 + 2 个消费面守卫洞。哨兵一律在转换函数头注释钉死口径（禁止后人误改 `?? null`
把真 0 吞成「—」），注释源即 audit 判词。

- **后端折叠破口（链条修范式）**：biz 层把源缺键折叠成 0 + proto 非 optional + kratos
  EmitUnpopulated 恒发零值时，前端单改 `?? null` 无法区分真 0 与假 0，必须链条修：
  **proto optional → pb 重生成 → biz 指针化（`*float64`，键有才赋值）→ service 直传 →
  前端 `number | null` + `?? null` → 面板 null 兜底文案**。已跑通两处：
  - `AuctionRow.auctionPct/volRatio/turnover/unmatched`（新股无昨收/无 5 日均量/无股本/
    无未匹配快照时源端不落键，`monitor.go auctionFloatPtr` 只透真键；`auction_amount` 键
    恒在保持 number+哨兵注释）。同簇第 10 处破口：昨涨停竞价强度均值循环缺键股不再按 0
    稀释（键有才入均值，`prevTierAuctionPct` 链路与 market.proto:455 既有样板同构）。
  - `PremiumDay.openAvg/highAvg`（开盘口径整批缺/快照收盘补齐前 High 全缺时样本空，
    `summarizePremium` openN/highN>0 才置指针；closeAvg/closeWin 缺失口径已由 hasClose=false
    表达，保持 number+哨兵）。
- **前端门控/过滤修**：`BrainLatencyHistogram.p50Ms/p95Ms` 空窗（total=0）→ null（0ms 不是
  合法分位，detail 显「样本不足」）；`FrozenEmotion.structureGaps` 脏值（null/0）filter 剔除
  （不再吞成「0板断层」文案）。
- **消费面收口 4 处**：detail.ts 竞价量比 toFixed 直调 → null 显「—」；溢价主卡 openAvg/
  highAvg null →「—」+ note 写明「无竞价开盘数据」；延迟 P50/P95 null →「样本不足」；
  quote-sidebar 涨跌行守卫 `last>0` 收紧为 `prevClose>0 && last>0`（修新股首日假「+0.00%」，
  prevClose=0 是派生不可算总闸门）。
- **口径冲突实锤**：signals.ts `highValue` 删掉 `(finalScore ?? 0) >= 85` 前端回退——后端
  对「模型降级但规则分≥85」明确 HighValue=false（biz_test.go:442-445 钉死），前端回退会
  复活降级高分信号；`high_value` 落库为唯一权威。
- **复核收口 2 项**：datasource-health 成功率 `(row.successRate ?? 1) < 0.9` 把缺失冒充满分、
  告警静默消失 → null 显「—」不参与告警（不虚警）+ title 写明无采样；limit-ladder
  `sealAmount==null` 死分支判哨兵钉链（seal_amount 全链条非指针，缺键折叠 0 参与求和不改变
  总额读数，死分支是契约漂移防线）。
- **回归钉死**：`web/src/api/__tests__/missing-not-zero.test.ts` 6 用例——四推导字段缺键→
  null / openAvg·highAvg→null / 空窗分位→null / structureGaps 脏值过滤 / highValue 不复活 /
