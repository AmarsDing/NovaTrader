## 1. 合成后要做成什么

打开软件，第一眼回答四件事：今天能不能做、做什么、为什么没选上、哪条链路是空的。点开一条，能顺着读完：谁赞成、谁反对、规则给出的价格和股数、风控夹了多少、这笔还没下单还是下一交易日才执行。

三份材料说的是同一层，只是切入点不同：

| 材料 | 它强调的 | 收进本文的位置 |
|------|----------|----------------|
| 个人交易信息全览 | 先有数，再有判断，再有一屏；缺数要大声说缺 | P1、P2、P6、P10、P11。P0 已完成 |
| ai-hedge-fund | 一次决策能顺着读完；下单前有批准页；会话可重放 | P3、P4、P5、P7、P8、P9 |
| 350 个 Grok 交易台 | 岗位分工，主管只把要签字的指令推上来，异议不要被平均分藏住 | P3 的票、P5 的值班表 |
| Vibe-Trading、TradingAgents、freqtrade | 数据源失败要剔除、四维到齐再写结论、回测留下时点、下单前确认且不重发 | P1、P2、P3、P7、P9、P10、P11。对照见第 10 节 |

视频里的画面是概念示意，不是可安装的软件。Grok、名人分析师、美股多空都不进本项目。交易台要学的是编制：扫描、模型、消息、资金、外围、风控，上面有一个主管。主管不下单。粒子网络不放进决策台，也不占第 22 个面板。只读监控页的画面以 `监控驾驶舱呈现方案.md` 为准。

## 3. 实施时守住的边界

1. 空数据写成缺口，不写成「今天没有信号」或「今天没有消息」。
2. 模型降级标 `规则分`。规则分不伪装成模型论点。
3. 确认之前不改模拟盘账本。实盘文件单在 P11 之前不写。
4. 夹掉的仓位留在现金，界面写出请求值、允许值和规则号。
5. 股票池、自选、黑名单不写进两个模板的定义。回测每次选定范围；模拟盘在启动时钉死范围，并记进当次会话。
6. 视觉保持红涨绿跌。发光只给 85 分以上的信号、预警和 Kill Switch。决策台本身不加发光，也不做粒子网络图。粒子网络只允许出现在 `监控驾驶舱实施方案.md` 规定的 `/monitor`。
7. 岗位固定六个加一个主管。不按视频去堆几百个机器人，也不做链上巨鲸。资金岗看主力、龙虎榜、北向、竞价。

## 4. 贯穿各阶段的一张票

界面上的「一条决策」用同一形状，避免决策台、交易面板、回测、会话账各说各话。

```text
票
  身份     代码、名称、模板（首板弱转强 | 强势回踩）、方向
  时机     形成日、执行日（下一交易日）、状态：待执行 | 已执行 | 漏选 | 过期
  价格     入场区间、止损、止盈、股数。来自规则，不来自模型
  投票     技术 / 消息 / 资金 / 外围：分数、来源（模型 | 规则分 | 未调用）、1～5 条理由和证据编号
  异议     低于阈值的维度，或风控否决。放在综合分前面
  风控     请求仓位、允许仓位、命中的 Rxx、夹掉的部分留在现金
  账本     尚未下单，或已成交的价格与股数
```

P3 先在决策台用现有信号、候选、研判、风控接口把这张票拼出来，不新开下单通道，也不新建一张和会话账平行的表。P9 再把同一形状落成可重放的会话记录。在那之前，票是读模型，不是第二本账。

主管不做额外一轮自由对话。它只排列已有结果：综合分、四票、异议、规则价、风控预检。证据编号沿用 M05：`F:` 因子、`N:` 情报。数字必须能在当次输入里找到。

推到眼前的条件：漏斗命中，且还在信号有效期 30 分钟内。没选上的进漏选列，不进待执行。除此之外的上涨，系统不接。

### P1 数进库

对应全览阶段 B。这一阶段主要是本机环境，不改策略。

1. 通达信金融终端做盘后数据下载，`D:\new_tdx\vipdoc` 出现全市场日线和分钟线。datahub 能读到，market 能写出快照。决策台「无快照」消失，或缺口写明仍缺哪一段。
2. 配上 Tushare 令牌。日线、复权、资金、龙虎榜在令牌缺失时继续标 unavailable，有令牌后采集任务真的跑完。
3. 新闻和公告源能发出 `intel.raw.*`。`stock_basic` 要有全市场简称，情报关联才有词典。
4. datahub、market、intel、strategy、brain、trade、notify、admin 都在跑。飞书 Webhook 仍可空；桌面通知只要上游有事件就能到。
5. 黄金、半导体、航空的外围映射可以在这一阶段补进 M02。没补之前，外围岗保持「未调用」，不估一个分数。
6. 源的顺序维持 M01：盘中快照走通达信，盘后读本机 `vipdoc`，日线和资金再接 Tushare，AkShare 做外围和涨停池备源。某一源失败，当次结果剔除它，缺口条写源名和原因。不用上一次成功的快照冒充现在。调用方指定了源时，不改道到另一源。
7. 不把 mootdx 加进默认链。[Vibe-Trading](https://github.com/HKUDS/Vibe-Trading) 在 2026-10 已把它移出默认链，因为通达信服务器不再响应该客户端协议。本项目继续读本机 `vipdoc` 文件。
8. 同一根 K 线只取一次。回测缺日就失败并点名日期，不在回测过程中临时打外网补 K 线。

验收：决策台缺口条与数据源面板一致。快照为空时，今日动作写「要有日线和快照才会出」，不写「今日没有机会」。

### P2 判断接通

对应全览阶段 C。地址未确认之前不做。

1. vLLM 地址写入配置，M05 `Analyze` 和晨报走模型。`intel.llm.enabled` 打开，重要度已由规则打完的条目做模型重评，否定句（如「不减持」）由模型修正。
2. 模型不可用时保持现有降级：维度 50 分、`source=rule`，晨报 `degraded=true`。界面用「规则分」，不用模型口吻。
3. 嵌入服务接上之后，知识库才做改写稿归簇和案例语义。这一步不挡住 P3。关键词检索继续用。
4. 四维用较短的调用，综合结论用更完整的一次。都走本地 vLLM，不为此再接云厂商。某一维失败只重试这一维，不把已经合格的三维推倒。重试规则仍按 M05：两次不合格按现有口径丢弃或降级。不引入另一套图执行引擎。

验收：同一只股票的四维里，有数据的维度 `source` 不是 `rule`；没有情报的消息面仍是规则分，并写明没有情报。

### P3 票能顺着读完

改 `web/src/view/OverviewView.vue` 和 `web/src/view/decision-desk.ts`，测试加在 `web/src/view/__tests__/decision-desk.test.ts`。信号或研判接口若还没有四维分数、理由和证据，从已落库的研判结果补只读字段，不新开一次模型调用。

左栏三列，右栏才是正文。现有的「今日动作」和「为什么没选上」收成这三列，晨报热词、缺口、持仓留在原位。

| 左栏 | 一行显示 | 右栏 |
|------|----------|------|
| 待执行 | 代码、模板、方向、入场、止损、止盈、股数，并写「下一交易日才执行」或「有效期内尚未下单」 | 四维投票、异议、1～5 条理由、证据、风控夹紧 |
| 已执行 | 同上，外加成交价和股数 | 同一张票，标题写执行的是哪一天的决策 |
| 漏选 | 代码、死在漏斗哪一层、一句原因 | 规则分。没有模型长文 |

风控块写：请求仓位、允许仓位、规则号、夹掉的部分留在现金。被 Rxx 拒绝的不进待执行。

模型降级的行标 `规则分`。85 分以上仍可用现有高亮，决策台容器不加发光。

四维到齐之后才写综合结论。结论要能点到反对的那一维。异议只保留一轮，不循环辩论。价格和指标上的数字仍只能来自事实包。

持仓接口失败和「真的空仓」分开写。没读到持仓时，不把账面显示成空仓，缺口条写账户没返回。空列表才是空仓。

CommandBar 在现有权益和 Kill Switch 旁增加「待执行 N」。点它聚焦决策台，不新做底栏页面。持仓权重继续用现在的算法。

点代码仍进行情，点下单仍进交易面板，并带上这张票的代码、方向和入场价。交易面板在 P4 才拦截。

验收：没有研判正文时右栏写「未调用」或「规则分」，不出现编造的理由。漏选原因仍来自漏斗字段，用现有 `missLabel`。WebSocket 推送后，待执行列表在 2 秒节流内更新。

### P4 模拟盘批准页

改 `web/src/view/TradeView.vue`。从决策台带过来的下单，以及在交易面板手填的模拟单，提交前都先经过这一页。确认之前不调用会改账本的接口。

正文只用三种：

1. 有待执行的票：写明形成日、执行日、代码、方向、入场、止损、止盈、股数，以及将提交给风控的仓位。若本次同时会让策略再跑一轮，接着写「确认后还会产生新的信号」；不会就写「这次只下这一笔」。
2. 今天没有待执行单，也不是该出信号的时点：写「只看估值，不下单」。确认按钮不可提交订单。
3. Kill Switch 已触发：写「只允许卖出」。买单在这一页就停，不把拒绝留到 R01 才看见。

缺行情或价格算不出来时，这一页列出缺什么，不给一个空价格让人确认。

实盘按钮保持拒绝，文案仍是未满 20 个交易日或未准入。批准页不打开文件单通道。

验收：取消或关闭批准页后，持仓和现金与打开前一致。确认后的拒单仍显示规则号。

### P5 岗位值班

改 `web/src/panels/brain/brain-monitor.panel.vue`，数据用现有模型链路和进度事件。

七行：扫描、模型、消息、资金、外围、风控、主管。每行：状态（未调用 / 进行中 / 完成 / 失败）、最近一次时间、一句结论、是否与主管冲突。

研判进行时：一行一个维度。分数或「规则分」先出现，理由随后补上。界面按秒刷新，不按 token 重排。缓存命中直接给最终结果。失败把异常原文留在该行。四维没有到齐时，主管行写「还在等」，不先给综合结论。

主管行没有单独的模型调用，它的结论就是当前待执行票的条数，以及有没有票被风控拿掉。

验收：vLLM 没配时，四个维度都是「未调用」或「规则分」，扫描和风控仍按自己的数据源显示。不出现 350 行。

### P6 当前标的的资金、席位、竞价

### P7 回测成绩条

改 `web/src/view/BacktestView.vue`。数字用 M07 已有口径，不在前端重算夏普。

跑的过程中和结束后都显示六格：组合净值、收益率、基准收益、超额、夏普、最大回撤。基准是 `000300.SH`。权益曲线上基金用面积，基准用折线，颜色仍是红涨绿跌。

成交带列最近成交：时间、代码、买卖、数量、价格、这笔之后是持仓还是已平。运行中曲线可以变长，结束时六格以引擎最终结果为准，并给出任务 id。运行中不提供「从界面拆掉这次任务」。失败显示异常原文。

每次回测留下一张运行记录：数据源、起止日、基准、警告、缺了哪些交易日。成绩条能点开这张记录。用了该日决策时点之后才出现的字段，任务失败，不出夏普。发布日不清楚的财务或公告整段不进样本，不用报告期冒充当时已经披露。

费用口径跟 M07。成绩条写明含费还是不含费，前端不再扣一遍。

大模型不参与这段历史重放。不把分析师链路按历史日期重跑一遍来当回测。若以后做影子评分，提示词不能带该日之后的价格和新闻；那不是本阶段。

### P8 模板和股票池分开

不新做向导，也不做多空策略库。两个模板的过滤、评分、入场出场、仓位、节奏继续留在 M06 的策略定义里。自选、黑名单、本次回测范围留在各自的表和请求参数里。

P9 的每条会话记录带上当时的范围：全市场，或一份代码列表，以及黑名单版本。影子进化比较模板和参数时，读这个范围，避免把「换了一批股票」当成「模板变好了」。

默认参数（融合 0.4/0.6、入选 75、高价值 85）在 P10 之前不改。样本不够时不调。

### P9 可重放的会话账

落在 PostgreSQL，经 `trade` 的数据层写入。不在家目录堆 JSON，不在业务里写裸 SQL。表结构进 `backend/ent/schema/`，并改 M09 设计文档后再生成代码。

一条会话至少包含：交易日、已执行的票、当日新形成且下一交易日才执行的票、持仓、现金、净值、成交、当时的股票池范围、与上一条的链接。只追加。重跑时旧记录标出主链，主链仍能按顺序重放。

推进规则：

1. 先对账。本地持仓、现金和会话推出来的不一致，就停下，不自动改平。有实盘之后，再与文件单 `position.csv` 的今仓、可卖对账；本阶段只对模拟账。
2. 推进中失败：停止新的模拟买入，写明原因。已有持仓的卖出仍可走人工。定时任务不能在坏账上继续买。
3. 不跳过交易日。停了若干天，下次从 `trade_calendar` 上最老的未完成交易日补，一次一天。不用「跳过周六日」代替日历。
4. 同一根 K 线上既用收盘价决策又用它成交，这条路径不存在。保持 M07 的下一交易日撮合。
5. 会话记下当次用的数据源和截止时点。持有窗口已过的票，补上实现收益和相对沪深 300 的超额。结算失败不挡住新票，票上写「未结算」。

20 个交易日的准入打开这本账，逐日能看到信号、拒单规则和净值。天数计数器只作辅助。

### P10 观察，再决定要不要加模板

对应全览阶段 E。加模板之前用现在这两个跑完。连板加速、烂板、趋势中军先不进漏斗。

准入沿用 M07 的检查表，并增加「会话账连续覆盖这些交易日，且没有未解释的对账失败」。回测门槛保持：回合数、回撤、年化、盈亏比、夏普。缺任何一项，界面继续拒绝实盘。

人批准才能换模板或换参数。不自动晋升。参数搜索仍用 M07 已有的单次、搜索和前推，不用另一套优化器在这 20 天里改掉 0.4/0.6、75 和 85。

复盘读 P9 的结算句，只给人看，也给以后调权重作材料。不自动改 R 规则，不从成交里反推一套新模板。要数的差异只有三类：止损当天又买回、没按止损卖、信号已出但没执行。同一标的止损后的冷却，先在这本账里计数；反复出现再提案成一条风控，本阶段不改规则。

### P11 文件单

对应全览阶段 F 和 M09。量化终端登录，文件单输入输出目录打开，`broker-gw` 健康。

半自动：人在批准页确认后才写 CSV。文件单带确定性的单号。批准超时或不确定是否已经写出时，先查输出目录和 `UNKNOWN`，不另写一张。`UNKNOWN` 只通过对账查 `sid`。终端退出或输出文件超时，有实盘持仓时停止新开仓并通知。止损止盈仍由 M08 盯盘生成普通限价单，不在终端里再挂一套条件单。

模型进程不读量化终端的登录态，也不持有终端目录之外的交易密钥。目录和账户只在配置和 `broker-gw`。模拟盘与实盘的出口分开，未准入时实盘出口保持关闭。

P10 未通过时，这段代码可以存在，界面上的实盘入口保持拒绝。

## 10. 三份仓库：采纳什么

核对的是 2026-10-10 的公开说明：[Vibe-Trading 中文说明](https://github.com/HKUDS/Vibe-Trading)、[TradingAgents 说明](https://github.com/TauricResearch/TradingAgents) 与其 [论文预印本](https://arxiv.org/abs/2412.20138)、[freqtrade 运行循环](https://www.freqtrade.io/en/stable/bot-basics/)。三者都是研究和模拟框架。加密货币交易所、美股社交源、自然语言写策略，不进本项目的主路。

| 仓库 | 值得留下的做法 | 落点 |
|------|----------------|------|
| Vibe-Trading | 同市场多源按顺序尝试；失败的源从当次结果剔除，快照标不完整；点名的源不悄悄换源；本机文件源不改道到网络 | P1 |
| Vibe-Trading | 回测留下数据源、区间、警告。时点之后才有的字段不进样本 | P7 |
| Vibe-Trading | 写操作要人批；进程不持有交易密钥；同一客户单号避免批准超时后写第二张 | P4、P11。不接入他们的券商代理 |
| Vibe-Trading | 用自己的成对账规则路径和实际路径：过早卖出、该止损没止损、信号没执行 | P10。账用本项目会话，不解析同花顺或富途导出 |
| TradingAgents | 分析岗位并行，报告到齐后再写结论；反对意见留在结论里 | P3、P5。辩论一轮封顶 |
| TradingAgents | 快模型做维度，深模型做汇总 | P2。都在本地 vLLM |
| TradingAgents | 没有持仓上下文和持仓为空不是同一件事。结算失败写明，不假装复盘过 | P3、P9 |
| TradingAgents | 价格和指标必须钉在已核对的快照上，模型不另编数字 | 已有 M05 证据校验，P3 界面照做 |
| freqtrade | 回测、模拟、实盘走同一套规则；数据先下好再回测；一根 K 线只取一次 | 规则共用已在 M07。取数纪律写进 P1、P7 |
| freqtrade | 下单前有确认；未成交超时后查状态，不重复发单 | P4、P11 |
| freqtrade | 回测若用到未来 K 线，结果作废 | P7。沿用 M07 截断自检，报告里写出来 |
| freqtrade | 止损后的冷却、连续亏损锁，是信号之外的否决，不是另一套策略 | P10 先计数。真要加，写成 M08 的一条规则 |

已经对齐、不必再立项的部分：模型不直接下单，费用进撮合口径，股票池和模板分开，模拟在实盘之前，急停停买。freqtrade 的参数搜索对应 M07 已有的搜索和前推，P10 之前不拿它改默认参数。

不采纳的部分已经收进第 8 节：alpha 因子库一次性横评、代理人群预设、把大模型决策按历史日期重放、交易所直连和杠杆、用训练替换模板、mootdx 与 Yahoo 作为行情主路。
