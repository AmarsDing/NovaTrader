当前 `main` 的界面是 **Textual 终端应用**（命令 `aihf`）。仓库根目录已经没有 `src/`、`app/` 网页工程。路线图里的 Web 仪表盘仍标成「脚手架、还跑在旧引擎上」，这次核对的树里没有那套 React Flow 画布。下面按现在能跑的产品写。

## 1. 它在解决什么

一句话：把「基金」做成一个会持续记账的对象。分析师给出观点和书面理由，确定性代码算仓位、过风控、下单。回测和模拟盘走同一条 `advance`。

组织方式和真实基金对齐：

```text
基金        资金、委托书、一直在跑
 ├─ 资金分配   每个策略分到多少钱（现在是人手写的比例）
 ├─ 策略 / 组合  若干分析师 + 一种合成仓位的规则
 │    分析师 → 观点（conviction −1～+1）+ 书面理由
 └─ 总风控 → 经纪商 → 账本（每笔决策和理由都留下）
```

三层都能替换，而且输出契约相同：

| 层 | 是什么 | 现在做到哪 |
|----|--------|------------|
| 分析师 | `AlphaModel.predict(ticker, date, data) → Signal` | 5 个大模型投资人 + 1 个量化模型 |
| 策略 | 若干模型 + 合成方式 + 资金切片 | 4 份 YAML 策略库，向导里还能自选分析师 |
| 基金 | 若干策略 + 总风控 + 本金 + 调仓节奏 + 基准 | 委托书写在 YAML，股票池不写在委托书里 |

股票池和「这张桌子怎么做」分开。委托书只写策略、人员、风控、本金、调仓频率、基准。回测每次指定股票；模拟盘在部署时把股票池钉死，之后每个交易日都交易同一批代码。

## 2. 一次会话在做什么

一个 session 是一个已经走完的交易日。`advance` 固定四步，回测和模拟盘是同一段代码：

```text
对账    经纪商持仓必须和账本推出来的一致，对不上就报错，不许悄悄改平
执行    执行上一会话留下的决策：先刷新观点，再按目标仓位对实际持仓下单
估值    用当日收盘给账面计价，得到净值
决策    只在调仓日：时点数据 → 分析师出 Signal → 合成目标权重 → 风控夹紧
记账    写一条 SessionRecord，和上一条哈希串起来
```

时点规则：T 日收盘做出的决策，到 T+1 收盘才执行。同一根收盘价上既评估又成交，这条路径不存在。

三种运行方式只换时钟、经纪商和状态放在哪：

| 模式 | 时钟 | 经纪商 | 状态 | 现状 |
|------|------|--------|------|------|
| 回测 | 历史 | 内存模拟 | 内存，结果另存 JSON | 已有 |
| 模拟盘 | 真实交易日 | 纸面账本 `broker.json` | 哈希链账本 | 已有 |
| 实盘 | 真实交易日 | 真实券商 | 同一套账本 | 未做，默认关闭 |

回测里的大模型提示词会「蒙住」代码、行业和日历日期，避免模型用训练记忆里的后来走势冒充当时的判断。模拟盘不蒙，因为面对的是尚未发生的下一会话。

## 3. 全部功能

### 3.1 分析师

大模型分析师只是一段系统提示词，机械部分都在 `LLMAgent`。输入是截至当日已披露的基本面快照。输出固定 JSON：`signal`（看多 / 看空 / 中性）、`confidence`（0–100）、`reasoning`（2～4 句）。再映射成 `Signal.value ∈ [-1, +1]`。

| 名字 | 权限 | 它在看什么 |
|------|------|------------|
| Benjamin Graham | 只做多 | 安全边际、资产负债、盈利是否稳定；贵了就是看空理由 |
| Warren Buffett | 只做多 | 护城河、资本配置、财务实力、估值、能否拿十年 |
| Charlie Munger | 只做多 | 先想怎么亏、生意质量、资本配置；看不清就丢进「太难」 |
| Peter Lynch | 只做多 | 增长类别、PEG、盈利是否跟着收入走、负债 |
| Stanley Druckenmiller | 可多可空 | 基本面拐点、市场已经计价了什么、不对称；没有宏观和价格数据时只看财报轨迹 |
| PEAD（量化） | 可多可空 | 盈利超预期后的漂移：8-K 公告日起 4 天内，超预期 +1、不及预期 −1，过期为 0 |

权限是硬的：只做多的分析师即使写出看空，也不能单独支撑一笔空头。空头必须有「可多可空」的分析师撑着。量化模型和名人分析师走同一个接口。

路线图里还没做的分析师：Cathie Wood、Michael Burry、Bill Ackman、Damodaran 等；量化侧的动量、均值回归、价值质量、制度切换、统计套利。

### 3.2 策略库

策略是 YAML，向导自动读目录。合成方法现在都是「按信念加权」。

| 文件 | 显示名 | 人员与权重 | 合成 |
|------|--------|------------|------|
| `deep-value.yaml` | Deep Value | Graham×2、Buffett、Munger | 只做多，总敞口目标 1 |
| `fundamental-ls.yaml` | Fundamental L/S | 五位分析师 | 美元中性；空头要 Druckenmiller 支持 |
| `inflections.yaml` | Inflections | Druckenmiller、Lynch | 多空；Lynch 只贡献多头观点 |
| `earnings-drift.yaml` | Earnings Drift | 只有 PEAD | 多空；模型本身就是策略 |

向导里还有「自己组桌子」：勾选分析师，生成一条自定义策略。多策略时资金切片均分。总风控默认：单票绝对权重 ≤ 25%，总绝对敞口 ≤ 100%（不加杠杆）。用户可以事后改 YAML。

调仓节奏三档：日、周、月。基准默认 SPY，回测的交易日网格也用它。

### 3.3 组合、风控、执行

组合层把各策略的观点收成目标权重。风控是纯算术，模型碰不到：

1. 单票超过上限就夹到上限，符号保留。
2. 总敞口仍超限，就全体按比例缩小。
3. 夹掉的敞口留在现金里，不再分给别的股票。
4. 每一次夹紧写成 `ClampEvent`：哪条限制、夹之前、夹之后。界面上能点开。

执行层把目标权重和真实持仓的差额变成订单。整股会造成目标和实际净值有差，报告里会写出这个差额。

### 3.4 账本与急停

模拟盘目录 `~/.hedge-fund/paper/<名字>/`：

| 文件 | 作用 |
|------|------|
| `fund.yaml` | 部署当时的委托书快照 + 股票池 |
| `broker.json` | 现金和股数 |
| `ledger/<session>.json` | 一条会话记录，和上一条哈希相连 |
| `control.json` | 急停：是否停下、原因、从何时起 |
| `events.jsonl` | 每次推进、失败、急停、恢复 |

重放账本得到持仓、现金和「待执行决策」。推进前先和 `broker.json` 对账，不一致抛 `BookMismatch`。`advance` 里面任何失败都会把基金停住，定时任务不能在坏账上继续做。急停之后 `tick` 拒绝交易。`--again` 可以重跑最近一个会话，旧记录挪到 `ledger/superseded/`，不留在主链上。

`tick` 幂等，而且不跳过漏掉的交易日。停了一周，就要补一周的会话，每次只走下一天。

### 3.5 回测与事件研究

`backtest_fund` 就是把 `advance` 在历史上循环。输出权益曲线、相对基准的收益、夏普、最大回撤、调仓次数、订单数，以及每一天的 `SessionRecord`。结果 JSON 存到 `~/.hedge-fund/research/`。

另有单模型研究用的旧回测器，以及事件研究：用市场模型算累计异常收益（CAR）。验证闸门（CPCV、回测过拟合概率 PBO）还没做。研究实验室、自动生成策略、自动晋升，都还在计划里，而且晋升默认要人批。

### 3.6 数据与模型

数据走 `DataClient`。现在的实现是 Financial Datasets（行情、基本面、盈利）。响应落在 `~/.hedge-fund/cache/`，第二次跑可以离线。基本面按**申报日**过滤，不用报告期，避免用到当时还没公布的数字。基础设施失败必须抛错；只有真的没有数据才返回空。静默的空会被回测当成「没有信号」。

模型注册表按供应商路由：Anthropic、OpenAI、DeepSeek、Google、xAI、Kimi，以及带结构化置信度的 TypeSafe（Jev）。Ollama 本地模型还在路线图上。界面里选一次模型，环境变量 `HEDGE_FUND_LLM_MODEL` 会带到所有分析师。密钥写到 `~/.hedge-fund/.env`，文件仅所有者可读；shell 里已经导出的变量优先。

### 3.7 命令行

没有参数时打开终端界面。机器调用走子命令，标准输出是纯 JSON：

| 命令 | 做的事 |
|------|--------|
| `aihf backtest <委托书> --universe AAPL,MSFT` | 默认最近约 18 个月，可加 `--start/--end/--model` |
| `aihf paper create <名字> --mandate ... --universe ...` | 部署模拟盘，本金和节奏来自委托书 |
| `aihf paper tick <名字>` | 推进下一个已完成会话 |
| `aihf paper tick <名字> --again` | 重跑最近一次 |
| `aihf paper status / list` | 净值、上次会话、待执行权重、急停 |
| `aihf paper halt / resume` | 急停与恢复；halt 必须写原因 |

## 4. 界面上的业务

应用是一叠屏幕：首页进入模拟盘或回测。配色是美股习惯（绿为赚、红为亏）。本项目视觉规范是红涨绿跌，颜色不要照搬，信息结构可以学。

### 4.1 首页

大标题，两条入口：

- **Paper trading**：在真实交易日上跑一只基金。
- **Backtesting**：把一只基金放到历史上重放。

底部一行显示「分析师正在用哪个模型」，`m` 打开模型选择，`k` 给当前供应商写 API key。模型按供应商分组；v2 还没有客户端的供应商列出来但不可选。密钥输入框是密码态，保存后只提示掩码，不明文回显。

建基金不在首页，在模拟盘里面。

### 4.2 模拟盘主列表

左栏是已部署基金，最后一行是「Build a new fund」。右栏随高亮变化。

一只基金的右栏，从上到下：

| 区块 | 显示什么 |
|------|----------|
| 身份 | 名字、急停徽章、策略名、调仓节奏、本金、股票池 |
| NEXT RUN | 下一会话会执行什么：执行哪一天的决策、目标权重、会不会接着做新决策；或者只估值、不下单 |
| PERFORMANCE | 净值、收益率、基准收益、起始日、会话数、订单数；至少两个点才画权益曲线（基金填色，基准用折线） |
| SESSIONS | 最近 3 个交易日：日期、当日净值变化、成交笔数、有没有形成新决策 |

按键：

| 键 | 业务 |
|----|------|
| Enter | 先过批准页，再跑下一会话。停着的基金会提示先恢复 |
| `s` | 打开这只基金的全部历史 |
| `h` / `r` | 急停 / 恢复。急停原因由程序写入 |
| `d` | 删除。确认页列出将毁掉的定义、回测份数、账本会话数，回车才执行 |

### 4.3 批准页（跑之前）

Enter 不会直接下单。这一页先查「下一个已完成的基准交易日是哪天」，再用人话写出这次会做什么。账本和经纪商在用户按 Enter 之前都不改。

三种正文：

- 有待执行决策：写出「在某日收盘执行某日的决策」，列出目标权重，并说明下单前会刷新观点。若当天也是调仓日，接着写「然后做新决策」。
- 没有待执行决策、也不是调仓日：只给账面计价。
- 已经跟到最新收盘：说明下次收盘大约在何时；Enter 变成「再跑一遍最近一天」，旧记录会挪走。

缺数据密钥或模型密钥时，先弹密钥页，补齐才进入批准页。

### 4.4 跑会话：分析师直播板，然后是报告

批准之后进入运行页。运行中不能退出，因为工作线程正在写账本。

直播板一行一个分析师，并行更新：

| 列 | 内容 |
|----|------|
| 状态 | 排队、进行中、完成 |
| 谁 | Graham、Buffett 等显示名 |
| 代码 | 正在看的 ticker |
| 结论 | 看多 / 看空 / 中性，外加置信度。结论比长文先出现 |
| 理由 | 正在吐出的句子，收成一行 |

阶段标题写明这次在干什么：执行某日决策、评估下一次决策，或只是计价。量化模型没有流式文本，跑完直接给出 Signal。缓存命中也不会流式输出，以最终 Signal 为准。直播只是预热缓存；真正落账的是随后的 `tick`。

跑完切到报告，底部固定一条：净值、现金、总敞口、净敞口，以及账本文件路径。失败会把异常类型和原文显示出来。

### 4.5 会话报告（历史里按 Enter 也是这一页）

左栏是导航，右栏是详情。一次会话最多两段：

1. **EXECUTED**：这一天实际动了账的那次决策（决策日写在标题上）。
2. **DECIDED**：今天新做的决策，标题写明「下一会话才执行」。

每一段里面：

- 按策略分组。组标题是策略名和资金切片比例。
- 每条信号一行：代码、分析师短名、方向符号、置信度。点开才是完整论点：方向、置信度或「投资信念」、conviction 数值、所属策略、2～4 句理由。Jev 模型还会列出看多 / 看空 / 中性概率。
- **Risk limits**：每条夹紧的范围（单票或整本）、请求值、允许值、限制名。
- **Orders**（只在已执行段）：买或卖、数量、代码、价格。没有订单时写「今天没有信念越过门槛」。
- **Portfolio / Proposed allocations**：已执行段是真实持仓（方向、股数、市值、权重），并比较目标净额和实际净额；未执行段只列目标权重，明确写「还没有订单和成交」。敞口被压成 0 的策略会写原因，并说明分到的资金闲置。

若这一天既没执行也没决策，左栏只剩「Portfolio」，右栏是收盘计价后的持仓。

### 4.6 历史页

一只基金的成绩单：

- 顶栏：名字、策略、节奏、本金、股票池、急停或正常状态。
- 六格指标：组合净值、收益率、基准收益、超额、夏普、最大回撤。
- 权益曲线：基金面积、基准折线。
- 左栏全部会话（新的在上）：日期、当日涨跌、成交笔数、是否做了决策。
- 右栏是该日摘要：执行了哪些成交（最多 8 笔）、新决策的目标权重（最多 8 个）。Enter 进入完整报告。

急停和「再跑一天」不在这页，回到基金列表。

### 4.7 建基金向导

只从模拟盘列表进入。左侧步骤轨，右侧当前步。Esc 退回上一步。名字若已被占用，会先弹出「替换」确认，列清将删除的定义、回测和账本；用户把向导走完之前什么都不删。

| 步骤 | 界面在问什么 | 约束 |
|------|----------------|------|
| Name | 基金名，默认 `ai-hedge-fund` | 小写连字符；和已有定义、模拟盘目录都不能撞 |
| Strategies | 四个库策略，可多选；另有「自己挑分析师」 | 至少一条 |
| Staff | 六个模型的多选（仅自定义时出现） | 至少一位；显示只做多 / 多空，量化模型带 quant 标记 |
| Capital | 起始资金，默认 100000 | 必须为正 |
| Cadence | 日（新闻速度、调用最多）、周（基本面默认）、月（调用最少） | 三选一 |
| Tickers | 这只基金交易哪些代码 | 至少一只；会预填最近一只模拟盘的股票池 |

完成后写 `~/.hedge-fund/mandates/<名字>.yaml`，并部署模拟盘目录。结束页两个动作：「跑第一会话」（回到列表并直接打开批准页）、「返回」。第一会话只做估值并形成第一笔决策，下一会话才执行。

代码里还有一套不选股票、结束直接去回测的向导模式，当前没有任何按钮会打开它。回测用的委托书，就是在模拟盘向导里存下来的那份。

### 4.8 回测：选委托书

左栏每只委托书一张卡片：序号、名字、最近一次回测的总收益箭头、策略数、调仓节奏、每条策略的多空模式。右栏是身份、各策略一句权限说明（只做多：买入或持现金；多空：空头必须由谁支持），以及该委托书的全部回测，新的在上，每条带当时的股票池和成绩。

`d` 删除。确认页两档：只删委托书；或连同历史回测一起删。已部署的模拟盘不动，因为它自己有一份委托书快照。

Enter 进入时间窗口，不在这一步开跑。

### 4.9 回测：窗口与直播重放

先填三样：股票池（预填这只委托书上次用过的代码）、开始日、结束日。默认窗口约 78 周，结束日默认为今天。日期必须是 `YYYY-MM-DD`，且结束晚于开始。密钥齐了才开始。

然后三阶段，运行中不能返回：

1. **Loading market data**：进度条 = 股票数 × 调仓日数。预取公司资料、价格、财务指标。
2. **Agents replaying history**：每个分析师一行，标出正在看的代码和日期。提示写明「每个日期只能看见当时已申报的数据」。这一步同样蒙住提示词。
3. **Replaying the fund**：六格指标随每个交易日刷新；权益曲线对基准；成交带最新 12 笔（日期、代码、买卖、数量、价格、名义金额、该票之后是多头、空头还是空仓）。

结束时标题换成结果：区间、调仓频率、执行次数、订单数、年化收益，并写出 JSON 路径。一个按钮回到首页。

## 5. 和 NovaTrader 已经对齐的地方

这些原则本项目的设计里已经有，不必当成新主张引进：

| ai-hedge-fund | NovaTrader 里已经写明的 |
|---------------|-------------------------|
| 大模型只出观点和叙述，不碰订单 | 决策 3、M05：模型给分数和理由；价格和仓位由规则算，订单先过风控 |
| 回测和交易是同一条路径 | M07：`pkg/rules` 与 `pkg/brokerif/sim` 和模拟盘共用；日线信号在收盘生成，下一交易日撮合 |
| 急停停买 | M08：Kill Switch 持久化，只放行人工卖出 |
| 时点诚实、禁止未来数据 | M07 按决策日复权，并有截断自检 |
| 模拟在实盘之前 | 连续 20 个交易日且准入通过，才允许半自动实盘 |

差在这些原则还没有变成「打开软件就能顺着读完的一次决策」。个人交易全览方案已经指出：21 个面板是散的，第一眼要看见今天能不能做、做什么、为什么没选上。

## 6. 建议借鉴的内容

按对当前驾驶舱的帮助排序。颜色、美股多空、名人人格都不要搬。

### 6.1 先做：一次决策能顺着读完

学会话报告的左右栏，放进决策台，不必再加第 22 个面板。

左栏一行一条，右栏才展开正文：

- 今天要执行的（昨天已经决定的）：代码、模板名、方向、入场、止损、止盈、股数。
- 今天新形成、下一交易日才生效的：同上，并写明「尚未下单」。
- 没选上的：代码、死在漏斗哪一层、一句话原因。
- 风控：请求仓位、允许仓位、命中的规则号（R00–R15）。夹掉的部分留在现金，界面上写出来。
- 账本条：净值、现金、总仓位。有持仓时列出市值权重。

M05 已经要求每条理由带证据，数字必须能在提示词输入里找到。界面上应能点开那 1～5 条理由和综合结论，而不是只看见一个分数。模型降级时，这一行标 `规则分`，不要伪装成模型写的论点。

### 6.2 先做：模拟盘下单前的批准页

学批准页的三句话结构，接到交易面板和 Kill Switch 条：

- 即将执行的是哪一天形成的信号，目标价、止损、股数写全。
- 这一步会不会同时产生新的信号。
- 若今天不是交易日或没有待执行单，明确写「只估值，不下单」。

用户确认之前，模拟盘账本不改。这和「文件单实盘仍须人工」是同一习惯，只是提前用在模拟盘上，方便以后对账。

### 6.3 接着做：模型思考时的直播板

学运行页的分析师表，用在「模型链路」：

一行一个维度或一只候选。结论（分数或看多看空）先到，理由后到。多只并行，帧率由界面时钟决定，不要每个 token 刷一次布局。缓存命中直接显示最终结果。失败把异常原文留在该行，链路空着时标「未调用」，对应现在的 `ai_degraded`。

### 6.4 接着做：回测重放时的成绩条

M07 已经会算收益、回撤和夏普。界面上按回测屏的六格来摆：组合、收益、基准、超额、夏普、最大回撤，外加一条相对基准的权益曲线，以及最新成交带（时间、代码、买卖、数量、价格、这笔之后的持仓方向）。

跑的过程中曲线在长，结束时数字以引擎最终结果为准，并给出结果文件或任务 id。运行中不要让用户把这次任务从界面上拆掉。

### 6.5 再做：委托书和股票池分开

两个模板（首板弱转强、强势回踩）可以写成和引擎同一份的策略描述：过滤、评分、入场出场、资金切片、调仓节奏。股票池、自选、黑名单不要写进策略定义里。回测每次选定股票池或全市场；模拟盘在启动那一刻钉死范围，会话记录里记下当时的范围。

这样影子进化比较的是「换模板、换参数」，不是「换了一批碰巧的股票」。

### 6.6 再做：模拟盘会话成为可重放的成绩

本项目用 PostgreSQL，不必照抄家目录 JSON。要学的是记录的形状：

- 一条会话 = 已执行的决策 + 新形成的决策 + 持仓、现金、净值、成交。
- 只追加。重跑时旧记录移出主链，主链仍可重放。
- 推进前对账，不一致就停，不许自动修。
- 管道里任何失败都触发急停，定时任务不能在坏账上继续买。
- 漏掉的交易日不跳过，下次补最老的一天。交易日历用本项目的 `trade_calendar`，不要用「跳过周六日」这种近似。

20 个交易日的准入，应该能打开这本会话账，逐日看见信号、拒单规则和净值，而不是只看见一个天数。

### 6.7 可后做

| 学什么 | 落到哪 | 注意 |
|--------|--------|------|
| 观点和仓位分开的契约 | M05 / M06 | 模型输出保持分数 + 理由；仓位继续由规则和 R00–R15 决定。不要改成 −1～+1 直接映射股数 |
| 磁盘缓存行情和提示词 | M01 / M05 | 重跑不重复打模型和数据源。缓存键含 as-of，避免把新数据写进旧日期 |
| 回测提示词蒙住「后来才知道的身份」 | M07 | 本项目已规定大模型信号不做历史回放。若以后做影子评分，提示词里不能出现该日之后的价格和新闻 |
| 研究账户和生产账户并排 | M07 影子进化 | 候选策略在旁边回测，赢了由人批准换上。自动换策略先不要做 |
| 数据失败大声报错 | M01 / M11 | 没有快照就标缺失，不要把空列表显示成「今天没有信号」 |

## 7. 明确不要搬的部分

| 他们的做法 | 本项目保持 |
|------------|------------|
| 美股代码、Financial Datasets、SPY 基准 | 通达信行情，A 股交易日历，基准用既定指数 |
| 名人投资人人格、基本面长持 | 超短两个模板；模型做四维评分和晨报 |
| 美元中性、多空对冲 | 只做多。T+1、涨停不买、跌停不卖已经在规则里 |
| 终端作为主界面 | Tauri + Vue 驾驶舱 |
| 绿涨红跌 | 视觉规范：红涨绿跌。发光只给高分信号、预警和 Kill Switch |
| 实盘经纪商插件（IB、Alpaca） | 东方财富量化终端 CSV 文件单，由 `broker-gw` 写文件 |
| 回测过拟合自动晋升 | 人批准；未满 20 个交易日界面继续拒绝实盘 |

## 8. 建议的落地顺序

1. 决策台按「已执行 / 待执行 / 漏选 / 风控夹紧」重排，理由可点开。
2. 模拟盘在改账本之前弹出批准页，写清价格、股数和将命中的风控。
3. 模型链路改成结论先到、理由后到的并行表。
4. 回测面板补六格指标、相对基准的曲线和成交带。
5. 模拟盘会话落成可重放记录，失败即急停，漏日不跳。用这本账来做 20 个交易日的准入检查。

第 1～4 步只动展示和确认，不改下单通道。第 5 步才碰模拟盘的记账。
