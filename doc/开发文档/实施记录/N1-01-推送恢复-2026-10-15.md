# N1-01 推送恢复与N0-02网关元数据穿透

日期：2026-10-15。状态：协议/transport/前端hub已实施并通过局部合同测试；业务store集成由本批主任务合并，跨服务原子快照与真实环境故障演练未因此完成。

## 数据流与修改

NATS Envelope→admin Hub（metadata保留）→每主题500帧环与epoch/topic_seq→sub_ack或resync_required→按主题REST恢复handler→冻结水位ACK→每25帧batch有界回放→async onPush消费者→已完成cursor。行情仅替换同类型/证券/频率/时间桶状态；订单/成交/风险与未知事件不合并。

代码：backend/app/admin/internal/gateway/hub.go与hub_test.go；backend/utils/websocket/model.go、client.go与client_test.go；web/src/ws/hub.ts、topics.ts及__tests__/hub.test.ts。M11固定三文档同步，M12由主任务统一。

## 失败政策

| 情形 | 实现行为 |
|---|---|
| 旧admin的seq=1000 | epoch不一致显式恢复，旧seq不能压住新seq=1 |
| 缺epoch/缺主题cursor/序号超前 | required，读取权威REST后按新水位交接 |
| 断线或REST期间超过500帧 | 不回放残缺尾部；新的resync_required和head，重新查询 |
| REST失败/无handler | 不ACK，link.sync为required；后续可注册/重试处理器 |
| 恢复时新事件 | 暂停该连接直接live，环保留；ACK后锁内回放再接live |
| duplicate/旧乱序 | 不重复应用；新跳号触发显式resync |
| 慢端满队列 | 关闭socket/取消订阅，计slow_disconnects，重连续传或恢复 |
| 前端恢复/消费积压超过1000 | 重新握手或断连，不静默推进cursor |
| 多窗口/复制sessionStorage | 每Hub独立恢复；新实例强制REST，不能把cursor当实体状态 |
| 动态退订/旧epoch晚到ACK/登出 | AbortSignal/request_id隔离，logout清除cursor |
| 历史LIVE确认/通知回放 | 保留read-model事件，但不重新弹确认/发桌面通知 |

metadata保留原Envelope外壳与单独gateway_received_at；源时间缺失不填网关时刻。NATS消费者lag改为NumPending而非全流序号差，附NumAckPending/NumRedelivered及basis。WS统计单列epoch、环容量、resync与slow_disconnects。

## 调用约定

```ts
const off = onResync(['position', 'signal'], async (ctx) => {
  // 必须等待权威查询和有效性校验；失败throw，检查ctx.signal取消。
  await restoreVerifiedState(ctx)
})
const offPush = onPush(async (msg) => {
  // 回放作为失效通知读取权威状态，不把旧payload写回快照。
  if (msg.topic === 'position') await refreshVerifiedAccount()
})
```

Hub只在async消费者成功后保存seq。返回void的历史监听不获得等待保证；实际store readiness与业务可执行性仍由各领域合同判定。`isLive`不等于数据源或账户已核对。

## 一致性限制和后续门槛

冻结W是网关seq边界，REST没有统一LSN/实体版本，不能称原子快照。恢复先读权威状态，回放再触发权威重查；版本化实体/store序列化与实际接口readiness由N1-02继续。超过环只保证状态重新读取，不能恢复所有瞬时通知或把WS当永久审计历史。NATS断连期间未收到的core行情也不由WS seq检测，源时效/覆盖必须独立呈现。

后续在真实NATS、admin、领域服务和多窗口环境复现重启/断流/恢复；核对最终store与权威API、订单/成交历史、页面同步状态；再执行5000证券压力和UI性能。旧协议客户端需与网关配套升级，不保留无epoch的静默续传。
