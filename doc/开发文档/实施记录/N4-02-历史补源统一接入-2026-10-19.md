# N4-02 历史补源统一接入（2026-10-19）

## 结果与范围

已将默认关闭的 source-worker 接入 Go datahub。真实冻结的 2025-01-06 通达信原包中全部 **5370 条有效 A 股日线**经过实际 Python HTTP 进程、Go 完整校验与隔离 PostgreSQL55432 入库。本轮复用已有原包，没有重新下载外网数据，没有启动日常采集服务或修改生产启用配置。

此次完整 `records` 合同独立于 10月16日 POC 工件内沪深北各10条、合计30条 `samples`。30样本继续用于证据预览，不能代表5370条输出或全市场覆盖率。5370是这份原包通过当前格式与 OHLC 校验的记录数，不是全体上市、停牌、退市证券的覆盖率证明。

只增加 `tdx_http_archive`（盘后 `daily_bar`、频率 `1d`）及 `openbb_fred`（`macro`）两种 Source。没有 Snapshot、实时主备、SecuritySource、上市/ST 补齐或交易功能。现有配置映射显式 `enabled:true` 才注册；生产默认值及配置文件均未启用。

## 数据流与合同

```text
固定 provider 或固定录制原包
  → Python 解析 / 内容寻址证据冻结
  → loopback HTTP v1 完整 records
  → Go 来源 / hash / OHLC / 市场 / 时钟校验
  → 同事务 outbox 占用 + PIT 修订追加 + current 条件补写
```

- worker 只监听 `127.0.0.1`。`POST /v1/source/collect` 的固定参数为 `schema_version:1` + `operation:tdx_history/date` 或 `operation:openbb_macro/series/start/end`；不接受自由 URL、文件路径、其他操作或请求级启用开关。
- 请求最大4KiB、原始压缩包及响应各8MiB、最多10000条非空完整记录、最多2个并发操作。HTTP 读请求5秒、provider20秒，Go25秒并受调用方 context 限制；忙时返回503，不创建无界工作队列。压缩包解压上限沿用100MiB。
- 成功响应含 `schema_version/status/domain/provider/provider_raw_sha256/provider_raw_kind/acquisition_mode/records_sha256/record_count/records/observed_at/available_at/training_ready/coverage/metadata`。记录 hash 校验完整记录 JSON 的确切字节；Go 逐行校验并在完整验证后才执行请求标的过滤。
- Go 只接受显式 `http://127.0.0.1:端口`，不带凭证、路径、query、fragment，不跟随重定向、不使用系统代理；worker 的请求不能改变上游地址。错误正文不回显 provider 异常、URL 或密钥。
- `GET /healthz` 只报告进程状态，provider=`unprobed`，coverage 未知；成功 HTTP 返回不等于业务持久化、完整覆盖或 outbox 已投递。
- worker 没有 DB 接口或账户/交易调用。测试子进程不继承 FRED、数据库等秘密环境。这里不宣称 Python 进程已经获得操作系统级资源及文件权限隔离。

## 录制身份、时间和修订

录制日期：`2025-01-06`。原始文件：`source-worker/evidence/tdx-2025-01-06/dfca352934d3681cb9e8e5644f0492d02a562d0a13f751acbc1d85febdf970f5.raw`。原 ZIP SHA256：`dfca352934d3681cb9e8e5644f0492d02a562d0a13f751acbc1d85febdf970f5`。

显式 `--recorded-only` 模式只允许该固定日期、文件及 hash，标 `acquisition_mode=recorded_provider_bytes`。它是原 provider 字节的录制回放，不能作为今日行情、新鲜上游证据或独立备源可用证明。未开启录制模式时仍只使用已审阅的固定 provider 入口；本轮没有在线源运行验收。

历史业务时间 `event_time` 保留原交易日。`observed_at` 是本次 worker 实际处理时钟，Go 拒绝超过1分钟的旧响应或超过5秒的未来时钟，仓储再次检查。重复处理可更新本次传输的观察时钟，但该时钟不进入稳定载荷或修订身份。`available_at=null`、证据 unknown、`training_ready=false`；不将本次采集时钟、包 Last-Modified、报告期或 FRED current-series 日期伪装为历史发布时间。

新增稳定 provenance 保存 provider、`provider_raw_sha256`、`provider_raw_kind`、`records_sha256` 和 acquisition mode。通达信 raw kind 为 `provider_http_zip_bytes`；FRED SDK 为 `sdk_normalized_result_json`，没有冒充 FRED 原始 HTTP 响应。现有 `Record.RawHash` 继续表示规范化载荷 SHA256，manifest 的 `canonical_normalized_payload_sha256` 语义与旧夹具保持兼容。真实原包 hash 与规范化单行 hash 分别保留、不能混用。

## 落库与重复/修订政策

以 domain、source 和排序后的记录修订 hash 生成 `sb:` 内容寻址批次身份（长度适配现有 outbox 字段）。先在同一个 ent 事务中依靠既有 outbox 唯一键占用批次，再追加 PIT、补写 current-view 并提交。相同批次并发请求由数据库唯一约束串行处理，重复返回0；不是先查再无条件 upsert。provider/raw 或规范化内容变化会得到新的修订与批次身份，不会被简单按日期去重。

current-view 使用 ent SQL builder 的 `OnConflict + UpdateWhere(source=同补源)`：只能插入缺项或修订已有同补源行；已有 Tushare/AkShare 等主源行保留。更低优先补源的 PIT 仍可追加，来源证据不会被抹去。不使用手写 SQL、没有 ent/schema 变更。

宏观单位完整保留在 PIT 中。现有 `macro_series.unit` 字段限制16字节；未知单位或超长单位只进入 PIT，不截断单位、不创建裸数值 current 行，也不覆盖主源。日线补源不创建 `stock_basic`，不补造上市日期/ST/停牌等历史事实。

ready outbox 的 count 明确是 `accepted_provider_records_not_current_view_overwrites`，并携带 `coverage_known:false`、`training_ready:false`、current-view 条件写入政策。count 包括主源保护下仅进入 PIT 的记录，不宣称 current 覆盖量或消费者已确认。没有完整历史分母时，批次 coverage 保持未知并产生质量提示；Source 健康是 `coverage_unknown`，不是 green。
