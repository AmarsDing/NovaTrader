# N7 信号执行事实回写（2026-10-18）

已接通真实订单/成交账本到策略信号的持久归并，并保护“trade已经提交、strategy尚未消费”的窗口不被到期任务抹除。该路径只更新既有执行事实，不产生订单、不代替最终风控，也未启用实盘。

## 调用链和身份

`trade.order/trade.fill` → strategy JetStream持久队列消费者 → 验证信封来源/主题及原client_order_id → Usecase解析原数据库委托关联的信号 → `data.signalRepo` 以 `TradeSignal.ForUpdate` 锁定 → 读取共享TradeOrder/TradeFill/关联ExecutionIntent → biz纯规则归并 → 同一事务更新TradeSignal、追加SignalEvent与outbox → 只读API及`strategy.signal.updated`。

事件只用于唤醒。载荷中的signal_id、价格、数量及状态都不能成为写库依据。支持当前订单snake_case身份和历史Go Fill结构的ClientOrderID；相互矛盾的身份拒绝。历史ApplyBar曾发布 `{book,symbol,count}` 聚合通知：仅真实trade来源、trade.order主题、精确三字段且值合法时兼容跳过，依靠周期账本扫描恢复；其它缺原ID消息不被放行，避免既有流毒记录无穷重投。

data只读取同信号/同账本的原订单，并同时检查成交自己的signal_id、book、证券、方向、数量、金额与原委托filled总量。订单与成交尚未一致时保护状态并失败重试，不将未知当作0。每信号最多1000原订单/10000成交，超限明确失败，不截断后发布结论。

## 状态含义

- 存在真实待确认、已接收、提交中、部分、撤单中或UNKNOWN委托且尚无实际成交：executing，表示委托处理中，不代表柜台ACK/成交。
- 有任何真实成交且数量对得上：done。部分成交也进入done，剩余量继续看原委托；`executed_volume`为实际成交之和，`executed_price`为实际成交金额/股数，按既有numeric(12,4)取整，费用未混入成交均价。
- 原委托全部已拒绝/已撤且零成交、无关联claimed/unknown意图：cancelled。不能把交易业务拒绝伪装成风险服务已返回的rejected信号。
- 对于迟到真实成交，内部事实归并可以将cancelled/expired/rejected纠正为done，并保留原状态→done流水。这只承认已经发生的事实，不重新提交订单。普通对外CanTransition/ActorAllowed的终态与角色权限保持原规则，客户端不能调用该恢复捷径。
- 后续部分成交增长会生成done→done的进度流水及outbox；同样数量/四位均价的重复事件不会重复写流水。没有成交时可空字段保持未知。
- closed不自动改写；按买入信号分配卖出批次、手续费、税费并算平仓Pnl仍须单独严谨实现。新归并不伪造exit_price、pnl_pct或“已闭仓”。

内部事实恢复直接记录actor=trade、明确“权威委托/成交归并”的原因，不补造未实际发生的risk_checking/approved事件。上游事件实际存在时延续trace/causation；定时恢复没有父事件，不虚构父身份。

## 竞态、恢复和观测

到期/取消迁移先锁同一信号行，再检查真实委托及关联claimed/unknown意图；有执行证据则返回ExecutionProtected，到期任务跳过。自动计划已有PlanFacts.ForShare，因此trade事务提交后，到期方才能取得ForUpdate并看见委托。原始手动绑定信号的新单也新增data验证端口：在已有全局账本事务内ForShare锁信号，匹配book/证券/方向/策略版本/当前状态/有效期，再继续风控和原FinalCheck；不调用Redis或远程HTTP。内部chase业务键只允许现有执行中/done信号的有限追单，不复活终态。risk.exit的stop_loss等trigger不是策略signal_id，已移除旧误绑定。

两个durable队列为strategy-trade-order-v1、strategy-trade-fill-v1，成功归并或验证幂等后才ACK；失败延迟2秒NAK，原身份重投。独立10秒恢复循环每次最多200个信号，采用ID游标覆盖所有状态，并在单条失败时继续后面的信号；不依赖在线事件，也不让扫描模型调用阻塞恢复。一次上下文5秒，恢复周期与批次是工作预算，不是全库恢复完成时限。

固定观测操作 `strategy/execution_projection` 记录实际单事件/有界恢复页的开始、完成及失败；received包括重投尝试，success包括真实归并及幂等核对完成，不等于唯一事件数、柜台ACK或全链路时延。指标完成在ACK之前记录。

Signal proto追加37/38两个optional只读字段，未占用旧字段；生成Go/gRPC/HTTP代码并在service返回。已有executed_price/volume列直接复用，无新增schema。
