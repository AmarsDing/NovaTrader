# N2-02 事件投递租约与持久追踪

日期：2026-10-18。已实现投递可靠性与持久事件查询，跨全部业务消费者的直接因果和处理ACK尚未完成。

## 投递

共享 outbox schema 追加 `lease_owner`、`lease_until`、`next_attempt_at`、死信时间及错误分类，已用 ent 工具生成。`pkg/outbox/lease.go` 在短事务内用 `FOR UPDATE SKIP LOCKED` 领取一条记录；30秒租约，网络发布在事务外、每次超时10秒。提交发布结果须匹配owner且租约未过期。发布后标记失败仍可能重投，稳定event_id与消费者幂等仍必需。

失败按指数退避，最多12次后进入死信；非法元数据直接隔离，不再阻塞健康记录。存储固定安全错误分类，不记录上游原文或秘密。当前没有死信重放写接口；只读查看不会重放事件。

## 查询

proto `api/admin/v1/observability.proto` 的 GetTrace，认证 `GET /api/ops/traces?trace_id=&limit=`。Gate→data AuditStore→outbox元数据投影，仅返回事件身份、来源、subject、时间、直接父事件与发布状态；最多200条，缺父事件/截断明确标记。不下发原始payload，不将 outbox published 解释成下游业务完成。

`TraceExplorer.vue` 接到原监控工具栏。精确trace查询、有界投递概况、pending/leased/retry/dead等实际状态；关闭和新查询取消旧请求，避免迟到结果覆盖。

## 实际验证

隔离PostgreSQL测试已覆盖多dispatcher只能一方领取、未过期租约不可抢、崩溃租约过期恢复、毒记录不挡健康记录、稳定身份失败重投。网关测试覆盖鉴权、过滤、错误脱敏与只读出口。2026-10-18合并复验由集成记录汇总。

## 仍保留的限制

持久查询覆盖outbox生产记录，既有未使用outbox的普通行情事件不因此持久化；直接父事件只有真实传播过才存在。不提供全消费者业务ACK、完整数据血缘、未接入时钟偏差或全链路P95。历史保留/归档和有审批的死信处置需另实现。

## 同日增补（2026-10-19）：死信重放审批（API 层，无监控入口）

前批留痕标注「回放/审批工作流仍缺」，本批把死信重放落成审批制 API（上一节将内容确认为 API-only，监控 §10 只读边界不扩第三项写）。

- **端点**：`POST /api/ops/dead-letter-replay`（`gateway/replays.go`）。Owner-only；审计未启用前置 503 一行不改；请求封闭为 `{event_id, reason}`——event_id 走 observationID 有限标识正则，reason 必填、≤280 字符；`ops.dead_letter_replay` 已登记 sensitive 动作名单。
- **语义**：只做**条件单行重排**（`data/deadletters.go` 的 `RequeueDeadLetter`）：行锁下仅接受「published_at 为空且 dead_letter=true」的行，重排为 dead_letter=false、attempts 归零给满 12 次退避预算、清 next_attempt_at（调度器下一拍即可取单）、清 lease_until/lease_owner（防陈旧租约）；**last_error 保留为案底**、trace/subject/payload 不动。实际投递由 outbox 调度器完成，重排不等于投递成功，再次失败仍会按租约退避退为死信——响应注记如实写明。
- **幂等与守卫**：行锁串行化并发审批，第二名审批者条件不再匹配；已重排/已投递/从未死信一律 409「不存在未投递死信」，失败与无对象同样写审计（OK=false）。留痕（dispositions）五值封闭集仍只含标注动词，replay 不混入标注语义，两接口互不可替代。
- **实测**：`go test ./app/admin/internal/gateway` 通过（新增 TestDeadLetterReplayOwnerOnlyAuditedAndIdempotent：未登录 401/viewer 403/审计关 503 且零施写/未接施写口 503/形状错误 400 且不触施写/施写失败 503+失败审计/无对象 409/成功 200+理由入审计/GET 405）。`NT_TEST_PG_PORT=55432 go test -count=1 -run "RequeueDeadLetter" ./app/admin/internal/data` 通过（1.0s，独立库 novatrader_admin_replay_test）：不存在如实 false；死行重排后 attempts/next_attempt_at/lease 清零、last_error 保留、身份字段未动；重排前不在调度器取单谓词、重排后必在；二次重排 false；已投递行拒绝复活且原状不动。`go build ./...`、`go vet ./app/admin/...`、全仓 `go test ./...` 均 exit 0。
- **仍未覆盖**：收件人（admin 本实例）之外的死信生产侧服务重放链路（trade/risk 等各自 outbox 共享同表，本端点按 event_id 重排，生产方调度器同样会拾取——已隐含覆盖，但未做多服务联合演练）；批量重放与重放后自动升级策略另议；全域因果、BRIEF/ACK 去重因果链仍未实现。

## 同日增补（2026-10-19）：全域因果覆盖口径（GET /api/ops/trace-coverage）

前节把「全域因果」标注为未实现，本批把它从感觉落成度量：持久域事件因果形状分布接口先让缺口可见，生产端续链改造以数字为准绳逐项推进（仍待补）。

- **端点**：`GET /api/ops/trace-coverage`（`gateway/coverage.go`）。只读，登录即可（与观测同权，viewer 可读）；非 GET 405；未接施读口 503「因果覆盖未启用」。窗口固定 2000 条（网关常量，data 层钳制上限 5000），窗口行数与最老一条时间随应答返回，读者知道自己在看哪一段。
- **口径**：outbox 持久域事件的因果形状——with_trace=有链号、children=带因果父（续链）、without_trace=链号为空、orphan_parents=因果父未在同一窗口持久历史中重现（行情等内存域父事件本来就不落盘，也可能在窗口外，不等于链路断裂）。「有父却丢链号」的畸形行同时计入 children 与 without_trace，如实计数不掩饰。只解码 metadata 列的合同信封副本，不读 raw business payload；只覆盖落盘域事件——market.* 与 brain.progress 按设计走内存，不在此口径；分组按 source 稳定排序。
- **意图**：生产者清单普查（2026-10-19）显示 trade/risk/backtest 与部分 datahub 已走 NewWithContext 续链，market/brain/notify/intel/datahub 多数仍 New+TraceID(ctx) 直发——链路非空与否完全取决上游 ctx 是否传链，此前无任何口径说明空链/根链/续链各占多少。本接口给出收敛度量，一改生产端就能从数字上看出来。

- **仍未覆盖**：生产端续链全域化（market/brain/notify 与 datahub 多数仍 New+ctx 直发，未逐服务改造）；跨窗口聚合与历史曲线；内存域（market.*）因果父与持久域的对应关系册；BRIEF/ACK 去重因果链。
