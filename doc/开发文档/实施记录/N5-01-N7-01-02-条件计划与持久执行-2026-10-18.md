# N5-01 / N7-01 / N7-02 条件计划与持久执行

日期：2026-10-18。状态：实现与隔离合同验证；完整故障矩阵和连续真实交易日仍未验收。当前只开放 SIM，不启用真实交易。

## 数据流与不变量

```text
strategy 的真实信号 + ConfigHead + 完整 SIM 账户 + Redis 源行情
  → trade/data PlanFacts（事务内锁定信号、配置）
  → DecisionSnapshotV1 + ConditionalPlanV1 追加版本
  → 用户选择 sim_confirm / sim_auto / revoke
  → trade Runner 每500ms检查已授权计划
  → 当前行情、账本、计划版本、信号、配置再核验
  → ExecutionIntent 固定业务键与 client_order_id
  → risk.CheckOrder(expected_config_revision)
  → 再次读取当前事实
  → 原订单、现金/持仓、意图状态与 outbox 同事务
  → 真实分钟行情触发 SIM 撮合；回报和账本继续使用原身份
```

`pkg/decision` 的快照冻结规则分、模型分、证据、反证、未知项、实际源时间、账户经济状态哈希、信号与策略/配置身份。模型正文不生成下单价或股数。计划保存入场区间、限价、止损/止盈、预算、执行日、有效期与失效条件；有效期不超过30分钟。修改生成新版本，授权与生命周期另存。

账户心跳的时间/快照代际变化不会单独作废计划；真实现金、持仓、冻结、原订单或日初基线变化会改变经济哈希并阻断旧计划。最新账户必须完整、已对账且未倒退，最新源行情需在10秒窗口内；股数受整手、费用、可卖数量及预算约束。配置保存版本和 risk 实际加载版本必须匹配。

## 并发、持久性与恢复

- `ExecutionIntent` 的业务键与原订单ID分别唯一，保存规范化请求哈希。claim 在最终风险检查前独立持久提交；重试复用原身份，同键换请求冲突。
- `TradeLedgerLock` 对所有实例的账本变更加行锁。目前使用单用户 global 锁以保证账户、计划与冻结检查原子性；持锁执行风控会增加串行等待，不能据此宣称高吞吐。
- 外层 ledger transaction 通过 data 私有 context 复用；仓储 Commit/Snapshot 不创建嵌套数据库事务。订单、意图状态、账本和 outbox 同提交。
- claim 后执行中断、事务结果不明保留 UNKNOWN，禁止另起订单。清理在外层事务结束后按原ID核对；找到实际订单则采用实际状态。
- 启动及周期恢复只核原单，不自动重报。恢复过程和撮合采用同一进程锁及跨实例 ledger 锁，防止旧 submitted 状态覆盖新 filled 状态。
- 自动计划在过期、事实/配置/账本变更或原意图不明时退出等待并记阻断原因。桌面关闭不停止服务端检查；临时行情不满足继续等待。

准入证据另见[连续运行记录](N7-03-连续运行准入证据-2026-10-18.md)。旧 `paper_days` 不再作为 LIVE 的单独通行证。`BrokerConnected` 默认 false、真实网关未接，L2/L3 不因此开放。
