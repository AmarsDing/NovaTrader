# N4-02 历史补源与 OpenBB 宏观 POC

2026-10-16。通达信官方历史包真实小范围 POC 通过；OpenBB/FRED 适配代码与离线合同已实现，真实调用受 key/隔离依赖条件阻塞。尚未把两个候选注册进生产主备链，也没有把历史终值当作 PIT 合格训练集。

## 实现与已核验版本

新增独立 `source-worker/`，标准库完成 TDX archive 解析；OpenBB 仅按需 import，可选环境与生产 pyworker 隔离。使用固定操作、固定provider URL、证券/序列白名单、响应大小/解压大小/超时上限。默认关闭，Python不直写PG，不接触交易凭据，不下载执行任何远程技能。

本次重新核验 [A-Stock-Data V3.10.2 发布格式](https://github.com/simonlin1212/a-stock-data/blob/main/SKILL.md)、[Apache-2.0](https://github.com/simonlin1212/a-stock-data/blob/main/LICENSE)，保存文档hash与适用许可文件，独立实现有界 parser。源的实际故障面是 `tdx.com.cn` 官方 HTTP，不能另计为独立于其他 TDX 通道的供应商。

OpenBB 采用 [V5 provider namespace](https://docs.openbb.co/odp/python/extensions/providers)，直接包固定 `openbb-core==2.0.0` / `openbb-fred==2.0.0`，与[provider pyproject](https://github.com/OpenBB-finance/OpenBB/blob/develop/openbb_platform/providers/fred/pyproject.toml)核验。真实宏观 provider 为 FRED；FRED key 只从服务器环境读取。只固定直接依赖，真实安装后的传递依赖 lock/环境hash尚未生成。

OpenBB [series实现](https://github.com/OpenBB-finance/OpenBB/blob/develop/openbb_platform/providers/fred/openbb_fred/models/series.py)删除 realtime_start/realtime_end，因此本 POC 不把 current-vintage 输出当作历史发布时间，保留 available_at unknown。需要另行接入有真实发布证据的 vintage 归档，才可解锁训练用途。

## OpenBB 与失败路径

真实CLI探针返回 `unavailable: server-side FRED_API_KEY is not configured`，已保存 `source-worker/evidence/openbb-probe.json`。没有申请账户/搜索密钥，也没有伪造30条FRED样本；真实运行仍需隔离依赖与服务器 key。

10项离线标准库测试通过，覆盖单位为股且不盲乘100、北交所文件边界/逐市场空结果、重复代码与价格序号、截断/非ZIP、HTTP429/404/503、OpenBB字段变化/缺数据/重复、缺key/错版本、默认关闭/禁止任意远程执行、重复冻结/内容冲突、持久化失败不发布半成品。这些故障fixture明确是合成，未当作真实供应商网络故障演练。

## 正式接入前剩余条件

- 提供真实的历史发布/修订证据；当前两个POC均未具备完整 PIT vintage。
- 正式环境审查 provider 使用条件、源优先级与字段完整度；不能用同源不同Python包冒充独立备源。
- 把经审查的只读结果经 Go datahub 领域仓储入库，并连接已有 scheduler/health/quota/breaker，避免独立worker直写数据库。
- 用更多日期核对退市证券、历史北交所覆盖、停牌恢复与公司行为；当前只是一包30样本的小范围验证。
- OpenBB真实调用与30条冻结原样本、完整传递依赖lock与资源测量均未通过，不标成已接入。

停止POC只需不启动worker（默认disabled）；不存在生产源切换、数据库回滚或交易权限变更。
