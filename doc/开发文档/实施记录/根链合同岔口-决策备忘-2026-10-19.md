## 问题

`events.New(source, subject, traceID, payload)` 的链号由调用方给；根事件（无上游链的首次生产）常传 `TraceID(ctx)`，得到的是空串。岔口：**是否让 New 在 traceID=="" 时自动发 uuid 链**？

## 现状事实（2026-10-19 实测）

- 入口开链已有首例：datahub「每次采集一链」（0caecb2f），本批其助手晋升为合同工具 `events.OpenTrace`。
- 消费缝合已落地：intel raw→scored/alert（9db7b950）、notify 直发 Handle（6d82a9c0）均走 ContextWithEnvelope，续上真实因果父。
- 「根不编链/不编父」的语义已被行为测试钉住：intel `TestProcessStitchesCausationFromParentEnvelope`（无父直发→trace 为空）、datahub `TestRunDomainOpensRunTraceForEmittedIntel`（运行根 CausationID 为空）、notify `TestDesktopPushWithoutParentKeepsNoteTrace`（Flush 触发链号不顶替行内链号）。
- 覆盖口径 `GET /api/ops/trace-coverage` 的 without_trace 桶正是本岔口的仪表盘：它度量「还有多少生产侧没串链」。本批另加了 `TestNewDoesNotInventTrace` 把「构造器不发明链」钉成更显式的合同。

## 三选项

### A：New 空链自动发链

- 利：所有事件立刻「有链」，接入方零改动。
- 代价 a：**仪表盘致残**——without_trace 恒为 0，「谁还没串链」信号被抹掉；口径可重定基线为 root/children 比，但当前端点语义、前端覆盖卡文案、任务书状态行全部要重洗。
- 代价 b：**身份诚实性**——trace=="" 的本义是「我不知道自己属于哪条链」；自动 uuid 让事件谎称有链，下游拿它当父时，整条「链」挂在一个无出处的 uuid 上，trace 查询返回一条没有源头的链。
- 代价 c：**构造器失纯**——New 从纯构造变成含随机性的工厂；上述钉测试的红线被其作者刻意推翻（翻转本身需要一次刻意评审）。
- 代价 d：九服务行为同刻翻转，无渐进窗口，故障面一次性最大化。

### B：维持现状（New 不动，各服务手写开链）

- 利：仪表盘保真，诚实语义不动。
- 代价：手工成本与长期漂移——每个服务入口各写一份等价物，尊重规则（已有链不覆盖）迟早被某个手写版弄错。

### C：合同工具 + 入口开链纪律（**推荐**）

- `events.OpenTrace(ctx)` 单点维护唯一语义：有链尊重（调用方串链、级联/回放透传）、无链开 uuid、根不编 causation。datahub 已完成接入示范（biz.OpenRunTrace → events.OpenTrace 一行委托，四个运行入口零改动）。
- New 保持纯构造；`TestNewDoesNotInventTrace` 把现状钉成合同——若日后拍板选 A，该测试的红是翻转动作本身，变更可被评审而不是静默发生。
- 仪表盘保真且可观察推进：随各服务入口逐行接入 OpenTrace，without_trace 自然收敛到 0——**收敛过程本身就是串链进展的证据**，不是被人按掉的开关。
- 代价：仍是逐服务一行接入，但语义单点维护，漂移被消灭。

## 推荐与若选 A 的执行清单

推荐 C。A 的唯一卖点（接入零成本）被 C 的「每入口一行」抵掉大半，而 A 的四个代价都不可逆或需全局重洗。

若拍板 A：翻 `events.New`；翻四处钉测试（intel 无父断言、datahub 运行根断言、notify 无父回退、新增的 TestNewDoesNotInventTrace）；覆盖口径 without_trace 桶下线并重写前端覆盖卡文案；九服务同窗口发布。

## 决策已定（2026-10-19）：选 C

**授权**：用户同日明示——「你根据系统的设计，深度分析，并帮我决策，一切为了系统好用」。准绳按此定义拆出：系统好用 = 展示给操作者的每个数字都可信；美容数字恰恰是「不好用」的本体。

**拍定 C 的依据**：

1. **A 正撞两条房规**。CLAUDE.md 决策链的「未知不得编」精神（决策 1：未知不是 0；决策 3：大模型不直接下单的同源逻辑——不让系统替现实发言）与运行纪律「不用 0 或绿色健康补齐未覆盖项」：给未知出处的根事件铸造 uuid，是 0 填充的换形——把「我不知道属于哪条链」涂改成「有一条链」，而那条链没有源头。
2. **A 对真目标零推进、且致残唯一的推进度量**。N2-02 验收要的是真实因果链；自动 uuid 不创造任何一跳真实因果，反而把 `without_trace` 桶恒抹成 0——缺口信号全灭，剩下八服务「还有多少没串链」从此不可见。C 的 without_trace 自然收敛过程本身就是进度证据。
3. **C 的代价可消化且语义单点**。逐服务一行接入，漂移被消灭（B 的死因）；地基（OpenTrace + 两枚钉测试）已落，datahub 接入示范已绿。九服务同刻翻转（A 的代价 d）不存在任何必要。

**执行口径**：各服务根入口按 C 逐批铺开——datahub（0caecb2f/50839b4c）→ strategy 扫描双入口（本批，scan/exit 的手搓等价物收编为 OpenTrace 单行委托 + 两枚集成钉）→ market/brain/notify 随各工作区归属逐批。`TestNewDoesNotInventTrace` 继续钉住 New 的纯构造合同。
