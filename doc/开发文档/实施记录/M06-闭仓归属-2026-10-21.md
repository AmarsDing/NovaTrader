## 1. 合同

### 1.1 名词

- **pair** = (book, symbol)。
- **窗口（零交叉窗口）**：以 `trade_fill` ent 自增 id 全序重放 pair 账本，维护累计库存 Q（买入加、卖出减，匿名 fill 一体计入）；Q 自 >0 归至 ==0 的那笔 fill 划出一个窗口。窗口 = 上一零交叉（不含）至本零交叉（含）。窗口内 Σ卖 qty == Σ买 qty（零交叉结构性成立）。
- **批次**：窗口内买 fill 按 signal_id 归集成的 FIFO 队列；signal_id 为空或指向非本窗口候选信号的买入 = **外来批**（占库存、参与 FIFO 排序、永不产出闭仓结果）。
- **候选信号**：status=done ∧ side=buy ∧ executed_volume IS NOT NULL ∧ executed_volume > 0 ∧ book = 本服务配置 book（首期 paper）。

### 1.2 归属方程（谁该 closed）

窗口内全部买入批次按 fill 时间序排 FIFO；窗口内全部卖出按时间序向批队头分摊：

1. 分摊覆盖到某候选信号的批次，且摊给它的量 == 该信号**窗口内**买入 Σqty（账本自证的应闭量）→ 该信号于本窗口闭仓。
2. 窗口结束时批队头有残余（批次未卖完）→ 该批次所属信号本窗口**不闭**，残余库存滚入下一窗口。
3. 卖出推进时批队已空（卖超）→ 数据矛盾：整 pair loud Error + 冷却，任何信号不迁。
4. 同 pair 一次重放可产出多个闭仓结果（多轮回窗口内各信号独立判定）。

**「谁该 closed」与分摊顺序无关**：窗口内 Σ卖==Σ买 保证归属结论唯一；FIFO 只用于把窗口卖出按时间序拆到各批次以计算每信号均价与净 pnl。

### 1.3 四道门（任一不过绝不迁，宁缺毋伪造）

- **Gate-B 归属证据门**（对比基准 = 信号**全部**名下 buy fill，不限窗口）：
  - Σqty < ExecutedVolume → 投影滞后/在途，本轮静默跳过（下轮自愈）。
  - Σqty == ExecutedVolume → 通过。
  - Σqty > ExecutedVolume → 结构不可达（EV 是全量投影上界）；防御分支同「<」处理并 Warnf。
  - 任一 buy fill 的 signal_id 解析失败或脏关联 → 该 fill 不计入该信号（外来批处理）。
- **Gate-D 残余意图门**：候选信号存在未决执行意图（business_key = `signal:<BOOK>:default:<id>` 或 PlanIDIn，state ∈ {claimed, unknown}，原语 `data/execution.go` unresolvedSignalIntent 现成）→ 本轮跳过，不冷却。
- **库存恒等门**：FIFO 卖超 / 窗口内 Σ卖≠Σ买（防御性复核）/ fills 读取超限截断 → 整 pair loud Errorf + 进程内冷却 10 分钟。冷却期内跳过评估、保留周期计数；冷却过期自动重试（迟到成交/投影回补可自愈，不永久拉黑）。
- **CAS 状态门**（现成）：写时 `ForUpdate` + `WHERE status='done'` 条件更新 + closePatch（买入限定、ExitPrice>0；**+Inf 由 planner 显式断言拒绝**——`biz/signal.go:224` 只挡 NaN 不挡 +Inf，此洞在 planner 侧堵死，不改既有文件语义）。

### 1.4 口径（冻结）

- **exit_price = 毛口径**（对称 executed_price）：归属于该信号的卖出 Σamount / Σqty，`math.Round(x*10000)/10000`，numeric(12,4)。
- **pnl_pct = 净口径扣双边实费**：`(Σ卖(amount−fee) − Σ买(amount+fee)) / Σ买(amount+fee) × 100`；费用一律取 `trade_fill.fee` 持久化值（ashare.DefaultFee 写库值：佣金万2.5最低5元、卖出印花万5、过户万0.1、取整到分），**不复刻费率常数再算**（避免费率双轨漂移）；符号按未舍入值判定（保护 M04 win/loss/flat 不被舍入翻转），再 round 4 位。
- **closed_at** = 该信号**最后一笔归属卖 fill 的 `trade_fill.created_at`** —— 即 trade 进程提交入库时刻的进程墙钟（ent `Default(time.Now)`，repo 从不 SetCreatedAt，引擎钟入库时被丢弃）。承重属性是**确定性**（重放恒定），不是物理真实成交时刻。
  - **SIM 回放伪影（如实登记）**：sim_bar_cursor 逐 bar 回放场景下 fill 行 created_at ≈ 回放当下墙钟而非 bar 时 → `holding_days` 被系统性压到贴近 1。属账本时钟继承属性，本批不改代码；复盘读取案例时按此口径解读。
- **holding_days**：一律由 `closePatch` 按交易日历自算（`uc.holdDays(cur.TradeDate, tradeDay(at))`），任何外部传入值拒收（现成不变量，planner 不出此字段）。
- **恒等式（验收与测试钉）**：同一窗口内各信号净 pnl 合计 + 外来批净 pnl，与账户**现金/权益窗口增量**恒等；与账户 RealizedPnL（只扣卖费）差 Σ买入费区间——两者非同一口径，测试各按各的正确口径钉，禁止混用。

### 1.5 写径与证据

- **唯一写径**（R2）：core 编排 → `biz.planClosure` 纯函数 → `uc.Transition(ctx, id, StatusClosed, reason, ActorTrade, &Close{ExitPrice, PnlPct, At})`。
  - `ErrConflict` / `ErrExecutionProtected` = 竞态正常结局，下轮重来（ExpireDue 跳过先例）；facts 无锁读 + Transition 内部 CAS 构成 TOCTOU 安全网，无错写可能。
  - `data` 层新增的只有**读方法**；closed 写入零新增路径。
- **证据载体**：`signal_events.reason`（field.Text 无界）= 中文前缀「闭仓归并」+ 紧凑 JSON：
  `{v:1, window:[首fillID,末fillID], signal_id, qty, buy_amount, buy_fee, sell_amount, sell_fee, exit_price, pnl_pct, closed_fill_id, replay_head}`，其中 buys/sells 全量 fill id 列表在 ≤4KB 时全量携带、超限降级为区间摘要——**JSON 键一个不少**（值降级而非键消失）。
  - 与条件更新 + outbox 同一事务三件套提交（`data/signal.go:128-178` 现成）。
  - 本 JSON 格式在本文冻结；M06 设计文档 §7 回写指向本件。
- **M04 消费零改动**：closed 载荷四字段（exit_price/pnl_pct/holding_days/closed_at）json tag 早备；protojson DiscardUnknown + kb_case (book,signal_id) 唯一键幂等现成。

## 2. 评审裁决与弃项

### 2.1 采纳与弃项

- 采纳 C：零交叉窗口归属模型 + 「账本推导而非事件声明」原则。
- 弃 B 的 RPC/服务跨界：F8 直读同库先例足够，RPC 引入新边界无收益；其 deferred-excess 规则被恢复棱镜证伪（外来库存错配恒为不可修正终态坏数据）→ 转为本件库存恒等门。
- 弃 A 的「零窗口」门（当前 positions 行==0）：同 bar 卖 T+1 再买回时当前行>0 会错误否决已归零窗口的归属——零交叉窗口门取代之（A 的真正资产是骨架与 Gate-D 教训，均已收编）。

### 2.2 事件 trade.position.zeroed：严格后置增量

- 判定：事件只买秒级时延 + causation 谱系；M04 案例按日构建，对 10s 级归属时延无感；成本是 trade 唯一成交生产函数（fillWithPool 卖支）热路径改动 + 新主题/新消费者。
- 处置：**首期纯扫描**。core 评估入口以 (book, symbol) 为参、归属逻辑与唤醒源解耦，未来接入事件唤醒不改任何归属代码；届时按 M09 契约册新增条目走完整评审。JetStream MaxAge=7d 的停机超期场景本就由扫描兜底，事件缺失不损正确性。

### 2.3 代价棱镜弱点收编

页内 pair 去重（§1.6 写死）；closed_at 措辞与 SIM 伪影（§1.4 入合同）；脏 pair 常驻成本（§1.3 冷却 + §4.2 SOP）；追单竞态（§4.1 登记不暗改）。

## 4. 已知竞态登记与 SOP

### 4.1 追单僵尸竞态（登记，不暗改）

- 场景：N7 允许 executing/done 信号有限追单（trade signal_validation.go 允许 + engine go 后续 bar 可成交陈年 working 单）。追单 fill 在零交叉**之后**入库、投影环尚未纠正 EV 的窗口期（≤10s 级）内，close 评估会看到 Σqty > EV。
- 定稿口径下的结局：Gate-B「> EV」分支跳过本轮并 Warnf；投影环（executionLoop 常驻，覆盖终态迟到纠正）把 EV 纠正后下轮正常归属。零交叉后的追单批量属**下一窗口**外来批，不污染本窗口归属。
- 残余暴露：若追单 fill 落在已 closed 信号名下（race 另一侧），该 fill 在后续窗口作外来批处理，M04 不产生其案例——仓位仍有 pair 级盯盘守护（risk.exit 对级语义），不裸奔。
- 处置：**登记 + 探测 + SOP，不改 trade**。护栏建议（BoundSignal 对零交叉后 pair 的 done 信号拒追单/或要求追单前等投影收敛）立项移交 trade 属主，不在本批暗改。
- 探测：Σqty>EV 分支 Warnf 计数；同一信号超配持续 >2 分钟升 Errorf，即为人工介入信号。

### 4.2 人工归属 SOP（运维）

触发：strategy 日志出现 `[closure]` 前缀的库存恒等门 Errorf，或超配持续升级 Errorf。
1. `SELECT id, signal_id, side, qty, price, amount, fee, created_at FROM trade_fill WHERE book=$1 AND symbol=$2 ORDER BY id;` 人工核账。
2. 对照 `trade_signal` 候选行 executed_volume 与窗口重放，判定矛盾类型（追单滞后/外来手工批/数据脏）。
3. 投影滞后型：等 1–2 个 tick 自愈，无需动作；冷却 10 分钟后自动重试。
4. 无法自愈型：按账本人工修正（冲正误单 / 修正信号量），禁止人工直写 closed —— closed 只能由归并环带着完整证据 JSON 迁入（R2/R3）。
5. 期间 M04 不会收到该信号案例（无虚假数据产出），属「正确缺席」。

### 4.3 TOCTOU 认账

facts 无锁读 → plan → Transition CAS：中间漂移只会导致 ErrConflict 本轮放弃，无错写路径；效率损失可忽略。

## 6. 增补丁（2026-10-21 实现批，效力同 §1）

合同序言约定「合同未定义的取值，禁止在实施中发明——先回本件补条款」。以下为实现批产出并经逐项裁决注册的解释项：

1. **replay_head 语义**：本次重放消费到的最大 fill id（= 该次 `ClosureFacts.Fills` 末行 id），同一 pair 一次重放产出的全部 plan 共享，语义为「决策时刻的账本尾部见证」；非窗口末 fill id。
2. **符号保全（§1.4 续条）**：`pnl = round4(raw)`；当 pnl==0 且 raw≠0，夹取 `math.Copysign(0.0001, raw)`（最小非零刻度），保证 M04 win/loss/flat 分类不被舍入翻转。
3. **reason 前缀形态**：「闭仓归并 」+ 一个半角空格，再接紧凑 JSON。
4. **>4KB 降级形态**：buys/sells 两键值换 `{first,last,count}` 区间摘要；14 键一个不少。
5. **信号行读取上限**：pair 候选信号行 Limit 1001、>1000 显式报错，与 fills LIMIT 20001 同属 §1.3「读取超限截断」物种，统一 `ErrClosureIdentityGate` 哨兵包装进恒等门分流。
6. **账本行级校验**（validClosureFill，恒等门前置）：side∈{buy,sell}、id>0、qty>0、price>0 有限、amount>0 有限且 |amount−price×qty|≤0.02、fee≥0 有限。0.02 容差钉在 paper 引擎不变量（2dp 价、amount=price×qty 精确入库）之上；LIVE 开放时随 §1.7 一并重审此容差与全部口径。
7. **同信号跨两窗口**：一次重放按窗口序产出多条 plan 时逐条 Transition；首条落库后次条面对终态得 `ErrBadTransition`——属竞态正常结局，跳过不失败，候选谓语下轮自动出清。
8. **良性写径错误集**（§1.5 续条）：`ErrConflict` / `ErrExecutionProtected` / `ErrBadTransition` 三者均跳过不失败。
