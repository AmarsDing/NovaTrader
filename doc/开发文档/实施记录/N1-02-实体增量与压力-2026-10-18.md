# N1-02 实体增量与压力（2026-10-18）

任务 N1-02「共享store与按键合并」剩余项：实体增量与压力。本批把账户域从「推送只当提示、逐帧全量 REST」升级为「完整账户快照推送按实体版本直接增量应用」，并补齐隐藏页降频与压力化验证。行情按证券键合并属另一会话的 G1 报价渲染管线（ws/data-frame.ts、utils/quote-flash.ts），本批不动，避免撞车。

## 合同与变更文件

- **输入**：position 主题推送。已核实后端 `SubjectTradeAccount` 载荷 = `pkg/accountstate.Snapshot`（完整账户态：cash/frozen/equity/available/day_start、逐项 holdings、open_orders、对账状态），信封 `entity_id=SIM:default`、`entity_version=generation`，两条实现路径（`data/repo.go` outbox、`biz/mem.go`）形状一致。REST `Account.cash` 与推送 `cash` 同口径（`biz/snapshot.go` 同一 `cash.Cash` 喂两边）。
- **新增 `web/src/api/account-push.ts`**：纯解析。载荷必须 version=1/kind=full/account_id=default/账本合法/载荷 generation === entity_version/as_of 不来自未来（容 5s）/holdings 行完整；任一不满足返回 null。推导 unrealized=Σ(市值−成本×数量)（与后端 AccountView 同口径）、dayPnl=equity−日初权益（day_start 未知给 null，不拿 0 顶）、lastPrice=市值/数量（与估值同源，不引入第二来源）。
- **`web/src/stores/account.ts`**：新增 `applyPush(payload, metadata)`。实体版本单调递增才落（旧版本/重放不改状态但也算已消化，不回退 REST）；账本不符或解析失败返回 false 由调用方整域回退。REST 仍独占 realized/paperDays/openHalted/haltReason（推送不含）；REST 的 dayPnl 为 null 时不再清掉推送口径。换账本重置实体版本。
- **慢响应栅栏**：refresh 起步时记 `applications` 计数，飞行期间落了新推送（pushWon）则 REST 只补其独有字段，equity/cash/positions/unrealized/accountOk/checkedAt 保留推送口径——慢响应不得在实体层面回写新状态（验收口径「慢响应不覆盖新账户/证券」）。
- **`web/src/workspace/connection-watchdog.ts`**：position 推送先走 applyPush；消化成功只按原语义刷订单/成交+风控（载荷不含这两个域，「风险/独立订单保留语义」），失败才整域回退五连刷。新增隐藏页轮询降频（可见 10s/隐藏 60s，可注入参数）：WS 推送与恢复链路不随降频变化，隐藏页告警照常走推送权威刷新。
