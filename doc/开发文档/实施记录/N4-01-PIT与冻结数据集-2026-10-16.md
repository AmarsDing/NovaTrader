# N4-01 PIT 与冻结数据集实施记录

2026-10-16。代码与隔离闭环已实现；真实上游的历史发布时间、退市/停牌/除权全量对拍仍依赖资料，不能据此宣称真实历史训练集已就绪。

## 数据流与合同

`pyworker/供应商 → datahub biz.Availability → data.Repo transaction → current view + DatasetRecord + outbox → backtest FreezeDataset → DatasetManifest → Task.Spec(manifest_id/hash) → OpenDataset → Go 回测/自检/优化 → provenance report`。

- 共享 `dataset_record` 仅追加修订，唯一 `revision_hash`；`dataset_manifest` 仅创建与读取，无更新入口，ent 字段均 immutable。兼容当前展示表的 upsert，研究不再依赖这些可变行。
- `event_time`、`available_at` 和 `observed_at` 分开。`available_at` 没有实际上游证据就为 null/unknown，财报报告期、宏观所属月、采集时刻、证券上市日和成分 in_date 都不能替代发布时刻。已知发布时间必须附 `availability_evidence`，晚于采集时刻拒绝。
- datahub 同事务捕获证券快照、未复权 K 线、复权因子、财务、宏观和板块成分修订。重复采集相同内容不增修订；财务/宏观 current view 被覆盖时，已捕获的旧研究版本保留。
- 存量行情、证券、名称史、财务、宏观和板块成员可重入回填为 unknown。unknown 不会混入训练/回测，排除原因与修订身份进入 manifest。
- ManifestV1 固定截止时刻、区间、频率、交易日历、已知证券池、全部可见修订、通用排除与回测排除原因。`At(t)` 仅选 t 时已发布的最新版本，修正不回写旧判断。
- `raw_hash_kind=canonical_normalized_payload_sha256` 明确目前保存的是规范化业务载荷 hash，**没有冒充已保存上游 HTTP 原始字节**。HTTP raw_response 仍属原采集留存功能，精确供应商原始响应与记录的逐行映射尚需后续补齐。
- hash 对键排序、数字精确十进制规范化，保留大整数；事件元数据采用 UTC 微秒，防 PostgreSQL JSONB 键序/数值表示与时间精度改变 hash。仓库有真实 Go 导出跨语言 fixture：`backend/pkg/dataset/testdata/manifest_v1.json`。

## 回测资格与兼容

新任务在排队前固定 manifest。可指定已冻结 `manifest_id`；服务核频率、区间/回看期与 hash。重跑沿用原 manifest，执行不再读 market_data。没有 manifest 的存量排队任务明确失败并要求重建，避免悄悄改用当前数据。

回放只用 K 线走完时已知的原始版本。证券名称/ST/上市退市/停牌及当日复权因子必须在 09:25 前有已知证据；缺失显式排除。晚到修订被保存供后续研究，但不替换当时回放的价格。基准指数不作为可交易证券加入股票池。此版是保守资格策略，尚未实现延迟行情到达后逐时更新历史 bar 的复杂回放。

盘前未知证券/因子不能按非 ST、默认因子 1 或默认在市补齐。没有合格 A 股数据会使任务失败。旧行情仍可供当前展示，对历史研究是否可用由 manifest 的资格判断。

现版本设置 250,000 条记录与 16 MiB 规范化对象的内存安全上限，超过明确拒绝、要求缩小区间/离线分片，绝不截断后当完整。大型分钟历史的自动分片与流式导出尚未实现。

## API

- `POST /api/backtest/datasets`，转发 `/v1/backtest/datasets`，输入 `{config:{strategy,freq,start,end,history_bars,...}}`，服务器冻结，不允许客户端伪造截止钟。
- `GET /api/backtest/datasets/{manifest_id}` 导出已冻结内容。
- `POST /api/backtest/tasks` 新增 optional `manifest_id`；为空先冻结再排队。
- DatasetReply 返回 `manifest_id/hash/manifest_json/record_count/excluded_count`。`manifest_json` 是精确 JSON 字符串；不能通过 protobuf.Struct 或 JavaScript number 往返原始数值，否则可能破坏大整数与 hash。
- API 访问继续由 admin 原有 backtest Owner 写入/审计与读取权限控制；上游服务端口按既有本机/内网部署。

## 已验证

实际在隔离 PostgreSQL 55432、专用 `novatrader_dataset_capture_test` / `novatrader_dataset_replay_test` 库执行；没有连接真实账户账本。

- 发布日晚于报告期：公布前不可见；宏观/财务修订在发布后才替代旧版本；缺发布时间有可查排除理由。
- 同样输入乱序/重复冻结结果一致；篡改载荷无法通过 Verify；JSONB 键序/空白、指数与小数尾零、超 2^53 整数和微秒往返不损失身份。
- `TestDatasetRevisionCurrentViewAndOutboxTransaction`：真实 Repo 重复采集仅一修订、后修订追加；在 current view 写入阶段故障时，新修订与 outbox 同事务回滚，旧 current view 保持。
- `TestPostgresFreezeQueueReplayImmutable`：真实 ent 数据 → 生产 Usecase 排队冻结 → Go 引擎执行 → 修改可变 market_data → 原任务重跑；manifest 身份、DataHash 和 FillsHash 一致，报告显示“复现一致”。
- 合成证券历史验证停牌、退市、盘前复权未知、晚修订不会进入错误回放；这些是合同 fixture，未当作真实市场对拍。
- API 通过 protojson 往返后，manifest_json 保持原 hash 与大整数精度。

发现并修复：PostgreSQL 单条 `ON CONFLICT DO NOTHING` 无返回 ID 时 ent 返回 `sql.ErrNoRows`，原先会把重复采集误判失败；仅内容寻址 no-op 的这个分支视为成功，不吞其他 SQL 错误。

## 外部依赖与后续

现有上游多数只提供历史终值和公告日期，没有可证明精确 `available_at`；适配层保持 unknown，已有可变历史不会自动变成合格 PIT 数据。必须接入供应商原发布时间/版本档案或审查明确的时间精度政策，再开启对应研究资格。

真实已退市池、历史暂停/恢复、公司行动多源对拍；供应商原始响应逐行 hash 映射；分钟数据自动分片与高负荷测量仍待完成。N4-02 后续已完成通达信一包30条真实样本POC，OpenBB受key/隔离依赖阻塞，见 [源POC记录](N4-02-历史与宏观源POC-2026-10-16.md)，没有因此放开训练资格。

最终检查：相关 PIT/PG/API 的 `go test -race` 子包均 PASS；首次整条命令的隐含vet遇到另一任务同时生成共享ent的中间态（undefined outbox.FieldLeaseUntil），未将这次整体exit1算通过。共享生成稳定后，对 `pkg/dataset`、`pkg/backtest`、`app/backtest/...`、`app/datahub/...` 的 `go vet` 及两服务 `go build` 均成功。执行使用临时可写GOCACHE，不改生产配置。

回滚：停止创建新研究任务，保留追加表与已冻结工件；旧 current view 展示不受影响。不删除数据、不手写回滚 SQL、不把既有 PIT 任务改回可变读取。
