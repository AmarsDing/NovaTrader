# N8-01/02 隔离文件单网关实施记录

2026-10-17。本次完成独立 Python 运输/回报/对账代码、隔离协议模拟器、mTLS JSON 接口及 Go 调用口和故障验证。N8 整体仍为“隔离实现完成、真实终端与业务回报集成待验收”，不代表实盘通道可用、连续日准入通过或自动交易授权。

## 官方合同核验与修正

核验 [官方文件单指南](https://emquant.18.cn/file-help/doc/file_order/scanner_v2.html) 与 [CSV 接入规范](https://emquant.18.cn/file-help/doc/file_order/scanner_v2_csv_guide.html)，检索于2026-10-16。现有代码/设计把 `.fin` 当提交触发点，已修正：新增或改变 CSV 就可能被扫描，`.fin` 只表示不再追加及允许清理。完整内容须在扫单目录外写完和 fsync，再一次发布。

合同保存在 `broker-gw/protocol-manifest.json`。只实现文档明确的沪深股票限价、买卖和撤单、七种委托状态及成交/撤单拒绝两种执行回报；北交所、基金/债券专属规则及真实终端列/编码未凭推测补齐。机器规范与测试不会把官方文档核验当作实际终端验收。

## 真实调用链与所有权

隔离 CLI 或 Go `pkg/brokerif/remote` → HTTPS/mTLS JSON（proto-first合同 `api/broker/v1/gateway.proto`）→ Python `Gateway` → `Storage` 原子占用/发布 → `input/*.csv` → 独立 `Simulator` → `output/<account>/` 五种 CSV → `reader` 稳定读取/去重/版本化 → Query / Reconcile。

生产 trade 仍未接此出口。网关只持有运输 spool 和文件证据，不建立业务订单库，不调用 PG、不保存交易密码。账户/订单/成交真值仍归 trade PostgreSQL；不绕开 root 新增的 BrokerConnected 默认关闭、risk 最终检查和计划资格限制。

## 已交付

- 仅可初始化空隔离根目录；拒绝非标记根、UNC、符号链接/junction、非法身份/账户、NaN/Inf、错误金额/数量/价格精度。
- account+kind+sid/request_id 永久占用，完整 fsync 后无覆盖硬链接发布，终端清理后同 sid 也不重写。占用后任何不确定状态保留 UNKNOWN；只重试 Windows 元数据 replace 的短暂共享冲突，不重试 CSV 发布。
- 覆盖文件一致性检测、追加文件完整行边界、严格头与枚举、缺失不当零、重复/矛盾回报、晚成交/撤单竞争、身份/累计数量/金额对账。当前以完整前缀重放，文件限额超出即阻塞，归档和持久消费游标未冒充完成。
- 协议模拟器验证 `.fin` 尚未存在也能扫描完整 CSV。模拟器只用于运输协议，不包含费用/完整交易所规则。
- 显式启动的 mTLS 服务，CA和客户端证书指纹双重校验、固定账户/协议、请求限制、受限线程数/超时。Go 端校验 CA/SAN，禁重定向，不提供跳过 TLS；不会把发布回执转换成旧 Adapter 的下单成功。
- `emfile` 旧工具同样修复半写、文件名碰撞、价格非有限数、未验证北交所前缀、清理后重复发布和并发身份处理。

## 待验收项

后续接线必须先落持久意图再调运输端口，超时核原sid；回报按账户/sid/exec_id及status_version事务去重；UNKNOWN与账差不恢复开仓；撤单确认后重算剩余，不能把文件发布当撤单成功。不得仅凭本次代码或测试将 BrokerConnected、实盘准入或L3打开。
