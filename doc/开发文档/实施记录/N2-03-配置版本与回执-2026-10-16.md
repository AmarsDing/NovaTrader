## 真实调用链

ConfigCenter / 监控节点配置抽屉 → admin `/api/config`、`/api/config/preview`、`/api/config/rollback` → admin data `AuditStore` → `pkg/params` → 共享 PostgreSQL `config_heads` + `strategy_config` + `strategy_version`。读固定不可变版本，写在同一事务内CAS更新singleton head后保存值与新版本，回滚也生成新版本。没有新数据库、裸SQL或第二条消息总线。

加载链：

- `app.*`：现有datahub/brain/intel/notify实际业务读点 → `appcfg` 5秒缓存 → 同一不可变快照 → `config_receipts` 的 `cache_loaded`。只说明服务配置缓存加载，不能证明模型/provider连通或任务成功。
- `m06.*`：strategy扫描的 `loadParams` 从单次版本快照解析参数，与该次扫描版本一致；成功记录 `strategy/scan/applied`，非法记录failed，不给默认回退贴上该版本。
- `market.*`：Warmup读取完整版本并校验，在行情引擎安装后写 `market/warmup/applied`。盘中保存不强制热换；预热失败保留原运行态。
- `risk.*`：现有3秒轮询及旧参数更新完成后，读取全量版本、完整解析、原子安装，再写 `risk/risk_engine/applied`。错误保留旧加载版本并设置 `config_ready=false`；下次成功读取和回执后恢复。StateReply增加 `config_revision` 与显式可空 `config_ready`；桌面不因mode仍为L1而假称已就绪。

## 接口与失败语义

新增手写 `api/admin/v1/config.proto` 并通过项目protoc工具生成Go/HTTP/gRPC合同；HTTP沿用Gate聚合入口。GET保持 `values` 兼容且增加schema_version/revision/secret_set/receipts/history/target_services/ETag。新版保存、预览与回滚都要求 `base_revision`；旧PUT可用If-Match，省略两者返回428，过期版本返回409，不自动重试覆盖。旧risk参数API也必须带base_revision，由服务层与同一CAS存储校验。

参数白名单与类型/整数/有限数/范围、JSON未知字段和上下界校验在后端执行。普通配置入口只能关闭实盘准入，不能凭配置布尔开实盘权限。秘密值只可设置/替换/清除，不进入GET、preview、history、receipt或审计详情；preview仅显示“已设置/设置新值/清除”。清除删除覆盖值，由已登记加载点回到原配置文件/环境变量或代码默认值。数据库中的秘密仍沿用原存储方式，未声称新增静态加密设施。

preview列出真实变更键、登记服务、生效时机和配置版本对旧计划资格的影响；收益、信号数量、在途任务和外部连通性明确“未测”，不返回零影响。风险与计划读取方可通过 `params.CurrentRevision` / `params.Read` 绑定当前配置版本。计划资格实际复检由N5/N7执行链实现，配置服务自身不执行或修改订单。

回执按服务/进程instance/读取scope区分，旧进程回执不会冒充重启后的新进程。更旧revision的迟到回执不能覆盖新加载版本。界面展示保存版本、加载版本、时间、失败或缺回执；没有回执不推定离线或成功。全局版本登记七个实际读取服务，清除最后一个覆盖键仍等待对应服务读取默认值。

ConfigCenter先预览再确认保存；修改草稿、切分类会使旧预览失效。其他窗口变更不覆盖当前草稿；刷新回执不能给旧草稿换上新base_revision。监控配置抽屉同样有预览、版本、回执与重新读取入口，保留原画布。秘密不回填输入框；ConfigCenter提供显式清除覆盖按钮。回滚先预览历史差异，再保存新版本。

## 运维与兼容

共享ent追加两表，既有版本保留；第一次读取建立head指向原active版本。所有旧params写方法统一走CAS，不通过重新激活旧版本回滚。代码回滚应先停止配置写入口并恢复上个应用版本；不要删除配置历史或手工执行回滚SQL。服务加载失败时保留证据和最后版本，修正后保存新版本再观察实际回执。

外部待验收：实际多主机断连/服务重启、长期配置缓存行为、真实模型/provider错误与完整视觉矩阵。缓存回执不代替外部探针；服务未运行时界面持续展示尚无回执。这些场景没有伪造通过证据。
