## 1. 通达信是什么

通达信是深圳市财富趋势科技股份有限公司的行情终端，不是另一款叫「通信达」的软件。本模块只用它的行情与本地数据。交易通道固定为 M09 的东财文件单。

官方入口：软件下载 https://www.tdx.com.cn/soft.html ；量化文档 https://help.tdx.com.cn/quant/ 。

## 2. 三种接法

| 接法 | 源名 | 跑在哪 | 依赖 | 适合 | 不适合 |
|------|------|--------|------|------|--------|
| A. 官方本地接口 | `tdx_local` | Windows pyworker | 客户端已登录。新版 `PYPlugins` 里的 `tqcenter` / `TPythClient.dll` | 实时快照、五档。这是默认主源 | Linux DGX；本机 V7.73 正式版没有插件时返回 503 `unavailable` |
| B. 本地 vipdoc | `tdx_file` | 读安装目录 | 用户做过「盘后数据下载」。日线 `vipdoc/sh\|sz\|bj/lday/*.day`，分钟 `.lc1/.lc5`，板块 `T0002/hq_cache/block_zs.dat` 等 | 收盘后增量入库、与 Tushare 对账、回测喂数 | 盘中 3 秒快照 |
| C. TCP 7709 | `tdx_tcp` | Windows 或 Linux pyworker | 连接行情主站 7709。实现用 mootdx | 客户端没开时的备源 | 社区逆向协议。`official=false`。禁止下单 |

接法 A 的调用约束：

- 必须先连上已经打开的客户端。连不上 → HTTP 503，reason 写清「客户端未启动」或「未安装 PYPlugins」。
- K 线读的是客户端已下载的本地数据；没下载就报 stale。
- 价格元，成交量手，成交额万元；pyworker 换成股和元再返回。
- 代码 `600519.SH`。与东财文件单 `SHSE.600519` 的转换只在 `pkg/symbol`。

分钟线：通达信文件标签是**结束时间**（09:31 表示 09:30–09:31）。入库前减 1 分钟，与 M02 的开始时间口径一致。每天 240 根：09:30–11:29、13:00–14:59。

## 4. 适配器流水线

```
registry → quota → breaker → fetch → validate → upsert → publish
```

限频在每个源的 HTTP 客户端上，按单次请求计。

### 4.0 东财节流收口（P3-9，2026-10-19）

东财全部请求走 Go datahub 单一出口（`data/eastmoney.go` → `data/httpc.go` 的 `do()`）；pyworker 与 source-worker 已无东财调用（N4-02 后确认），收口落点唯一。

- **节奏**：QPS 默认 4（gap 250ms，低于实测阈值 >5/s）+ 并发上限 4（<10）+ 长连接复用（`MaxIdleConnsPerHost=并发×2`、`IdleConnTimeout=90s`）。实测 `push2` 3 秒约 190 次即被重置连接（eastmoney.go 头注）。
- **随机抖动**：固定节奏仍存在同步连发（多个域同时到令牌）；`Limiter` 令牌后再加 `[0, gap/2)` 随机延迟（`HTTPOptions.JitterGap`，东财默认开）打散。
- **失败退避**：403/429（疑似限流/封禁）、5xx、网络错误（连接重置/EOF）退避重试至多 2 次（`HTTPOptions.Retries`，东财默认 2）；基准 1s/2s 指数，throttled 再乘 4（4s/8s）。重试同样消耗 QPS 令牌。400 等非限流 4xx 与 ctx 取消/超时不重试。
- **封禁可见性**（「没取到≠静默」）：403/429 的 `httpError.Error()` 消息以行首「【疑似限流/封禁】」打标（「说明」列 nowrap、横向滚动，行首一眼可辨），`healthBook.record` 截 500 字符写入 `source_health.last_error`，数据源治理面板原样可见，不新增 state。
- **源优先级原则**：通达信/pyworker 能拿的域（security、daily_bar、snapshot 等）东财排名始终靠后（第三备起）；flash/news/report/hot_rank/sector_quote/limit_pool/unlock 无 tdx 等价源才把东财当主源。属既有 registry 配置，本次未改。

- 断路器：连续失败 3 次打开，冷却 60s 后放一次半开探测；成功回切并告警 `info`，主源断开告警 `error`。
- `ErrUnsupported` 不计失败（例如 AkShare 拒绝全市场分钟线）。
- `UnavailableError` 计入失败，健康状态显示 `unavailable`。
- `StaleError` 计入失败并写 `data_quality_issue(check_name=stale)`，禁止把旧数据当最新。
- 写入用业务主键 upsert。落库与 `md.<域>.ready` 同一事务进 outbox。
- 非官方源有独立 `enabled`；`allow_unofficial=false` 时全部跳过。

## 7. 推送帧合同（快照 meta / bar / 异动 / WS 包络）

2026-10-19 立档（参考-tradingview P2-14）。本节是跨服务推送面的唯一来源：datahub / market 产出 → NATS → admin 网关 hub → WS → 前端；§6 只列 datahub 自发主题，Redis 快照本体格式见 M02 设计文档 §1。**WS 推送帧未走 proto**（proto-first 例外现状，proto 化见 §7.9）。

### 7.1 今天真正到前端的行情帧只有两类

| topic / event | NATS 主题 | 载荷 |
|----|----|----|
| market / market | `market.snapshot` | 快照批次 meta 六键（§7.3） |
| alert / move | `market.alert` | 个股异动帧（§7.5） |

`market.bar.1m` 已产未路由（§7.4，待用管线）；tick/quote 只是 hub 合流白名单里的预留帧类名，全仓无生产者，不能按「既有 tick 帧」理解。

### 7.2 WS 包络（admin:2003 → 前端）

| 键 | 口径 |
|----|----|
| `topic`（旧名 `e`） | 前端取 `topic \|\| e`（hub.ts:344）；无顶层 `kind` 键，帧题材在 `metadata.subject`（hub.go:243-246） |
| `data`（旧名 `payload`/`d`） | 服务端同源双写，前端读序 `data ?? payload ?? d`（hub.go:670-686；hub.ts:373） |
| `topic_seq`（旧名 `seq`） | 正整数安全值；前端 `n<=last` 去重弃帧、`n!==last+1` 缺口强制 resync、按主题顺序派发（hub.ts:348-416） |
| `server_epoch` | hub 进程 uuid；变更即作废序号游标与重放缓冲（hub.ts:310-316） |
| `request_id` / 控制帧 | `sub_ack` / `resync_required` / `resync_ack`，均带 epoch + request_id |
| `metadata` | 事件信封除 payload 外全字段 + `gateway_received_at`；`schema_version/event_id/trace_id/time/source/subject` 恒在（hub.go:656-666） |
| 重放 | `replay_batch` 25 帧/批，逐帧标 `replayed=true`；慢客户端 TrySend 失败即关连强制重同步（hub.go:480-492） |

### 7.3 topic=market：快照批次 meta 帧（datahub 发）

载荷 `SnapshotMeta` 六键：`as_of / source / count / latency_ms / seq / stale`（datahub repo.go:108-116）。

- `seq` 是 datahub 内部轮次原子序号，与 WS `topic_seq` 无关。
- **`stale` 恒 false**：失败路径只把 Redis `snap:meta` 标 stale 并告警，不发 NATS；唯一发布点在成功路径（collector.go:147-157, 177）。前端 stale 展示位是死显示；真实陈旧信号 = 帧停更（心跳年龄）或 REST `Quote.stale`。
- 数据本体分层：单券快照本体在 Redis `snap:latest`（14 字段见 M02 §1）；前端单券走 REST GetQuote（`source = snap / 1d / ""`）；WS meta 帧只是批次心跳，前端只刷新快照标题行、不拉 REST（快照刷新 MarketView.vue:398-399；对账靠 60s 定时器 :432-435）。

### 7.4 bar 帧（market 服务产，`market.bar.1m`）——已产未路由

载荷 `{"bars":[Bar…]}`；仅 watch 租约候选池标的；仅刚封口或被晚到成交修正的 1 分钟线；修正同 `time` 重发整根，下游 upsert（usecase.go:314-328；bar.go:128-156）。
Bar 字段：`symbol / time / open / high / low / close / volume(int64) / amount` + omitempty `limit_known / no_limit / limit_up / limit_down`（执行限价四件套，仅 live watched 标的；持久化与研究帧不带）。

- `time` = 上海 RFC3339 槽起点。槽口径：集合竞价并入 09:30；11:30 后到 13:00 归 11:29；15:00 收盘竞价归 14:59；空分钟补平线（bar.go:30-88）。
- **无 `freq` 键**：频率由主题后缀隐含（`.1m`）；REST freq 取值仅 `1m/1d`。**无 `adj_factor`**：推送 bar 恒不复权。
- **未路由**：hub `natsRoutes` 无此绑定（hub.go:598-614），WS 不透传；前端增量管线（§7.7）今日消费零帧，**图表收敛 100% 靠 REST**（初始 load + 60s 对账 + resync 先按缺口窗口 [末根, 最新] 回填、回填够不到/超上限才整载，P2-9 见参考-tradingview §7）。
- **接线前两条必修**：(a) freq 守卫——前端按行/帧级 `freq` 过滤（MarketView.vue:405-411），但 Bar 无 `freq` 且前端忽略 `metadata.subject`，贸然接线日线图表会开放地址吞进 1m bar；须给载荷加 `freq` 或前端改读 metadata。(b) 「无 bar 行即 meta」兜底加形态校验——`MarketView.vue:398` 的 `if (!rows.length)` 会把任意无行新帧（含预留的 tick-only 帧）静默误刷成快照标题。
- 时间比较无失真：槽起点恒定位上海时区、JSON 恒带 `+08:00`，前端 `Date.parse` 比序与 chartTime 口径一致（bar.go:30-50；chartTime utils/time.ts:127-137）。

### 7.5 topic=alert / event=move：个股异动帧（market 服务发）

载荷 `symbol / kind / time / price / pct / name`，`kind ∈ limit_up / break / surge`，同类异动引擎侧 5 分钟去重（engine.go:56-85；hub.go:612）。前端在图表面之外消费（通知面 hub.ts:523-528、监控脉冲 monitor/pulses.ts:37）。

### 7.6 hub 合流、顺序与恢复

- 合流白名单：`tick / quote / market / bar / market.snapshot / market.bar.1m / market.factor.updated`；`market.alert`、`market.limit.changed` 属事件不入合流（hub.go:247-252）。
- key = `kind:symbol:freq:bucket`：kind 取 `metadata.subject` 回退 event；symbol 取行级 `symbol/stock_code/code`；bucket 仅 bar 系取 `time/timestamp/start_time/end_time/bar_time` 首非空；无 bucket 不合流（不吞完整 bar）。`{"bars":[…]}` 包裹帧的行对 marketKey 不可见 → key 为空直放，**批量帧不参与服务端合流**（hub.go:233-275）。
- latest-wins，每 key 每秒至多 1 帧，同 flush 内按 key 字典序入环；合流池上限 5000 key，超出直放普通事件。
- 顺序：每 topic int64 seq 从 1 单调、每主题 500 帧环、epoch = hub uuid；断线 `after-seq` 回放、`replay_batch` 分批（hub.go:494-547, 463-478）。
- NATS 侧 `market.*` 全走 core NATS at-most-once，无 durable、无重放（envelope.go:58-61）——**离线缺口唯一权威恢复是 REST**；前端 resync 先按缺口窗口 [末根, 最新] REST 回填合并（P2-9），回填够不到/合并超 LIVE_CAP 才整段重载。
- 订阅收窄（P0-3）：`market_filters:[{symbol, freq?}]`；freq 缺省按证券级全放行；任一 market 订阅者未收窄则整字段省略、回退全量（全有或全无，hub.ts:93-110；hub.go:281-317）。

### 7.7 前端消费侧口径（镜像，详见参考-tradingview §7 P0-1/P0-2 记录）

MarketView 只读 `msg.topic` 与 `msg.data`：三形态归一 `{bar}` / `{bars:[]}` / 顶层扁平；time 六键（`time/barTime/bar_time/timestamp/startTime/start_time`）、symbol 四键、`freq` 单键回退，无法解析时间的行整行丢弃；行/帧级 symbol+freq 与当前图表显式不匹配才拒、缺省开放地址。`applyLiveBar` 乱序拒（cur<prev）/同根替（cur==prev）/新根追（cur>prev），末根 >LIVE_CAP 800 或空表触发整载；逐行经 data-frame 同 key 后到覆盖先到、rAF 合批（隐页 1Hz）；`frameEpoch` 代际守卫——load() 递增使排队中的旧帧自废止，REST 权威压过在途增量；NtKline.updateLast 只 `update()` 不动视口。**该管线今日待用（§7.4 未路由）。**

## 10. 校验

- 快照：空结果失败；少于 `MinSnapshotCount`（默认 3000）失败；盘中最新 `time` 落后超过 `stale_after`（默认 10s）→ stale。
- K 线：价格非正、高低倒挂丢弃；相对前收超过 31% 保留但记 outlier。
- 完整率：覆盖率 &lt; 50% 换源；&lt; 99.9% 记 warn。
- 对账：抽样 50 只，收盘价差 &gt; 0.01 元或量相对差 &gt; 1% 记 reconcile。

## N3-01 「没取到 ≠ 0」统一封装（P3-10，2026-10-19）

纪律：一次取数的结果只有两种形态——**取到了** 或 **缺失且带原因**；禁止用零值冒充没取到，禁止把「源失败」与「真无数据」混为一谈。统一封装在 `backend/library/dataformat/result.go`（原机场气象模板残留已删）：

- **`Result[T]`**：`OK(v)` / `Missing(why, note)`；零值即 Missing(unknown)，忘了赋值也不会变成「0 = 有值」。
- **Why 六值**：`not_run`（采集没跑）/ `source_down`（源失败，含 P3-9 打标的限流封禁）/ `empty`（源成功但窗口内真无，如 90 天解禁 0 行且采集新鲜）/ `stale`（过期不可用）/ `filtered`（被校验隔离）/ `unknown`（证据不足的兜底，能不用就不用）。
- **传播**：`Map`/`FlatMap` 缺失原样传播（原因保留）；`First` 用于主备源链，全缺时保留最具体的缺失原因；`ValueOr(def)` 只允许展示层兜底语义，**禁止拿默认值继续计算**。
- **与既有机制的分工**：源状态走 `source_health`（P3-9 限流封禁标签）；行级问题走 `biz.Issue` → `data_quality_issue`；函数返回值层面的「缺失无法被静默吞掉」走 `Result[T]`。三者互补，替代的是「返回 0 就完事」的旧习惯。
- **存储侧不变**：可空数值仍用 ent NULLable + `*float64`（如 `emotion_day_frozen`、`intraday_alert`），`Result` 管应用层传递，不进 schema。
- **写作红线**：采集/查询失败必须留下可追查的痕迹（issue / last_error / missing 原因之一），API 与面板显式展示「没取到（原因）」；空结果集聚合前必须先判断是 WhyEmpty 还是没取到；`Completeness` 的 expect 为空不等于全覆盖（调用方自行传缺失语义）。M02 消费侧同守此约（见 M02 设计文档纪律段）。

## N4-02 完整补源合同与落库（2026-10-19）

固定 provider/录制原包 → 127.0.0.1 HTTP v1 完整 records → Go 验证 → ent 同事务 outbox唯一占用、PIT追加和current条件补写。`tdx_http_archive` 只实现 DailyBarSource，`openbb_fred` 只实现 MacroSource；只有显式启用才注册，不注册 Snapshot。请求4KiB、响应/原包8MiB、记录≤10000、两并发、超时有限；不接受请求级URL/路径、凭证地址或重定向。原始provider SHA256、records SHA256、raw kind及录制模式独立于现有规范化 Record.RawHash 保存，观察时钟不进入稳定修订身份。

数据库先依靠既有唯一 outbox EventID 竞争同内容批次，再追加PIT和current；current冲突仅在已有source为同补源时更新，主源保留；任一步失败全部回滚。宏观单位未知或超出现有16字节字段时仅保留完整PIT，不写裸数值current。记录数表示接受的provider记录，不能当作主源覆盖写入数或coverage证明；健康维持coverage_unknown。完整合同、边界和真实PG证据见 [统一接入记录](../实施记录/N4-02-历史补源统一接入-2026-10-19.md)。

## N4-03 解禁域（P2-8，2026-10-19）

为 M05 筹码供给段补的采集域 `unlock`，Go 侧走东财数据中心同款 `dc()` 分页助手（**不改 pyworker**，东吴脚本采集链历史参考已废）：

- 报表：`RPT_LIFT_STAGE`，`https://datacenter-web.eastmoney.com/api/data/v1/get`，`columns=ALL`，filter `(FREE_DATE>='day')(FREE_DATE<='day+90')`——90 天前向窗口是 A 股供给冲击标准观察窗（TradingAgents lockup_watcher 同款口径）。
- 贴源字段映射：`SECURITY_CODE→symbol`（secu 归一）、`FREE_DATE→free_date`、`FREE_SHARES_TYPE→lift_type`、`ABLE_FREE_SHARES→shares`（**单位万股，与源一致**）、`FREE_RATIO→ratio_pct`（占流通股 %）、`TOTAL_RATIO→total_ratio_pct`（占总股本 %）、`BATCH_HOLDER_NUM→batch_holder_num`。**源报表没有市值列与股东名列**：`market_value` 恒 NULL，不做股数×收盘价的伪算——没取到不等于 0。
- 写库「整窗替换」：`UpsertUnlockPlans(from, to, items)` 先删 `free_date∈[from,to]` 再按 `(symbol, free_date, lift_type)` bulk upsert——源头推迟/取消的批次同步消失，天然幂等空结果。
- 校验为空：窗口内一张解禁都没有是合法结果，`CollectUnlock` 的 check 传 nil 放行。
- 调度：`datahub.unlock` 15:25（交易日，Timeout 3min，Retry 2），盘后前滚一次赶在 brain 15:50 复盘前；失败时 brain 靠 `UnlockFresh`（`source_health.last_success_at` 近 4 日）区分「真无解禁」与「采集没跑」。
- **不进 `BackfillDomains`**：窗口是滚动替换语义，逐日回填会拿今天的快照覆盖历史切面，没意义；文档层面钉住不补数。
- 源优先级只有 `eastmoney`（config.yaml `domains.unlock`），未配置其它回退路。
