# M01 数据采集 · 需求文档

| 项 | 内容 |
|----|------|
| 模块 | M01 |
| 服务 | `datahub`（Go，HTTP 2011 / gRPC 2012）+ `pyworker`（Python HTTP 边车） |
| 版本 | v0.3（2026-10-08 评审后修订） |
| 优先级口径 | P0 属于 MVP |

## 0. 评审结论（v0.2 → v0.3）

| # | 问题 | 处理 |
|---|------|------|
| 1 | 只写「发布 `md.*` / `intel.raw.*`」，M02/M08 实际读 Redis 快照 | 明确快照写 `snap:latest`，每轮发普通 NATS `market.snapshot`；落库数据集发 `md.<域>.ready` |
| 2 | 新闻/公告若写入 `news_sentiment` 会和 M03 抢表 | 情报只发 `intel.raw.<kind>`，由 M03 去重打分入库 |
| 3 | 验收要求对账，功能表没有对应条目 | 新增 FR-01-15 |
| 4 | 分钟线时间标签未定，通达信文件用结束时间 | 入库统一为**开始时间**；读 vipdoc 时减 1 分钟 |
| 5 | 「完整率 99.9%」没有分母 | 分母 = 当日已上市、未退市的 A 股；当天还排除当前停牌 |
| 6 | 通达信成交量是手、成交额是万元 | 入库统一为股、元；各源在适配器内换算 |
| 7 | 正式版通达信没有 `PYPlugins` 时，官方接口会静默失败 | 依赖未就绪必须报 `unavailable`，禁止把旧 vipdoc 当实时行情（FR-01-14） |
| 8 | 设计草图写 gRPC 调 pyworker，与「边车可单独开关」冲突 | pyworker 对 datahub 提供 HTTP；datahub 对外仍是 gRPC+HTTP |
| 9 | Tushare 无积分时 P0 日线会空窗 | Tushare 无令牌视为 `unavailable`，自动切通达信文件 / 东财备源 |
| 10 | 舆情热榜默认关，但没有功能编号 | 纳入 FR-01-01 的域开关；默认 `hot_rank.enabled=false` |

未改：三种通达信接法都做；非官方源可一键关；7709 禁止下单。

## 1. 目标

把行情、资金、板块、新闻、公告、研报、外围、宏观收成统一记录。主源失败切备源。下游只订事件或读 Redis / PostgreSQL，不自己抓网站。

## 2. 数据域

| 数据域 | 内容 | 频率 | 主源 → 备源 | 去向 |
|--------|------|------|-------------|------|
| 证券基础 | 列表、上市退市、ST、停牌、股本 | 日 + 盘前 | Tushare → 通达信 TCP / 东财 | `stock_basic` + `md.security.ready` |
| 日线与复权 | OHLCV、前收、复权因子 | 日 | Tushare → 通达信 vipdoc / 东财 | `market_data` + `md.daily_bar.ready` / `md.adj_factor.ready` |
| 分钟线 | 1/5 分钟（开始时间） | 盘后增量 | 通达信 vipdoc → 7709 → AkShare（仅指定标的） | `market_data` + `md.minute_bar.ready` |
| 实时快照 | 最新价、涨跌幅、量额、五档 | 盘中 ≤3s | **通达信官方** → 7709 → 东财网页 → 新浪/腾讯 | Redis `snap:latest` + `market.snapshot` |
| 涨停生态 | 涨停/跌停/炸板池 | 盘中 ≤10s | 东财 → AkShare | `limit_pool` + `md.limit_pool.ready` |
| 资金 | 盘中主力；盘后主力/北向十大/龙虎榜/两融 | 盘中 / 盘后 | Tushare → 东财 | Redis `snap:flow`；`money_flow` / `hsgt_top10` / `lhb_seat` / `margin_detail` |
| 板块题材 | 行业/概念成分与行情 | 盘前成分 / 盘中行情 | 通达信板块文件 → 东财 | `sector` / `sector_member`；Redis `snap:sector` |
| 财务（排雷） | 预告、快报 | 日 | Tushare → 东财 / 通达信财务 | `finance_report` + `md.finance.ready` |
| 新闻 | 快讯、要闻 | ≤1min | 东财快讯 / Tavily → RSS | `intel.raw.flash` / `intel.raw.news` |
| 公告 | 上市公司公告 | ≤1min | 巨潮 → 东财 | `intel.raw.announcement` |
| 研报 | 摘要与评级 | 日 | 东财 | `intel.raw.report` |
| 外围 | 美股、中概、A50、汇率、原油、黄金、美债 | 盘前 / 夜盘 | AkShare | `overseas_quote` + `md.overseas.ready` |
| 宏观 | CPI、PMI、利率等 | 日扫月频序列 | AkShare | `macro_series` + `md.macro.ready` |
| 舆情 | 热榜 | 5min | 东财，**默认关** | `hot_rank` |

通达信（财富趋势，tdx.com.cn）就是口头说的「通信达」。它只承担行情与本地数据，不承担下单。下单见 M09。

## 3. 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-01-01 | 统一适配器；每个数据域可配置主备和开关 | P0 |
| FR-01-02 | 连续失败 3 次切备源并告警；主源恢复后可回切 | P0 |
| FR-01-03 | 按源限频、记当日配额；重启后配额从库恢复 | P0 |
| FR-01-04 | 全市场快照 ≤3s 写入 Redis；延迟、数量、行情落后做成指标 | P0 |
| FR-01-05 | 按日期、标的、数据域补数；写入走业务主键 upsert，重复补数不增行 | P0 |
| FR-01-06 | 完整性、异常值、时间戳校验；失败告警 | P0 |
| FR-01-07 | 落库完成经 outbox 发 `md.<域>.ready`；情报发 `intel.raw.<kind>`；快照发 `market.snapshot` | P0 |
| FR-01-08 | 数据源健康：成功率、延迟、最后成功时间、配额、断路状态 | P1 |
| FR-01-09 | 手动补拉（HTTP/gRPC 提交异步任务） | P1 |
| FR-01-10 | AkShare、通达信解析只放在 `pyworker`，由 datahub 调度；datahub 不解析通达信二进制 | P0 |
| FR-01-11 | 原始响应可留 7 天，默认可关；快照等循环域不留 | P2 |
| FR-01-12 | 非官方源（网页抓取、7709）可单独关闭；`allow_unofficial=false` 时全部跳过 | P0 |
| FR-01-13 | 通达信三种接法都要实现适配器：官方本地接口、本地 vipdoc 文件、TCP 7709 备源。交易环境默认只用前两种 | P0 |
| FR-01-14 | 通达信客户端未启动、插件缺失或盘后数据不是应有交易日时，必须明确报「数据不是最新」或 `unavailable`，禁止把旧文件当成实时行情 | P0 |
| FR-01-15 | 同一交易日，已入库日线与另一源抽样对账；不一致写入质量问题并标出两个来源 | P0 |

## 4. 约束

- 代码内部形式 `600519.SH`。通达信与东财文件单的转换只用 `pkg/symbol`。
- 价格元、成交量股、成交额元。通达信手→×100，万元→×10000；Tushare 日线量手、额千元，按官方文档换算。
- 快照 `as_of` 超过阈值（默认 10s）或 `stale=true` 时，M08 拒绝自动单。
- pyworker 与 M09 `broker-gw` 是两个进程；行情进程挂了不能影响下单。
- 7709 是社区协议，禁止用于下单，默认可关。

## 5. 验收

- 盘中快照端到端 P95 ≤ 3s（通达信客户端在线，或 7709 备源可用，或东财网页备源可用）。
- 交易日日线覆盖率 ≥ 99.9%（分母见第 0 节第 5 条）。低于 50% 的源结果视为失败并切源。
- 主备切换：连续失败 3 次后下一轮走备源；冷却（默认 60s）后探测成功即回切。
- 同一只股票，通达信日线与 Tushare 日线抽样不一致时能对账并标出来源。
- 插件缺失或 vipdoc 不是最新时，健康状态或质量问题里能看到明确原因，快照被标 `stale`。
