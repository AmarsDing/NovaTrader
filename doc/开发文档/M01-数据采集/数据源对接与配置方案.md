# 数据源对接与配置方案

> 版本：v1.0（2026-10-20）  
> 定位：回答四个问题——①现在接了哪些源、②接口齐不齐/缺什么、③外面还有什么源可用（免费/付费）、④怎么做到「用户自己清楚地配置、按需求切换」。  
> 事实基线：代码盘点以工作区现状为准（含 N4-02 进行中改动）；外部源 2026-10-19 当天 curl 实测或官网核实，个别价格标注「需询价」。  
> 红线：不违反决策 1/2/3（通达信行情主线不变、下单仍走东财文件单、大模型不直接下单）；全程遵守《0.数据纪律》「没取到≠0」。

---

## 0. 一句话结论

**接口骨架已经很全（20 个数据域、13 个源全落地），真正缺的是两样：一是若干「数据缺口」没补（通达信财务、一致预期、筹码分布等），二是配置「半自助」——现在只能开/关源，加源、调降级顺序、配额都得改配置文件重启。方案给出一份「可选源目录」（免费为主、付费可选）+ 一套「数据源中心」自助配置设计。**

## 1. 现状盘点：已经有什么

### 1.1 架构骨架（很好，不动）

datahub 按「**数据域 × 源能力接口**」注册：`biz/source.go` 定义 20 个域接口（日线/分钟线/复权因子/快照/涨跌停池/资金流/龙虎榜/解禁/两融/沪深港通/板块/财务/情报 flash·news·announcement·report/外围/宏观/热度榜），一个源实现哪些域接口就自动能服务哪些域；`config.yaml` 里每个域配 `sources: [主, 备, …]` 降级链，主源失败自动换备源。健康账本（成功率/延迟/断路状态）每分钟落 `source_health` 表，前端已有「数据源健康」面板（状态灯/成功率/手动采集/开关）。

这套骨架天然支持「一个域挂多个源、用户自选切换」——下面的自助配置设计只是在它上面补齐运行时能力。

### 1.3 配置链路现状（半自助）

| 层 | 机制 | 能配什么 | 局限 |
|---|---|---|---|
| 运行时（5 秒生效） | 配置中心 → `/api/config` → `strategy_config` → appcfg 缓存，键族 `app.ds.*` | 每个源的**开/关**、tushare/tavily 的 token、pyworker 地址、rss/tavily 的 feeds | **不能**：加新源、改域降级顺序、配 QPS/配额/official |
| 静态（重启生效） | `configs/config.yaml` + `conf.proto` | 一切（sources 链、qps、quota、token、超时） | 要改代码库的 yaml，重启服务，非用户友好 |

**这就是「能不能自己配置」的现状回答：开关可以，其余不行。** 第 4 节给出补全设计。

## 4. 目标设计：用户自助配置的「数据源中心」

### 4.1 设计原则

1. **不配 yaml、不重启**：源开关、凭证、降级链、配额全部走配置中心（`app.*` 键 → strategy_config → appcfg 5 秒生效，链路已存在，只扩键族）。
2. **每域多源 + 降级**：沿用现有 `domain → sources[]` 模型，用户在界面上拖拽排序即改降级链。
3. **没取到 ≠ 0**：任何源失败显式缺失（`dataformat.Result`），健康面板如实红。
4. **免费为主、付费可选**：每个源卡片标明费用档（免费 / 免费+门槛 / 付费），换源即换，系统不绑定任何一家。
5. **凭证只写不读**：secret 键永不回显明文（现有 config.go 的 secret_set 布尔模式沿用）。

### 4.2 源目录（Source Catalog）：每个源「能提供什么数据」一目了然

新增一份 Go 侧注册自描述清单（manifest），每个源声明：

```
名称、提供哪些域（徽章）、费用档、稳定性标注、所需凭证（token/key/无）、
限频建议、接入位置（Go 直连 / pyworker / source-worker）、官方/非官方、备注风险
```

通过一个管理接口（如 `/api/datahub/catalog`）吐给前端。前端渲染成**源卡片墙**：一眼看到「东财=快照/资金流/龙虎榜/解禁/两融…13 域、免费、健康绿灯、可开关可填 token」。这就回答了「每个数据源能够提供哪些数据，怎样很清晰」。

### 4.3 键族扩展（运行时全自助）

在现有白名单（`pkg/params/validate.go`，`app.ds.*` → datahub）上扩：

| 键 | 类型 | 作用 | 现状 |
|---|---|---|---|
| `app.ds.<source>.on` | bool | 开/关源 | 已有 |
| `app.ds.<source>.token` | secret | 凭证（tushare/tavily/FRED…） | 已有部分，扩到所有需要 key 的源 |
| `app.ds.<source>.url` | url | 覆盖端点（边车地址/代理） | 已有 pyworker |
| `app.ds.<source>.qps` | int | 限频 | **新增** |
| `app.ds.<source>.quota` | int | 日配额 | **新增** |
| `app.domain.<domain>.sources` | json | **域降级链排序**（如 `["eastmoney","tushare","baostock"]`） | **新增**，采集前盖写（现有 `applySourceSwitches` 同位置扩展） |

校验：域名/源名白名单、降级链里的源必须支持该域（`Supports()` 已有断言）、qps/quota 上下界。非法值 422 拒绝，不落库。

### 4.4 前端「数据源中心」设计（一个面板三个页签）

建议把现有「数据源健康」面板升级为数据源中心：

1. **源墙页签**：源卡片网格（名称/域徽章/费用档/健康灯/成功率/开关/凭证输入/「手动采集」按钮）。默认免费源在前，付费源灰标识价。
2. **域视图页签**：20 个域一行一条，每条显示当前降级链（拖拽排序 + 候选源下拉加挂 + 间隔秒），改完 5 秒生效。
3. **健康页签**：现有健康表 + 质量问题表原样保留（成功率/延迟/断路/最近错误/数据质量）。

视觉与交互按《1.视觉需求.md》：红涨绿跌不受影响，状态灯用现有 token；改动后跑 `/dev/gallery` 走查矩阵。

### 4.5 新增一个源的标准动作（开发者用，用户无感）

- **Go 直资源**：实现所需域接口 + manifest 登记 + 默认 yaml 追加（带 `enabled:false`）。模板参考 `eastmoney.go`。  
- **Python 边车源（推荐用于爬虫类）**：照 `source-worker` 的 `tdx_history/openbb_macro` 白名单 operation 模式加一个 operation（合约校验、127.0.0.1、限并发已有），Go 侧一小段适配。这是已经被 N4-02 验证过的最低成本路径。  
- **用户侧**：新源随版本出现在源墙，默认关，填 key（若需要）、打开、拖进域降级链。

## 6. 运维纪律（防「接口随时暴毙」）

1. **接口巡检**：网页系源每天一次烟雾探测（东财报表名轮换=两融活例、金十/财联社收紧=活例），失败进 `data_quality_issue` 表并在健康面板红显。
2. **多源互备**：关键域（快照/日线/资金流/公告）必须 ≥2 源在链上。
3. **没取到≠0**：任何取数失败/为空/未知显式缺失，禁止 0 冒充（《0.数据纪律》）。
4. **制度性断更登记**：北向这类「官方改规则」事件记入设计文档，因子侧按断更口径处理。
5. **版本钉死**：AkShare 等聚合库 pin 版本 + 升级回归，不裸追最新。

## 7. 合规与风险

- 网页系免费接口（东财/新浪/腾讯/东财股吧）为公开数据，低频采集+UA 礼貌+限速为界；商用再分发另行评估。

- 研报全文再分发侵权，只用元数据/摘要。
